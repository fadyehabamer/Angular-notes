This page covers the parts that actually appear in Angular code, in the order you meet them — starting from zero. If you can read JavaScript, you can read this.أنجولار مكتوب بـ TypeScript، فأي ملف أنجولار هتفتحه هو ملف TypeScript. والخبر الحلو: مش محتاج اللغة كلها. الصفحة دي فيها الأجزاء اللي بتظهر فعلاً في كود أنجولار، بالترتيب اللي هتقابلهم بيه — من الصفر. لو بتعرف تقرا جافاسكريبت، تقدر تقرا ده.

TypeScript is JavaScript with labelsTypeScript هو جافاسكريبت مع لافتات

Every line of JavaScript you already know is valid TypeScript. TypeScript adds one thing: you can say what kind of value a variable holds, and the editor checks it before you run the code.كل سطر جافاسكريبت إنت عارفه هو TypeScript صحيح. TypeScript بيضيف حاجة واحدة: تقدر تقول القيمة نوعها إيه، والمحرر بيتأكد قبل ما تشغّل الكود.

the whole ideacompareقارن
// JavaScript — nothing stops you until it explodes at runtimelet price = 100;price = 'one hundred';        // fine today, crash tomorrow // TypeScript — the same line, caught while you typelet price: number = 100;price = 'one hundred';        // Type 'string' is not assignable to type 'number'

That : number is a type annotation. It produces no code — the browser never sees it. It exists purely so the compiler and your editor can catch mistakes and offer autocomplete.الـ : number دي اسمها type annotation. مش بتنتج كود — البراوزر عمره ما بيشوفها. موجودة بس عشان الـ compiler والمحرر يمسكوا الغلطات ويقترحوا عليك.

You will annotate less than you thinkهتكتب أنواع أقل مما تتخيل

TypeScript infers most types. let price = 100 is already a number — writing : number there adds nothing. Annotate function parameters and public APIs; let everything else be inferred.TypeScript بـيستنتج معظم الأنواع. let price = 100 هو أصلاً number — كتابة : number هنا مش بتضيف حاجة. اكتب الأنواع في معاملات الدوال والواجهات العامة، وسيب الباقي يتستنتج.

Describing objectsوصف الـ objects

interface and type: naming a shapeinterface و type: تسمية الشكل

Almost every object in an Angular app has a name for its shape — a User, an Order, a Product. You write it once and use it everywhere.تقريباً كل object في تطبيق أنجولار ليه اسم لشكله — User أو Order أو Product. بتكتبه مرة وتستخدمه في كل حتة.

models/user.tsa real Angular fileملف أنجولار حقيقي
export interface User {  id: string;  name: string;  email: string;  age?: number;                    // ? = optional, may be missing  readonly createdAt: string;      // cannot be reassigned after creation  roles: string[];} // now the shape has a name you can use anywhereconst mona: User = {  id: 'u1',  name: 'Mona',  email: 'mona@shop.eg',  createdAt: '2026-01-04',  roles: ['admin'],};                                 // age omitted — allowed, it is optional

type does the same job and a bit more. The practical rule: use interface for object shapes, and type when you need a union or an alias for something that is not an object.type بتعمل نفس الشغل وزيادة شوية. القاعدة العملية: استعمل interface لأشكال الـ objects، وtype لما تحتاج union أو اسم بديل لحاجة مش object.

The number one errorالايرور رقم واحد

null, undefined, and “possibly undefined”null و undefined و «possibly undefined»

Angular projects ship with strict mode on. That means TypeScript refuses to let you use a value that might be missing, until you prove it is there. This is the error every beginner meets on day one.مشاريع أنجولار بتيجي وstrict mode مفتوح. ومعناها إن TypeScript مش هيسيبك تستخدم قيمة ممكن تكون ناقصة، لحد ما تثبت إنها موجودة. ودي الغلطة اللي كل مبتدئ بيقابلها أول يوم.

the error, and the four ways outread this twiceاقراها مرتين
const user: User | undefined = findUser('u1'); console.log(user.name);        // ✗ 'user' is possibly 'undefined' // 1. check first — the compiler follows your if statementif (user) {  console.log(user.name);      // ✓ inside here it cannot be undefined} // 2. optional chaining — returns undefined instead of throwingconsole.log(user?.name);       // ✓ // 3. a fallback value with ??  (only fires on null/undefined)const label = user?.name ?? 'Guest';   // ✓ // 4. the non-null assertion — you SWEAR it is thereconsole.log(user!.name);       // ✓ compiles, and crashes if you were wrong
About that exclamation markبخصوص علامة التعجب دي

! does not check anything — it silences the compiler. Every ! you write is a promise you are making with no evidence. Use options 1–3 first; reach for ! only when you can explain out loud why it can never be null.! مش بتتأكد من حاجة — بتسكّت الـ compiler بس. كل ! بتكتبها هي وعد منك من غير دليل. استعمل الحلول 1 لـ 3 الأول؛ ومتلجأش لـ ! غير لما تقدر تقول بصوت عالي ليه دي مستحيل تكون null.

Note the difference between ?? and ||. || fires on any falsy value, so 0 and '' get replaced too. ?? fires only on null and undefined — which is almost always what you meant.خد بالك من الفرق بين ?? و||. || بتشتغل مع أي قيمة falsy، فـ 0 و'' بيتبدلوا كمان. أما ?? فبتشتغل بس مع null وundefined — وده تقريباً دايماً اللي كنت تقصده.

the difference that bites?? vs ||?? مقابل ||
const qty = 0; qty || 1;     // → 1   … 0 is falsy, so it was replaced. Probably a bug.qty ?? 1;     // → 0   … 0 is a real value, kept. Probably what you wanted.

Functions, parameters and return typesالدوال والمعاملات وأنواع الإرجاع

Parameters are where annotations earn their keep — TypeScript cannot infer what a caller will hand you.المعاملات هي المكان اللي الأنواع بتثبت فيه فايدتها — TypeScript مش بيقدر يستنتج المتصل هيديك إيه.

functions.tsevery formكل الأشكال
// annotate the parameters; the return type is usually inferredfunction greet(name: string) {  return `Hello ${name}`;         // inferred as string} // optional parameter, and one with a defaultfunction price(amount: number, currency = 'EGP', discount?: number) {  const off = discount ?? 0;  return `${amount - off} ${currency}`;} // arrow function — the form you see most in Angularconst double = (n: number): number => n * 2; // a function that returns nothingfunction log(message: string): void {  console.log(message);} // a function passed as a value — describe its shapefunction onEach(items: string[], fn: (item: string, index: number) => void) {  items.forEach(fn);}
Where you meet this in Angularهتقابل ده فين في أنجولار

(item: string, index: number) => void is exactly the shape you write for a route guard, an HTTP interceptor, or the callback in .map(). Angular is full of functions passed as values.(item: string, index: number) => void ده بالظبط الشكل اللي بتكتبه لـ route guard أو HTTP interceptor أو الـ callback جوه .map(). أنجولار مليان دوال بتتمرر كقيم.

Where components liveمكان الـ components

Classes, and the parts Angular cares aboutالكلاسات، والأجزاء اللي أنجولار بيهتم بيها

Every Angular component and service is a class. You need four things from classes: fields, a constructor, access modifiers, and readonly.كل component وservice في أنجولار هو كلاس. ومحتاج أربع حاجات من الكلاسات: الحقول، والـ constructor، ومحددات الوصول، وreadonly.

classes.tsthe four thingsالأربع حاجات
export class Cart {  // a field with an initial value — its type is inferred  items: Item[] = [];   // public (the default): anyone may read and write it  public currency = 'EGP';   // private: only code inside this class may touch it  private secret = 'abc';   // protected: this class and anything that extends it  protected internalId = 0;   // readonly: set once, never reassigned  readonly createdAt = new Date();   // a method  add(item: Item) {    this.items = [...this.items, item];  }   // a getter — reads like a field, runs like a method  get count() {    return this.items.length;  }}

Angular components use exactly this and little else. You will see readonly on almost every line of a modern component — because a signal, an input or an injected service is created once and never reassigned.الـ components في أنجولار بتستخدم ده بالظبط ومش أكتر. وهتشوف readonly في كل سطر تقريباً في component حديث — لإن الـ signal أو الـ input أو الـ service المحقونة بتتعمل مرة واحدة وعمرها ما بتتغير.

what it looks like in Angularjoining upالتوصيل
@Component({ selector: 'app-cart', template: `…` })export class CartComponent {  // injected once, never reassigned → readonly  private readonly store = inject(CartStore);   // created once; the VALUE inside changes, the signal does not  readonly items = signal<Item[]>([]);   // a plain method, called from the template  add(item: Item) {    this.items.update(list => [...list, item]);  }}
readonly is not the same as constreadonly مش زي const

readonly items = signal([]) means you cannot do this.items = somethingElse. It does not freeze what is inside — items.set([...]) still works, and that is exactly the point.readonly items = signal([]) معناها إنك مش هتقدر تعمل this.items = حاجة تانية. لكنها مش بتجمّد اللي جوه — items.set([...]) لسه شغالة، وده بالظبط المقصود.

The scary-looking oneاللي شكله مخيف

Generics: the <angle brackets> everywhere in Angularالـ Generics: الـ <أقواس> اللي في كل حتة في أنجولار

signal<Item[]>([]), input.required<string>(), http.get<User>(…) — the same idea three times. A generic is a type you fill in later, like a parameter but for types.signal<Item[]>([]) وinput.required<string>() وhttp.get<User>(…) — نفس الفكرة تلات مرات. الـ generic هو نوع بتملاه بعدين، زي المعامل بالظبط بس للأنواع.

Read it out loudاقراها بصوت عالي

signal<Item[]>([]) reads as “a signal of Item array, starting empty”. Once you hear the word of, generics stop being intimidating.signal<Item[]>([]) بتتقري «signal بتاعة array من Item، وبتبدأ فاضية». أول ما تسمع كلمة بتاعة، الـ generics بتبطّل تخوّف.

Free shortcutsاختصارات ببلاش

Utility types you will reach forأنواع جاهزة هتحتاجها

TypeScript ships types that build new shapes out of existing ones. These five cover nearly every real case.TypeScript بييجي معاه أنواع بتبني أشكال جديدة من أشكال موجودة. الخمسة دول بيغطوا تقريباً كل حالة حقيقية.

utility-types.tsall fiveالخمسة
interface User { id: string; name: string; email: string; age: number; } // every field optional — the shape of a PATCH request bodytype UserPatch = Partial<User>;// { id?: string; name?: string; email?: string; age?: number } // keep only these fields — the shape of a list rowtype UserRow = Pick<User, 'id' | 'name'>;// { id: string; name: string } // everything except these — the shape of a create formtype NewUser = Omit<User, 'id'>;// { name: string; email: string; age: number } // nothing can be reassignedtype FrozenUser = Readonly<User>; // a dictionary: keys of one type, values of anothertype PricesBySku = Record<string, number>;// { 'sku-1': 100, 'sku-2': 250, … }

These matter because they keep one source of truth. When a field is added to User, every shape derived from it updates automatically — nothing to remember, nothing to forget.دي مهمة لإنها بتحافظ على مصدر واحد للحقيقة. لما حقل يتضاف لـ User، كل الأشكال المشتقة منه بتتحدث لوحدها — مفيش حاجة تفتكرها ولا حاجة تنساها.

Proving itإثبات النوع

Narrowing: convincing the compilerالتضييق: تقنع الـ compiler

When a value could be several things, TypeScript follows your if statements and works out which one it is inside each branch. This is called narrowing, and it is why you rarely need casts.لما القيمة تقدر تكون كذا حاجة، TypeScript بيتابع الـ if بتاعتك ويحدد هي إيه جوه كل فرع. ده اسمه narrowing، وعشان كده نادراً ما تحتاج تعمل cast.

narrowing.tsfour waysأربع طرق
function show(value: string | number | null) {  if (value === null) return '—';  //  value is string | number from here on   if (typeof value === 'number') {    return value.toFixed(2);      // ✓ it is a number in this branch  }   return value.trim();            // ✓ only string is left} // discriminated union — one shared field decides which shape it istype Result =  | { ok: true;  data: User }  | { ok: false; error: string }; function handle(r: Result) {  if (r.ok) return r.data.name;   // ✓ TypeScript knows data exists  return r.error;                 // ✓ and here, error exists}
This is how resource status worksكده بتشتغل حالة الـ resource

Angular’s status() being 'idle' | 'loading' | 'resolved' | 'error' is a discriminated union. Checking it in a template with @if narrows it exactly the same way.الـ status() في أنجولار لما تكون 'idle' | 'loading' | 'resolved' | 'error' دي discriminated union. وفحصها في التمبلت بـ @if بيضيّقها بنفس الطريقة بالظبط.

Decorators: what @Component actually isالـ Decorators: @Component ده إيه بالظبط

A decorator is a function you attach to a class to add information about it. @Component({...}) does not change your class — it records metadata that Angular reads later.الـ decorator دالة بتلزقها على كلاس عشان تضيف معلومات عنه. @Component({...}) مش بيغيّر الكلاس بتاعك — بيسجّل metadata أنجولار بيقراها بعدين.

@Component({  selector: 'app-user-card',  template: '<h3>{{ name() }}</h3>',})export class UserCard {  readonly name = input.required<string>();} // Read it as: "this is an ordinary class, AND Angular should know//  it answers to <app-user-card> and renders that template."//// The object inside the brackets is just an object. That is why// selector, template and imports are written with : and ,

The four you will meet: @Component on a component, @Directive on a directive, @Injectable on a service, and @Pipe on a pipe. Modern Angular has replaced most of the others — @Input and @Output are now the functions input() and output().الأربعة اللي هتقابلهم: @Component على الـ component، و@Directive على الـ directive، و@Injectable على الـ service، و@Pipe على الـ pipe. وأنجولار الحديث استبدل معظم الباقي — @Input و@Output بقوا الدوال input() وoutput().

How to read a long errorإزاي تقرا ايرور طويل

Read the last line first. TypeScript nests its explanation, and the innermost line is the actual mismatch — usually one field name.اقرا آخر سطر الأول. TypeScript بيعشّش الشرح، وأعمق سطر هو الاختلاف الحقيقي — وغالباً بيبقى اسم حقل واحد.

The settingsالإعدادات

The tsconfig lines that change your lifeسطور الـ tsconfig اللي بتغيّر حياتك

ng new already sets these correctly. Know what they do so you understand why the compiler behaves the way it does — and so you never turn them off to make an error go away.ng new بيظبطهم صح أصلاً. اعرف بيعملوا إيه عشان تفهم الـ compiler بيتصرف كده ليه — وعشان عمرك ما تقفلهم بس عشان ايرور يختفي.

tsconfig.jsonwhat mattersالمهم
{  "compilerOptions": {    "strict": true,                     // turns on all the checks below    "noImplicitAny": true,              // an untyped parameter is an error    "strictNullChecks": true,           // null and undefined are real types    "noUnusedLocals": true,             // dead variables are errors    "paths": {      "@app/*": ["src/app/*"]           // import from '@app/models/user'    }  },  "angularCompilerOptions": {    "strictTemplates": true             // type-checks your HTML too  }}
strictTemplates is the good onestrictTemplates هي الحلوة

With it on, passing a string to an input declared as number is an error in the HTML file. Your templates get the same safety as your classes. Never turn it off.لما تكون مفتوحة، إنك تمرّر string لـ input معلن number بيبقى ايرور في ملف الـ HTML. فالتمبلتس بتاخد نفس الأمان بتاع الكلاسات. عمرك ما تقفلها.

If an error is annoying, the answer is almost never to relax the config. Strict mode is the reason a large Angular app stays refactorable — every rule you switch off is a category of bug you agreed to find at runtime instead.لو ايرور مضايقك، الحل تقريباً عمره ما بيكون إنك تخفف الإعدادات. الـ strict mode هو السبب إن تطبيق أنجولار الكبير يفضل قابل لإعادة الهيكلة — وكل قاعدة بتقفلها دي نوعية باجات وافقت تكتشفها وقت التشغيل بدل كده.
