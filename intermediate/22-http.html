HTTP without the subscribeHTTP من غير subscribe

Interceptors are functions. Requests can be declared instead of triggered — and the loading flag, the error branch and the race condition you keep hand-writing already exist in the box.الـ interceptors بقت functions. والريكويست تقدر تعلن عنه بدل ما تطلقه — والـ loading flag وفرع الايرور وحالة السباق اللي بتكتبها بإيدك كل مرة، كلهم موجودين جاهزين.

What it actually isهي إيه بالظبط

Interceptors are a checkpoint every request passes through, so auth headers and error handling live in one file instead of forty.الـ interceptors هي نقطة تفتيش كل طلب بيعدّي منها، فالـ auth headers ومعالجة الأخطاء بتبقى في ملف واحد بدل أربعين.

Think of it likeاعتبرها زي

Airport security. Every passenger goes through the same gate, and the rules are written once at the gate — not once per passenger.أمن المطار. كل مسافر بيعدّي من نفس البوابة، والقواعد مكتوبة مرة واحدة عند البوابة — مش مرة لكل مسافر.

You reach for it whenهتحتاجها لما

Attaching tokens, logging, retrying, showing a global spinner, translating server errors into human sentences.لما تلزق tokens، أو تسجّل، أو تعيد المحاولة، أو تعرض spinner عام، أو تترجم أخطاء السيرفر لجُمل مفهومة.

Every name on this page — yours or Angular’s?كل اسم في الصفحة دي — بتاعك ولا بتاع أنجولار؟

An interceptor is just a function Angular calls with two arguments. req and next are only the usual parameter names: Angular passes them by position, so you could call them anything. The methods you call on them (clone, pipe) are fixed.الـ interceptor ما هو إلا function أنجولار بيناديها بـ argumentين. req وnext دول بس الأسامي المعتادة للـ parameters: أنجولار بيبعتهم بالترتيب، فتقدر تسميهم أي حاجة. أما الميثودز اللي بتناديها عليهم (clone، pipe) فثابتة.

Watch outخد بالك

  • resource, rxResource and httpResource are developer preview and their option names have already changed once (request → params, loader → stream). Fine in an app you control; be careful in a published library.resource وrxResource وhttpResource لسه developer preview وأسامي الـ options اتغيرت مرة بالفعل (request بقت params، وloader بقت stream). عادي في تطبيق إنت مسيطر عليه؛ خد بالك في library هتنشرها.
  • An HttpRequest is immutable. req.headers.set(...) returns a new object and changes nothing — you must req.clone({...}).الـ HttpRequest ثابت. req.headers.set(...) بيرجّع object جديد ومبيغيّرش حاجة — لازم req.clone({...}).
  • Interceptor order is the array order, and it applies outward on the response. Put logging first and auth last if you want to log the final request.ترتيب الـ interceptors هو ترتيب المصفوفة، وبيتطبق بالعكس على الرد. حط الـ logging الأول والـ auth الآخر لو عايز تسجّل الريكويست النهائي.
  • HttpClient completes after one value, so a forgotten subscribe is not a leak — but it is an untracked side effect. Prefer the async pipe, toSignal, or a resource.HttpClient بيقفل بعد قيمة واحدة، فالـ subscribe اللي نسيته مش تسريب — بس هو فعلاً side effect مش متتبَّع. الأفضل async pipe أو toSignal أو resource.
  • Returning undefined from the URL function means “do not request yet”. That is how you express a search that waits for two characters.لو دالة الـ URL رجّعت undefined معناها “متطلبش حاجة دلوقتي”. وكده تعبّر عن بحث مستني حرفين.
If you remember one thingلو هتفتكر حاجة واحدة

An interceptor must return the chain: return next(req). Forget that line and every request in your app hangs forever.الـ interceptor لازم يرجّع السلسلة: return next(req). تنسى السطر ده، وكل طلب في تطبيقك هيعلّق للأبد.

Q01 Where is an interceptor registered?الـ interceptor بيتسجّل فين؟
whyليه

Functional interceptors are listed once, next to provideHttpClient(), and every request in the app then passes through them in order. That is the whole appeal: the token and the error handling live in one file.الـ interceptors الوظيفية بتتسجّل مرة واحدة جنب provideHttpClient()، وبعدها كل طلب في التطبيق بيعدّي منها بالترتيب. وده كل جمالها: التوكن ومعالجة الأخطاء في ملف واحد.

Q02 Why does an interceptor clone() the request?ليه الـ interceptor بيعمل clone() للطلب؟
auth.interceptor.ts
export const authInterceptor: HttpInterceptorFn = (req, next) => {  const withToken = req.clone({    setHeaders: { Authorization: 'Bearer ' + token() },  });  return next(withToken);};
whyليه

Requests are deliberately immutable so that a retry replays exactly what was sent. clone() hands you a modified copy; assigning to req.headers directly does nothing at all.الطلبات غير قابلة للتغيير بشكل مقصود علشان إعادة المحاولة تبعت نفس اللي اتبعت بالظبط. وclone() بتدّيك نسخة معدّلة، أما إنك تكتب في req.headers مباشرة فمش بيعمل حاجة خالص.

Q03 catchError must return what?catchError لازم ترجّع إيه؟
whyليه

The stream has to continue with something. of([]) recovers with an empty list; throwError(() => err) passes the problem on. Returning a bare value is a type error and a common first mistake.الـ stream لازم يكمل بـ حاجة. of([]) بتتعافى بقائمة فاضية، وthrowError(() => err) بتمرر المشكلة لبعدين. وإنك ترجّع قيمة عادية ده خطأ نوع، وغلطة أولى شائعة.
