HTTP and interceptors, name by nameالـ HTTP والـ interceptors، اسم اسم

The idea is simple: the page asks for data, and every request passes one checkpoint on its way out. The confusing part is the names. req and next look like Angular words but are not. setHeaders looks like a name you picked but is. And the route’s :id has to match a name in a completely different file. This page sorts every one of them.الفكرة بسيطة: الصفحة بتطلب داتا، وكل request بيعدّي على نقطة تفتيش واحدة وهو خارج. اللي بيلخبط هو الأسماء. req وnext شكلهم كلمات أنجولار بس هما مش كده. وsetHeaders شكلها اسم انت اخترته بس هي بتاعة أنجولار. و:id اللي في الـ route لازم يبقى زي اسم في ملف تاني خالص. الصفحة دي بترتّب كل واحد فيهم.

One URL, six stopsURL واحد، ست محطات

Someone opens /users/42. The page must load user 42 from the server, and every request must carry the sign-in token. Follow the id from the address bar to the screen:حد فتح /users/42. الصفحة لازم تجيب user رقم 42 من السيرفر، وكل request لازم يكون معاه توكن الـ sign-in. امشي ورا الـ id من شريط العنوان لحد الشاشة:

  1. 1app.routes.tsrouter · names the paramالـ router · بيسمّي الـ param
    { path: 'users/:id', component: UserPage },{ path: 'users/:banana', component: Potato },

    The router matches the URL. The colon makes :id a route param, and the name after it, id, is yours. path and component are Angular’s keys. UserPage is your class.الـ router بيطابق الـ URL. النقطتين بيخلّوا :id route param، والاسم اللي بعدهم، id، بتاعك. وpath وcomponent مفاتيح أنجولار. وUserPage الكلاس بتاعك.

  2. 2user-page.tspage · receives itالصفحة · بتستقبله
    readonly id = input.required<string>();readonly banana = input.required<string>();

    The router drops '42' into the input with the same name. That is why id is orange: the routes file and the page must spell it the same. This only happens because the config turned on withComponentInputBinding.الـ router بيحط '42' في الـ input اللي ليه نفس الاسم. وعشان كده id برتقاني: ملف الـ routes والصفحة لازم يكتبوه زي بعض. وده بيحصل بس عشان الـ config مشغّل withComponentInputBinding.

  3. 3user-page.tspage · declares the readالصفحة · بتعلن القراية
    readonly user = httpResource<User>(() => `/api/users/${this.id()}`);readonly carrot = httpResource<Muffin>(() => `/api/users/${this.banana()}`);

    httpResource is Angular’s. user is your name for the result, and User is your data type. The arrow function builds the URL; because it calls this.id(), a new id means a new request.httpResource بتاعة أنجولار. وuser اسمك انت للنتيجة، وUser نوع الداتا بتاعك. الـ arrow function بتبني الـ URL؛ وعشان بتنادي this.id()، أي id جديد معناه request جديد.

  4. 4app.config.tsconfig · the checkpoint listالـ config · قايمة نقط التفتيش
    provideHttpClient(withInterceptors([authInterceptor])),provideHttpClient(withInterceptors([waffle])),

    Before it leaves, the request goes through every interceptor in this list, in order. provideHttpClient and withInterceptors are Angular’s. authInterceptor is the one name this file shares with the interceptor’s file.قبل ما يخرج، الـ request بيعدّي على كل interceptor في القايمة دي، بالترتيب. provideHttpClient وwithInterceptors بتوع أنجولار. وauthInterceptor هو الاسم الوحيد اللي الملف ده متشارك فيه مع ملف الـ interceptor.

  5. 5auth.interceptor.tsinterceptor · adds the tokenالـ interceptor · بيضيف التوكن
    export const authInterceptor: HttpInterceptorFn = (req, next) => {export const waffle: HttpInterceptorFn = (donut, pepper) => {  const token = inject(Session).accessToken();  const lemon = inject(Pumpkin).turnip();  return next(req.clone({ setHeaders: { Authorization: `Bearer ${token}` } }));  return pepper(donut.clone({ setHeaders: { Authorization: `Bearer ${lemon}` } }));};

    req and next are not Angular words. Angular calls your function with two things, in order: the request, then “whoever is next”. You name them. clone and setHeaders are Angular’s. Authorization and Bearer are what your server expects.req وnext مش كلمات أنجولار. أنجولار بينادي الـ function بتاعتك بحاجتين، بالترتيب: الـ request، وبعدين “اللي عليه الدور”. انت اللي بتسمّيهم. وclone وsetHeaders بتوع أنجولار. وAuthorization وBearer دول اللي السيرفر مستنيهم.

  6. 6user-page.htmltemplate · shows itالتمبلت · بيعرضه
    @if (user.value(); as u) {@if (carrot.value(); as biscuit) {  <h1>{{ u.name }}</h1>  <h1>{{ biscuit.taco }}</h1>}

    The answer arrives in value, a signal every resource has. u is a short name you give it for this block only. name is a field of your User interface, so the interface and the template must agree.الرد بيوصل في value، signal موجودة في أي resource. وu اسم قصير بتديهوله للبلوك ده بس. وname field في الـ interface User بتاعك، فالـ interface والتمبلت لازم يتفقوا.

The whole thing in one lineالحكاية كلها في سطر

:id in the route fills the id input, the resource builds /api/users/42, authInterceptor adds the header on the way out, and the template reads user.value(). Three pairs of names must match: route ↔ input, interceptor ↔ config, interface ↔ template.:id اللي في الـ route بيملا الـ input id، والـ resource بيبني /api/users/42، وauthInterceptor بيضيف الـ header وهو خارج، والتمبلت بيقرا user.value(). فيه تلات أزواج أسماء لازم يتطابقوا: الـ route ↔ الـ input، الـ interceptor ↔ الـ config، الـ interface ↔ التمبلت.

AThe route param must equal the input nameالـ route param لازم يساوي اسم الـ input

withComponentInputBinding matches by name only. The text after the colon in the route is the name it looks for on the page. The page has id, so the route must say :id.withComponentInputBinding بتطابق بالاسم بس. الكلام اللي بعد النقطتين في الـ route هو الاسم اللي بتدوّر عليه في الصفحة. الصفحة فيها id، فالـ route لازم يقول :id.

app.routes.tsavoidتجنّب
{ path: 'users/:userId', component: UserPage },{ path: 'users/:userId', component: Potato },
app.routes.tsdo thisاعمل كده
{ path: 'users/:id', component: UserPage },{ path: 'users/:banana', component: Potato },

The left one compiles. At runtime the router has a userId and the page has no input called that, so the id input stays empty. Rename one side, rename the other.اللي على الشمال بيعمل compile. وهو شغال الـ router معاه userId والصفحة معندهاش input بالاسم ده، فالـ input id بيفضل فاضي. غيّر ناحية، غيّر التانية.

BThe header name belongs to the serverاسم الـ header بتاع السيرفر

Inside setHeaders, the key is the real HTTP header name. Authorization is spelled the American way, and the value is Bearer, one space, then the token. You could send a header called MyToken and Angular would happily send it. Whether anything works depends on what your server reads.جوه setHeaders، المفتاح هو اسم الـ HTTP header الحقيقي. Authorization مكتوبة بالطريقة الأمريكاني، والقيمة Bearer، مسافة واحدة، وبعدين التوكن. تقدر تبعت header اسمه MyToken وأنجولار هيبعته عادي. بس هل حاجة هتشتغل ولا لأ، ده على حسب السيرفر بيقرا إيه.

auth.interceptor.tsavoidتجنّب
setHeaders: { Authorisation: `Bearer${token}` },setHeaders: { Authorisation: `Bearer${lemon}` },
auth.interceptor.tsdo thisاعمل كده
setHeaders: { Authorization: `Bearer ${token}` },setHeaders: { Authorization: `Bearer ${lemon}` },

Two mistakes on the left: British spelling, and no space after Bearer. Both compile, both send a request, and the server answers 401.فيه غلطتين على الشمال: الإملا البريطاني، ومفيش مسافة بعد Bearer. الاتنين بيعملوا compile، والاتنين بيبعتوا request، والسيرفر بيرد بـ 401.

Older codeكود أقدم

Class interceptors and subscribe: same names, more of Angular’sالـ interceptors الكلاس وsubscribe: نفس الأسماء، وكلمات أنجولار أكتر

Tutorials and older projects write interceptors as classes and load data by subscribing. Your names barely change. What changes is how many names Angular forces on you.الشروحات والمشاريع الأقدم بتكتب الـ interceptors على شكل كلاسات وبتجيب الداتا بـ subscribe. أسماءك بالعافية بتتغير. اللي بيتغير هو عدد الأسماء اللي أنجولار بيفرضها عليك.

app.config.ts — older styleregistering the classتسجيل الكلاس

In the class version, intercept is not your choice: the HttpInterceptor interface demands exactly that method name, and handle is the older handler’s method. In the function version all of that disappears and only your names are left.في نسخة الكلاس، intercept مش اختيارك: الـ interface HttpInterceptor طالب اسم الميثود ده بالظبط، وhandle ميثود الـ handler القديم. وHTTP_INTERCEPTORS token بتاع أنجولار، وmulti لازم تبقى true عشان الـ token ده بيلم قايمة. في نسخة الـ function كل ده بيختفي ومبيفضلش غير أسماءك.

user-page.ts — older styleavoidتجنّب

Same id, same User, same user. In the older version ngOnInit is a fixed name Angular calls, http is your field name, and u is just the callback’s parameter. Mistakes that fail silentlyغلطات بتفشل في صمت

HTTP mistakes rarely crash. The request still goes out, just without the header, or to the wrong URL, and you find out from a 401 or a 404 in the Network tab.غلطات الـ HTTP نادرًا ما بتوقّع التطبيق. الـ request لسه بيخرج، بس من غير الـ header، أو على URL غلط، وبتعرف من 401 أو 404 في تاب الـ Network.

1The interceptor is written but not listedالـ interceptor مكتوب بس مش متسجل
app.config.tsavoidتجنّب
provideHttpClient(),
app.config.tsdo thisاعمل كده
provideHttpClient(withInterceptors([authInterceptor])),provideHttpClient(withInterceptors([waffle])),

A file that exports an interceptor does nothing by itself. Angular only runs the functions in withInterceptors([ ]). Every request leaves without the token.ملف بيعمل export لـ interceptor مبيعملش حاجة لوحده. أنجولار بيشغّل بس الـ functions اللي في withInterceptors([ ]). وكل request بيخرج من غير التوكن.

2Editing the request instead of cloning itإنك تعدّل الـ request بدل ما تعمل له clone
auth.interceptor.tsavoidتجنّب
req.headers.set('Authorization', `Bearer ${token}`);donut.headers.set('Authorization', `Bearer ${lemon}`);return next(req);return pepper(donut);
auth.interceptor.tsdo thisاعمل كده
return next(req.clone({return pepper(donut.clone({  setHeaders: { Authorization: `Bearer ${token}` },  setHeaders: { Authorization: `Bearer ${lemon}` },}));

Requests and their headers cannot be changed. set on headers returns a new copy, and the left code throws that copy away. The original request goes out untouched.الـ requests والـ headers بتاعتها مينفعش يتغيروا. set على headers بترجّع نسخة جديدة، والكود اللي على الشمال بيرمي النسخة دي. والـ request الأصلي بيخرج زي ما هو.

3Input binding not switched onربط الـ inputs مش متشغّل
app.config.tsavoidتجنّب
provideRouter(routes),provideRouter(mango),
app.config.tsdo thisاعمل كده
provideRouter(routes, withComponentInputBinding()),provideRouter(mango, withComponentInputBinding()),

Without this feature the router never copies route params into inputs, however well the names match. id stays empty, and reading an empty input.required is a runtime error (NG0950) instead of a request.من غير الـ feature دي الـ router عمره ما بينسخ الـ route params في الـ inputs، مهما الأسماء كانت متطابقة. id بيفضل فاضي، وقراية input.required فاضي بتطلع runtime error (NG0950) بدل الـ request.

4Forgetting the brackets on a signal inside the URLنسيان القوسين على signal جوه الـ URL
user-page.tsavoidتجنّب

TypeScript is happy to put a function inside a string, so there is no error. The URL gets a text description of the signal instead of 42, and the server answers 404. A signal is only read when you call it.TypeScript مش عنده مشكلة يحط function جوه string، فمفيش error. الـ URL بياخد نص بيوصف الـ signal بدل 42، والسيرفر بيرد بـ 404. الـ signal مبيتقريش غير لما تناديها.

5Forgetting to returnنسيان الـ return
auth.interceptor.tsavoidتجنّب
export const authInterceptor: HttpInterceptorFn = (req, next) => {export const waffle: HttpInterceptorFn = (donut, pepper) => {  next(req);  pepper(donut);};
auth.interceptor.tsdo thisاعمل كده

This one does give an error, thanks to the HttpInterceptorFn type, but it reads oddly: something like “void is not assignable to Observable<HttpEvent<unknown>>”.
