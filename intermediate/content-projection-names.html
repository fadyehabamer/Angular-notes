<ng-content>, name by name<ng-content>، اسم اسم

The idea is simple: the panel leaves holes, the parent fills them. The confusing part is the names. The button sits inside the panel on screen, yet it calls the parent’s method. The word actions appears in two components and neither one owns it alone. And nothing tells you when the two sides stop matching. This page sorts out every name.الفكرة بسيطة: الـ panel بيسيب فتحات، والأب بيملاها. اللي بيلخبط هو الأسماء. الزرار قاعد جوه الـ panel على الشاشة، ومع ذلك بينادي ميثود الأب. وكلمة actions موجودة في اتنين components ومحدش فيهم صاحبها لوحده. ومفيش حاجة بتقولك لما الناحيتين يبطلوا يطابقوا. الصفحة دي بتفرز كل اسم.

One Reset button, five stopsزرار Reset واحد، خمس محطات

A settings page shows its notification options inside a reusable panel. The panel draws the border, the heading and the Show/Hide button. The settings page supplies a Reset button for the header and the options for the body. Follow the Reset button:صفحة إعدادات بتعرض اختيارات الإشعارات جوه panel بيتستخدم في أكتر من مكان. الـ panel بيرسم البرواز والعنوان وزرار Show/Hide. وصفحة الإعدادات بتدّي زرار Reset للهيدر، والاختيارات للـ body. امشي ورا زرار Reset:

  1. 1settings.component.htmlparent · opens the tagالأب · بيفتح التاج
    <app-panel heading="Notifications" [collapsible]="true"><app-waffle mango="Notifications" [pickle]="true">

    The settings page writes the panel’s tag. heading and collapsible are the panel’s inputs: plain values go in through attributes, like with any component.صفحة الإعدادات بتكتب تاج الـ panel. وheading وcollapsible الـ inputs بتوع الـ panel: القيم العادية بتدخل من الـ attributes، زي أي component.

  2. 2settings.component.htmlparent · writes the contentالأب · بيكتب المحتوى
      <button slot="actions" (click)="reset()">Reset</button>  <button banana="potato" (click)="pepper()">Reset</button>

    Markup goes in between the tags. The parent labels this button slot="actions". Both words, slot and actions, are yours; Angular gives them no meaning. reset is the settings page’s own method.الـ markup بيدخل بين التاجات. الأب بيعلّم الزرار ده بـ slot="actions". الكلمتين، slot وactions، بتوعك؛ أنجولار مش بيديهم أي معنى. وreset ميثود صفحة الإعدادات نفسها.

  3. 3panel.component.htmlpanel · named slotالـ panel · slot متسمّي
        <ng-content select="[slot=actions]" />    <ng-content select="[banana=potato]" />

    The panel leaves a hole in its header. ng-content and select are Angular’s. The value is a CSS selector: “children that have slot equal to actions”. It must match the parent letter for letter.الـ panel بيسيب فتحة في الهيدر بتاعه. ng-content وselect بتوع أنجولار. والقيمة CSS selector: «الأبناء اللي عليهم slot بيساوي actions». لازم تطابق الأب حرف حرف.

  4. 4panel.component.htmlpanel · default slotالـ panel · الـ slot الافتراضي
      <div class="body" [hidden]="!open()">  <div class="taco" [hidden]="!kiwi()">    <ng-content />  </div>

    A bare ng-content takes everything the named slots did not claim: the paragraph and the checkbox. open is the panel’s own signal; the settings page never sees it.ng-content من غير select بياخد كل اللي الـ slots المتسمّية ماخدتهوش: الفقرة والـ checkbox. وopen الـ signal بتاعة الـ panel نفسه؛ صفحة الإعدادات عمرها ما بتشوفها.

  5. 5settings.component.tsparent · the click lands hereالأب · الكليك بيوصل هنا
    reset() {pepper() {  this.emailOn.set(true);  this.lemon.set(true);}

    The user clicks Reset inside the panel’s header, and the settings page’s reset runs. The panel only moved the button; it did not adopt it. That is why the panel can be reused by any page.المستخدم بيدوس Reset جوه هيدر الـ panel، والـ reset بتاعة صفحة الإعدادات هي اللي بتشتغل. الـ panel نقل الزرار بس؛ ماتبنّاهوش. وعشان كده الـ panel ينفع يتستخدم في أي صفحة.

The whole thing in one lineالحكاية كلها في سطر

Parent: slot="actions". Panel: select="[slot=actions]". That pair is the only name projection makes the two components share. Everything written between the tags keeps belonging to the parent.الأب: slot="actions". الـ panel: select="[slot=actions]". الاتنين دول هما الاسم الوحيد اللي الـ projection بيخلي الاتنين components يتشاركوا فيه. وكل حاجة مكتوبة بين التاجات بتفضل بتاعة الأب.

Panel or parent?الـ panel ولا الأب؟

Who writes what, and who picks the nameمين بيكتب إيه، ومين بيختار الاسم

  • Whoever writes the markup owns it. Its bindings, its (click) handlers and its CSS all belong to the component whose file it is written in, even when it shows up inside another component.اللي بيكتب الـ markup هو صاحبه. الـ bindings والـ (click) والـ CSS بتوعه كلهم بتوع الـ component اللي اتكتب في ملفه، حتى لو ظهر جوه component تاني.
  • Inputs carry values, projection carries markup. A string heading goes through an input. A button, a paragraph or a whole form goes between the tags.الـ inputs بتشيل قيم، والـ projection بيشيل markup. عنوان نصي بيعدّي من input. زرار أو فقرة أو فورم كامل بيدخلوا بين التاجات.
  • The panel never names the parent’s things. It only knows its own slot names. That is what lets the settings page, the profile page and the billing page all reuse it.الـ panel عمره ما بيسمّي حاجات الأب. هو يعرف أسماء الـ slots بتاعته بس. وده اللي بيخلي صفحة الإعدادات وصفحة البروفايل وصفحة الفواتير يستخدموه كلهم.
