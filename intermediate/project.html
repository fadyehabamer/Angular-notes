Step 02الخطوة 02

A typed API serviceخدمة API بأنواع

One file owns the server. Components never import HttpClient; they import methods that return typed observables. When the API changes — and it will — you change one file.ملف واحد هو اللي بيمسك السيرفر. الـ components عمرك ما هتستورد HttpClient؛ بتستورد methods بترجّع observables بأنواع. لما الـ API يتغير — وهي هتتغير — هتغير ملف واحد.

src/app/api/product.tstypesأنواع
export interface ApiProduct {  id: number;  title: string;  price: number;  category: string;  description: string;  image: string;}
src/app/api/store-api.service.tsnew fileملف جديد
import { Injectable, inject } from '@angular/core';import { HttpClient } from '@angular/common/http';import { ApiProduct } from './product'; @Injectable({ providedIn: 'root' })export class StoreApi {  private http = inject(HttpClient);  private base = 'https://fakestoreapi.com';   products(category?: string) {    const url = category      ? `${this.base}/products/category/${category}`      : `${this.base}/products`;    return this.http.get<ApiProduct[]>(url);  }   product(id: number) {    return this.http.get<ApiProduct>(`${this.base}/products/${id}`);  }   categories() {    return this.http.get<string[]>(`${this.base}/products/categories`);  }}
src/app/app.config.tsregister HTTPسجّل HTTP
import { provideHttpClient } from '@angular/common/http'; export const appConfig: ApplicationConfig = {  providers: [    provideZoneChangeDetection({ eventCoalescing: true }),    provideRouter(routes),    provideHttpClient(),  ],};
Best practice — one API service per backendعادة صح — خدمة API واحدة لكل backend

Notice what the service does not do: no caching policy, no retry, no error toasts. Those are cross-cutting concerns that arrive as an interceptor in step 08. The service stays a thin, typed mirror of the HTTP surface.خد بالك من اللي الـ service مش بتعمله: لا caching ولا retry ولا رسايل error. دي حاجات عرضية بتيجي كـ interceptor في الخطوة 08. الـ service تفضل مراية رفيعة ومكتوبة بأنواع لسطح الـ HTTP.

Step 03الخطوة 03

Product list: loading, ready, error, emptyليستة المنتجات: تحميل وجاهز وخطأ وفاضي

Four states on every screen that touches a server: loading, ready, error, empty. Amateurs render the ready state only; you will render all four, every time.أربع حالات في أي شاشة بتلمس سيرفر: تحميل، وجاهز، وخطأ، وفاضي. المبتدئين بيظهروا حالة الجاهز بس؛ وإنت هتظهر الأربعة كل مرة.

src/app/pages/product-list/product-list.tsnew pageصفحة جديدة
import { Component, inject, signal } from '@angular/core';import { RouterLink } from '@angular/router';import { toSignal } from '@angular/core/rxjs-interop';import { StoreApi } from '../../api/store-api.service';import { ApiProduct } from '../../api/product'; type Load<T> =  | { state: 'loading' }  | { state: 'ready'; data: T }  | { state: 'error'; msg: string }  | { state: 'empty' }; @Component({  selector: 'product-list',  imports: [RouterLink],  template: `    <h1>Products</h1>     @for (c of cats(); track c) {      <button (click)="pick(c)"              [class.on]="c === picked()">{{ c }}</button>    }     @switch (load().state) {      @case ('loading') { <p>Loading…</p> }      @case ('error')   { <p>{{ load().msg }}</p> }      @case ('empty')   { <p>No products in this category.</p> }      @case ('ready')   {        <ul>          @for (p of load().data; track p.id) {            <li>              <a [routerLink]="['/product', p.id]">{{ p.title }}</a>              — {{ p.price }}            </li>          }        </ul>      }    }  `})export class ProductList {  private api = inject(StoreApi);   picked = signal<string | undefined>(undefined);  load = signal<Load<ApiProduct[]>>({ state: 'loading' });   cats = toSignal(this.api.categories(), { initialValue: [] as string[] });   pick(c: string) { this.picked.set(c); this.fetch(); }   private fetch() {    this.load.set({ state: 'loading' });    this.api.products(this.picked()).subscribe({      next: ps => this.load.set(ps.length        ? { state: 'ready', data: ps } : { state: 'empty' }),      error: () => this.load.set({        state: 'error',        msg: 'Could not reach the shop. Try again.' })    });  }}
Best practice — model the states, do not improvise themعادة صح — اكتب الحالات كنوع، ومتخترعهاش في الطريق

The Load<T> union makes it impossible to render data you do not have: inside @case ('ready') the compiler knows load().data exists. A loading: boolean flag cannot give you that guarantee — it is the source of the classic undefined-list bug. Topic 22 showed toSignal; the union shape is what you graduate to when the states get real.اتحاد Load<T> بيخلي عرض داتا معندكش فيها حاجة مستحيل: جوه @case ('ready') الـ compiler عارف إن load().data موجودة. علم loading: boolean مش هيديك الضمانة دي — وهو مصدر باج الليستة undefined الكلاسيكي. الموضوع 22 وراك toSignal؛ وشكل الاتحاد ده اللي بتتدرّج ليه لما الحالات تبقى حقيقية.

Checkpointنقطة فحص

Products render with working category buttons. Prove the error state: DevTools → Network → Offline, reload, and you see the friendly message instead of a blank page. Turn the network back on, click a category, and it recovers.المنتجات بتظهر وزار الفئات شغال. اثبت حالة الخطأ: DevTools ← Network ← Offline، واعمل reload، وهتشوف الرسالة اللطيفة بدل صفحة فاضية. رجّع النت ودوس على فئة، وهيرجع شغال.

Step 08الخطوة 08

An interceptor: retry and a friendly messageInterceptor: إعادة محاولة ورسالة لطيفة

One function through which every HTTP call flows. That is where cross-cutting concerns live: retrying flaky requests, normalising errors, logging.دالة واحدة بيمر عليها كل نداءات الـ HTTP. دي المكان اللي الحاجات العرضية بتعيش فيه: إعادة المحاولة، وتوحيد الأخطاء، والتسجيل.

src/app/api/api.interceptor.tsnew fileملف جديد
import { HttpInterceptorFn } from '@angular/common/http';import { catchError, retry, throwError } from 'rxjs'; export const apiInterceptor: HttpInterceptorFn = (req, next) =>  next(req).pipe(    retry({ count: 2, delay: 400 }),   // transient network hiccups    catchError(err => {      const msg = err.status === 404        ? 'Not found.'        : 'Network problem — try again.';      return throwError(() => new Error(msg));    })  );
src/app/app.config.tsregister itسجّله
import { provideHttpClient, withInterceptors } from '@angular/common/http';import { apiInterceptor } from './api/api.interceptor'; provideHttpClient(withInterceptors([apiInterceptor]))
Retry GETs, never blindly retry POSTsأعِد الـ GET، وعمرك ما تعيد POST بثقة

Public APIs fail transiently all the time; two quick retries fix most of it for three lines of code. But a retried POST can double an order — topics 22 and 23 draw that line. In real code, retry only idempotent requests.الـ APIs العامة بتفشل فجائي طول الوقت؛ ومحاولتين سريعين بيحلوا معظمها بثلاث سطور. بس الـ POST اللي بيتعاد ممكن يضاعف الأوردر — الموضوعين 22 و23 بيرسموا الخط ده. في الكود الحقيقي، أعِد بس الطلبات اللي مفيهاش ضرر لو اتكررت.

Checkpointنقطة فحص

Kill your network during a category switch: the retry buys you a beat before the error lands, and the message is yours, not the browser's.قطّع النت أثناء تبديل الفئة: الـ retry بيشتريلك ثانية قبل ما الخطأ يوصل، والرسالة رسالتك إنت، مش رسالة البراوزر.
