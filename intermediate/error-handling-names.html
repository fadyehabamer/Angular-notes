Error handling, name by nameالتعامل مع الأخطاء، اسم اسم

The idea is simple: retry what might work, tell the person in words, and give them a way out. The confusing part is the names. handleError looks like a name you chose, and it is not. err looks like an RxJS word, and it is yours. And error appears four times in one file with four owners. This page sorts every one of them.الفكرة بسيطة: جرّب تاني اللي ممكن ينجح، وقول للشخص بكلام مفهوم، وادّيله مخرج. اللي بيلخبط هو الأسماء. handleError شكله اسم انت اخترته، وهو مش كده. وerr شكله كلمة RxJS، وهو بتاعك. وerror بتظهر أربع مرات في ملف واحد وليها أربع أصحاب. الصفحة دي بترتّب كل واحد فيهم.

The whole thing in one lineالحكاية كلها في سطر

HTTP failures: retry → catchError → toasts.show(…) → throwError → the page’s orders.error() → Try again. Everything else: Angular → handleError. The names files share are show, Toasts, errorInterceptor and GlobalErrorHandler.أخطاء الـ HTTP: retry ← catchError ← toasts.show(…) ← throwError ← orders.error() في الصفحة ← Try again. أي حاجة تانية: أنجولار ← handleError. الأسماء اللي الملفات متشاركة فيها هي show وToasts وerrorInterceptor وGlobalErrorHandler.

Why is err yours? Because RxJS passes values by position. catchError calls your function with the error first. delay calls it with the error first and the attempt number second. status and message on err are Angular’s fields. status is the HTTP code; 0 means the request never reached a server (offline, blocked, or CORS). count and delay are the only keys retry understands, apart from resetOnSuccess.status وmessage اللي على err fields بتاعة أنجولار. status هو كود الـ HTTP؛ و0 معناها الـ request موصلش لأي سيرفر (مفيش نت، أو اتمنع، أو CORS). وcount وdelay هما المفتاحين الوحيدين اللي retry فاهمهم، غير resetOnSuccess.
