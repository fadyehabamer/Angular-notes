Component styles, name by nameستايلات الـ component، اسم اسم

The idea is simple: a component’s CSS only styles that component’s own template. The confusing part is the names. A class name is a promise between two files, and nothing checks it. sold-out and soldOut sit on the same line and are two different names. :host looks like a class you made and is not. This page sorts out which names are yours, which are CSS’s, which are Angular’s, and which files have to agree.الفكرة بسيطة: الـ CSS بتاع الـ component بيستايل التمبلت بتاعه هو بس. اللي بيلخبط هو الأسماء. اسم الـ class وعد بين ملفين، ومحدش بيراجعه. sold-out وsoldOut قاعدين على نفس السطر وهما اسمين مختلفين. و:host شكلها class انت عاملها وهي مش كده. الصفحة دي بتفرز أنهي أسماء بتاعتك، وأنهي بتاعة CSS، وأنهي بتاعة أنجولار، وأنهي ملفات لازم تتفق.

  1. 1card.component.tscard · links its CSSالكارت · بيربط الـ CSS بتاعه
    styleUrl: './card.component.css',

    styleUrl is Angular’s key; the path is yours. This line is what makes the stylesheet belong to the card. Everything in that file will only ever style the card’s own template.styleUrl مفتاح أنجولار؛ والمسار بتاعك. السطر ده هو اللي بيخلّي الـ stylesheet ملك الكارت. كل حاجة في الملف ده هتستايل تمبلت الكارت بس، ومفيش غيره.

  2. 2card.component.htmlcard · names the classesالكارت · بيسمّي الـ classes
    <h3 class="title" [class.sold-out]="soldOut()">{{ product().name }}</h3><h3 class="banana" [class.sold-potato]="radish()">{{ pepper().biscuit }}</h3>

    Three different kinds of name on one line. title and sold-out are CSS class names you picked. class in [class.…] is Angular’s. soldOut on the right is a TypeScript value that decides whether the class is on.تلات أنواع أسماء على سطر واحد. title وsold-out أسماء CSS classes انت اخترتها. وclass في [class.…] بتاعة أنجولار. وsoldOut اللي على اليمين قيمة TypeScript بتقرر الـ class تتحط ولا لأ.

  3. 3card.component.csscard · styles themالكارت · بيستايلهم
    .title { margin: 0; color: var(--card-title, inherit); }.banana { margin: 0; color: var(--turnip, inherit); }.sold-out { opacity: 0.5; text-decoration: line-through; }.sold-potato { opacity: 0.5; text-decoration: line-through; }

    The stylesheet types the same class names again. Nothing connects them except the spelling. var is CSS’s; --card-title is a variable name you invented so the parent can change the colour later.الـ stylesheet بيكتب نفس أسماء الـ classes تاني. مفيش حاجة بتربطهم غير الكتابة. var بتاعة CSS؛ و--card-title اسم variable انت اخترعته عشان الأب يقدر يغيّر اللون بعدين.

  4. 4what the browser receivesthe browser · the trickالمتصفح · الحيلة
    <app-card _nghost-ng-c123 class="featured"><app-muffin _nghost-ng-c123 class="mango">  <h3 _ngcontent-ng-c123 class="title">Wireless mouse</h3>  <h3 _ngcontent-ng-c123 class="banana">Wireless mouse</h3></app-card></app-muffin>

    Angular stamps an attribute like _ngcontent-ng-c123 on every element of the card’s template, and quietly rewrites your rule to .title[_ngcontent-ng-c123]. An h3 in another component has a different number, so your rule cannot touch it. You never type these names.أنجولار بيختم attribute زي _ngcontent-ng-c123 على كل عنصر في تمبلت الكارت، وبيعيد كتابة الـ rule بتاعتك في السر لـ .title[_ngcontent-ng-c123]. أي h3 في component تاني عليه رقم تاني، فالـ rule بتاعتك مستحيل تلمسه. وانت عمرك ما بتكتب الأسماء دي.

  5. 5shop.component.htmlshop · classes the tagالمحل · بيحط class على التاج
    <app-card [product]="item" [class.featured]="item.promoted" /><app-muffin [pepper]="koshary" [class.mango]="koshary.melon" />

    The shop cannot style what is inside the card, but it owns the <app-card> tag itself. So it puts a class on it: featured, a word you picked. The data field is promoted: a different name, on purpose.المحل مايقدرش يستايل اللي جوه الكارت، بس هو صاحب تاج <app-card> نفسه. فبيحط عليه class: featured، كلمة انت اخترتها. والـ field اللي في الداتا اسمه promoted: اسم تاني، عن قصد.

  6. 6card.component.csscard · reacts to its tagالكارت · بيرد على التاج بتاعه
    :host(.featured) {:host(.mango) {  border-color: var(--brand);  border-color: var(--noodle);}

    :host is Angular’s name for “my own tag”. :host(.featured) means “when my tag has the class featured”. That word must match what the shop wrote. --brand comes from the global styles.css.:host اسم أنجولار لـ «التاج بتاعي». و:host(.featured) معناها «لما التاج بتاعي يبقى عليه الـ class اللي اسمها featured». الكلمة دي لازم تطابق اللي المحل كتبه. و--brand جاية من styles.css العام.

The whole thing in one lineالحكاية كلها في سطر

A class name is a promise between a template and a stylesheet of the same component. The only things that cross from one component to another are classes on the host tag (read with :host(…)) and CSS variables. And no compiler checks any of these names.اسم الـ class وعد بين تمبلت وstylesheet لنفس الـ component. والحاجات الوحيدة اللي بتعدّي من component لتاني هي الـ classes اللي على تاج الـ host (بتتقري بـ :host(…)) والـ CSS variables. ومفيش compiler بيراجع أي اسم من دول.

  • A stylesheet styles the template it is linked to with styleUrl. Not the parent’s template, not the children’s. Put the rule where the element is written.الـ stylesheet بيستايل التمبلت اللي مربوط بيه بـ styleUrl. مش تمبلت الأب، ولا تمبلتس الأبناء. حط الـ rule مكان ما العنصر اتكتب.
  • The host tag is the one element two components share. The parent writes <app-card class="…"> and styles it from outside; the card styles the same tag from inside with :host.تاج الـ host هو العنصر الوحيد اللي اتنين components بيشوفوه. الأب بيكتب <app-card class="…"> وبيستايله من برّه؛ والكارت بيستايل نفس التاج من جوه بـ :host.
  • Variables cross the wall; class names do not. A --variable set on any ancestor is inherited by everything inside, whatever component wrote it.الـ variables بتعدّي الحيطة؛ أسماء الـ classes لأ. أي --variable متحطوطة على أي جد، كل اللي جواه بيورثها، مهما كان مين الـ component اللي كتبه.

Where the spelling is not freeفين الكتابة مش براحتك

Your names are free, but a few rules decide how they must be written.أسماءك براحتك، بس فيه كام قاعدة بتقرر لازم تتكتب إزاي.

AVariables need two dashes, and case mattersالـ variables محتاجة شرطتين، والحروف الكبيرة فارقة

CSS decides that a custom property starts with --. After that the name is yours, but it is case-sensitive: --Brand and --brand are two different variables.الـ CSS هو اللي قرر إن الـ custom property بتبدأ بـ --. بعد كده الاسم بتاعك، بس الحروف الكبيرة والصغيرة فارقة: --Brand و--brand اتنين variables مختلفين.

BDashed class names need quotes in an objectأسماء الـ classes اللي فيها شرطة محتاجة quotes في الـ object

Mistakes that fail silentlyغلطات بتفشل في صمت

Every mistake on this list is valid CSS. The browser applies what matches and ignores the rest, without a word.كل غلطة في الليستة دي CSS سليم. المتصفح بيطبق اللي بيطابق وبيتجاهل الباقي، من غير ولا كلمة.

1Styling the child’s class from the parentتستايل class بتاعة الابن من الأب
shop.component.cssavoidتجنّب
.title { color: navy; }.banana { color: navy; }
shop.component.cssdo thisاعمل كده
.shelf { --card-title: navy; }.waffle { --turnip: navy; }

The h3.title is written in the card’s template, so it carries the card’s attribute, not the shop’s. The shop’s rule becomes .title[_ngcontent-…shop…] and never matches. Set a variable the card reads instead.الـ h3.title مكتوب في تمبلت الكارت، فعليه الـ attribute بتاع الكارت، مش بتاع المحل. الـ rule بتاعة المحل بتبقى .title[_ngcontent-…shop…] وعمرها ما بتطابق. حط variable الكارت بيقراها بدل كده.

2The TypeScript name used as the class nameاسم الـ TypeScript مستخدم كاسم الـ class
card.component.htmlavoidتجنّب
<h3 class="title" [class.soldOut]="soldOut()">…</h3><h3 class="banana" [class.soldOut]="radish()">…</h3>
card.component.htmldo thisاعمل كده
<h3 class="title" [class.sold-out]="soldOut()">…</h3><h3 class="banana" [class.sold-potato]="radish()">…</h3>

The left side names the CSS class; the right side is the TS value. Writing soldOut on both sides puts a class called soldOut on the heading, while the stylesheet waits for sold-out.الناحية الشمال بتسمّي الـ CSS class؛ واليمين قيمة الـ TS. لو كتبت soldOut في الناحيتين، هتتحط class اسمها soldOut على العنوان، والـ stylesheet مستني sold-out.

3A space after :hostمسافة بعد :host
card.component.cssavoidتجنّب
:host .featured {:host .mango {  border-color: var(--brand);  border-color: var(--noodle);}
card.component.cssdo thisاعمل كده
:host(.featured) {:host(.mango) {  border-color: var(--brand);  border-color: var(--noodle);}

With a space, it means “an element with class featured inside my tag”. There is none. With brackets, it means “my tag itself has the class”.بالمسافة، معناها «عنصر عليه class featured جوه التاج بتاعي». ومفيش. وبالقوسين، معناها «التاج بتاعي نفسه عليه الـ class».

4A variable spelled two waysvariable مكتوبة بطريقتين
shop.component.cssavoidتجنّب
.shelf { --cardTitle: navy; }.waffle { --cardTitle: navy; }
shop.component.cssdo thisاعمل كده
.shelf { --card-title: navy; }.waffle { --turnip: navy; }

The card reads --card-title. Nobody set that one, so var() falls back to inherit and the title keeps its normal colour.الكارت بيقرا --card-title. ومحدش حط دي، فـ var() بترجع للـ fallback inherit والعنوان بيفضل بلونه العادي.

5Forgetting display on :hostنسيان display على :host
card.component.cssavoidتجنّب
:host {  width: 240px;}
card.component.cssdo thisاعمل كده
:host {  display: block;  width: 240px;}

Not a naming mistake, but it looks like one. A custom tag like <app-card> is inline by default, and inline elements ignore width. The rule matched; it just had no effect.مش غلطة أسماء، بس شكلها كده. التاج المتألف زي <app-card> بيبقى inline افتراضيًا، والعناصر الـ inline بتتجاهل width. الـ rule طابقت؛ بس مالهاش تأثير.

When it does nothingلما مايعملش حاجة

Five questions, in this orderخمس أسئلة، بالترتيب ده

Your style “does not apply”. Ask these before adding !important or ::ng-deep.الستايل بتاعك «مش بيتطبق». اسأل الأسئلة دي قبل ما تزوّد !important أو ::ng-deep.

Checkpointنقطة فحص

1. Which component’s template writes this element? Is your rule in that component’s stylesheet?1. تمبلت أنهي component هو اللي كاتب العنصر ده؟ الـ rule بتاعتك في الـ stylesheet بتاع الـ component ده؟

Checkpointنقطة فحص

2. Is the class spelled exactly the same in the template and the CSS: dashes, capitals, no TS name by mistake?2. الـ class مكتوبة بالظبط نفس الشكل في التمبلت والـ CSS: الشرط، والحروف الكبيرة، ومفيش اسم TS بالغلط؟

Checkpointنقطة فحص

3. Styling the component’s own tag? Use :host or :host(.x) without a space, and give it a display.3. بتستايل تاج الـ component نفسه؟ استخدم :host أو :host(.x) من غير مسافة، وادّيله display.

Checkpointنقطة فحص

4. Using a variable? Is it set on an ancestor of the element, with -- and the same spelling and case?4. بتستخدم variable؟ متحطوطة على حاجة فوق العنصر، بـ -- وبنفس الكتابة والحروف؟

Checkpointنقطة فحص

5. In DevTools: does the element have the class? Is your rule listed, and is it crossed out by a stronger one?5. في الـ DevTools: العنصر عليه الـ class؟ الـ rule بتاعتك ظاهرة، ولا متشطبة عشان فيه واحدة أقوى منها؟
