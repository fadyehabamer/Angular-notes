Routes are data, guards are functionsالـ routes مجرد داتا، والـ guards مجرد functions

A route config is a plain array you read top to bottom. Lazy loading is one property. Guards are functions that can inject() anything — and the difference between canMatch and canActivate decides whether an unauthorised user downloads your admin bundle.ملف الـ routes مصفوفة عادية تقراها من فوق لتحت. الـ lazy loading سطر واحد. والـ guards functions تقدر تعمل inject() لأي حاجة — والفرق بين canMatch وcanActivate هو اللي بيحدد هل اللي مش مصرّح له هينزّل bundle الأدمن ولا لأ.

What it actually isهي إيه بالظبط

Routes are just an array of objects, and guards are just functions that return true or false. There is no magic here.الـ routes مجرد array من الـ objects، والـ guards مجرد دوال بترجّع true أو false. مفيش سحر هنا.

Think of it likeاعتبرها زي

A building directory plus a security guard at the lift. The list says which floor; the guard decides whether you get on.دليل مبنى وحارس أمن عند الأسانسير. اللستة بتقول أنهي دور، والحارس بيقرر تركب ولا لأ.

You reach for it whenهتحتاجها لما

Login-only pages, admin areas, unsaved-changes warnings, and screens that need data before they draw.الصفحات اللي للمسجّلين بس، ومناطق الأدمن، وتحذير التغييرات غير المحفوظة، والشاشات المحتاجة داتا قبل ما ترسم.

Every name on this page — yours or Angular’s?كل اسم في الصفحة دي — بتاعك ولا بتاع أنجولار؟

Every key in a route object (path, loadComponent, canActivate…) is Angular’s. The values are yours, and many of them are promises: with withComponentInputBinding(), :id, ?status= and data: { section } must be spelled exactly like the inputs they fill.كل مفتاح في الـ route object (path، loadComponent، canActivate…) بتاع أنجولار. أما القيم فبتاعتك، وكتير منها وعود: مع withComponentInputBinding()، الـ :id والـ ?status= والـ data: { section } لازم يتكتبوا بالظبط زي الـ inputs اللي بيملوها.

Watch outخد بالك

  • canActivate runs after the lazy chunk downloads. For role-gated features use canMatch so the bundle is never even requested.canActivate بيشتغل بعد ما الـ chunk ينزل. للحاجات المربوطة بصلاحيات استعمل canMatch عشان الـ bundle ميتطلبش أصلاً.
  • Route order matters. ** must be last, and a path: '' without pathMatch: 'full' matches everything.ترتيب الراوتس مهم. ** لازم تبقى الأخيرة، وpath: '' من غير pathMatch: 'full' بيطابق كل حاجة.
  • Reading route.snapshot.params once is the classic bug: navigating /user/1 → /user/2 reuses the component and the snapshot never changes. Use input binding or paramMap.قراية route.snapshot.params مرة واحدة دي الباج الكلاسيكي: التنقل من /user/1 لـ /user/2 بيعيد استخدام نفس الـ component والـ snapshot مبيتغيرش. استعمل input binding أو paramMap.
  • withComponentInputBinding() only fills inputs whose name matches the param, query param or data key. A typo is silent.withComponentInputBinding() بيملا بس الـ inputs اللي اسمها مطابق للـ param أو الـ query param أو مفتاح الـ data. أي غلطة إملائية بتعدي بالسكوت.
  • Query params arrive as strings. input(1, { transform: numberAttribute }) saves you a pile of +x conversions.الـ query params بتوصل strings. وinput(1, { transform: numberAttribute }) بيوفر عليك كومة تحويلات +x.

Q01 A guard returns false. What happens?guard رجّع false. إيه اللي بيحصل؟
whyليه

A falsy guard result aborts the navigation entirely. Returning a UrlTree instead — return router.parseUrl('/login') — cancels it and sends the user somewhere useful, which is almost always what you want.لو الـ guard رجّع قيمة كاذبة، التنقل بيتلغي بالكامل. ولو رجّعت UrlTree بدالها — return router.parseUrl('/login') — بتلغيه وكمان بتوصّل المستخدم لمكان مفيد، وده اللي إنت عايزه في الغالب.

Q02 Where must the wildcard route { path: '**' } go?مسار الـ wildcard { path: '**' } لازم يكون فين؟
whyليه

The router walks the array top to bottom and stops at the first match. Put '**' anywhere but last and it swallows every route below it — your app becomes one big 404 page.الـ router بيمشي في المصفوفة من فوق لتحت وبيوقف عند أول تطابق. ولو حطيت '**' في أي مكان غير الآخر، هيبلع كل المسارات اللي تحته — وتطبيقك يبقى صفحة 404 كبيرة.

Q03 loadComponent versus loadChildren — which is which?loadComponent مقابل loadChildren — مين فيهم إيه؟
whyليه

loadComponent lazily loads one page. loadChildren lazily loads a whole child route array — a settings area with five tabs, say — so the entire section becomes one chunk.loadComponent بتحمّل صفحة واحدة عند الحاجة. وloadChildren بتحمّل مصفوفة مسارات فرعية كاملة — زي قسم إعدادات فيه خمس تابات — فالقسم كله يبقى حزمة واحدة.

Q04 Navigating /user/1 → /user/2 does not reload the data. Why?التنقل من /user/1 لـ /user/2 مش بيعيد تحميل البيانات. ليه؟
whyليه

Angular reuses the component rather than destroying it, so a route.snapshot read in ngOnInit happens once and never again. Subscribe to route.paramMap, or use route input binding with an effect().أنجولار بيستخدم الـ component تاني بدل ما يهدمه، فقراية route.snapshot في ngOnInit بتحصل مرة واحدة وخلاص. اعمل subscribe لـ route.paramMap، أو استخدم ربط الـ inputs بالمسار مع effect().
