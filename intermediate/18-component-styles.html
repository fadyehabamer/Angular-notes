Why your CSS does not reach the childليه الـ CSS بتاعك مش واصل للابن

Styles written in a component file apply to that component only. This surprises everybody once, and it is deliberate: it is what stops a class named .card in one feature from silently restyling a different .card across the app.الاستايلات اللي بتتكتب في ملف component بتتطبق على الـ component ده بس. ودي بتفاجئ الكل مرة، وهي مقصودة: هي اللي بتمنع class اسمه .card في فيتشر إنه يغيّر شكل .card تاني في التطبيق من غير ما حد ياخد باله.

What it actually isهي إيه بالظبط

Your component's CSS is locked inside that component. It does not leak out, and it does not reach in.الـ CSS بتاع الـ component مقفول جواه. مش بيتسرّب لبره، ومش بيوصل لجوه.

Think of it likeاعتبرها زي

A hotel room. You can repaint your own room freely, and it never changes the room next door — that is the point of the walls.أوضة في فندق. تقدر تدهن أوضتك زي ما إنت عايز، ومش هيتغيّر حاجة في الأوضة اللي جنبك — ودي فايدة الحيطان.

You reach for it whenهتحتاجها لما

Every time you write CSS. And especially the first time you shout why is my style not applying?في كل مرة تكتب CSS. وخصوصاً أول مرة تزعّق ليه الستايل مش شغال؟

Children are protectedالأبناء محميين

Your CSS stops at the child's tag. Its insides belong to it, not to you.الـ CSS بتاعك بيقف عند تاج الابن. جواه ملكه هو، مش ملكك.

::ng-deep breaks in::ng-deep بتخترق

It works, it is deprecated, and it is global. Always pair it with :host.بتشتغل، وبتتشال قريب، وعامة على المشروع كله. دايماً حطها مع :host.

Custom properties passالـ custom properties بتعدّي

CSS variables cross the boundary by design. This is the clean way to theme a child.متغيرات الـ CSS بتعدّي الحدود بتصميمها. دي الطريقة النضيفة إنك تنسّق ابن.

Real exampleمثال حقيقي Theming without ::ng-deepتغيير الثيم من غير ::ng-deep

The instinct when a child component looks wrong is to reach in with ::ng-deep. Custom properties do the job properly: the child declares what is themeable, and any ancestor can set it — including a caller in a different library.أول رد فعل لما component ابن يبقى شكله غلط هو إنك تمد إيدك بـ ::ng-deep. والمتغيرات المخصصة بتعمل الشغل صح: الابن بيعلن إيه اللي قابل للتغيير، وأي أب يقدر يحطه — حتى لو من مكتبة تانية.

Watch outخد بالك

  • A style in a component file will never reach inside a child component. That is the feature, not a bug — reach for CSS custom properties instead.الاستايل اللي في ملف component عمره ما هيوصل جوه component ابن. ودي ميزة مش باج — استعمل CSS custom properties بدالها.
  • ::ng-deep is deprecated and it leaks: once a rule pierces the boundary it applies globally, not just under your component. Scope it with :host at minimum.::ng-deep مهجورة وبتسرّب: أول ما قاعدة تخترق الحاجز بتتطبق عالمياً، مش تحت الـ component بتاعك بس. على الأقل احصرها بـ :host.
  • ViewEncapsulation.None makes that component’s styles global, permanently, for the whole app. It is almost never the right answer.ViewEncapsulation.None بتخلي استايلات الـ component دي عامة، بشكل دائم، للتطبيق كله. وتقريباً عمرها ما بتكون الحل الصح.
  • A component has no display value of its own — a custom element is display: inline by default. Set :host { display: block } or your widths and margins will be ignored.الـ component مالوش قيمة display خاصة بيه — العنصر المخصص بيبقى display: inline افتراضياً. حط :host { display: block } وإلا العرض والهوامش هيتجاهلوا.
  • [style.color]="null" removes the inline style. Returning '' or undefined also works — but null is the explicit way to say “no value”.[style.color]="null" بتشيل الاستايل الـ inline. و'' أو undefined بيشتغلوا كمان — بس null هي الطريقة الصريحة اللي معناها «مفيش قيمة».
If you remember one thingلو هتفتكر حاجة واحدة

Angular adds a hidden attribute to your elements and rewrites your selectors to match it. That is the whole trick.أنجولار بيضيف attribute مخفي لعناصرك وبيعيد كتابة الـ selectors عشان تطابقه. دي الحيلة كلها.
