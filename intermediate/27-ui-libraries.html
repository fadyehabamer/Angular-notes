Angular Material and the CDKAngular Material والـ CDK

Do not hand-build a date picker, a data table with sorting, or an accessible dialog. Material gives you finished components; the CDK underneath it gives you the hard behaviour — overlays, focus traps, virtual scrolling — with no styling at all, so you can put your own design on top.متبنيش بإيدك date picker ولا جدول بترتيب ولا dialog متاح للجميع. Material بيديك components جاهزة؛ والـ CDK اللي تحتيه بيديك السلوك الصعب — الـ overlays وحصر الـ focus والـ virtual scrolling — من غير أي تنسيق، فتقدر تحط تصميمك إنت فوقه.

What it actually isهي إيه بالظبط

Angular Material is ready-made components. The CDK is the machinery underneath them, with no styling at all.Angular Material هو components جاهزة. والـ CDK هو الميكانيكا اللي تحتيها، من غير أي تنسيق.

Think of it likeاعتبرها زي

Material is furniture from a shop. The CDK is the hinges, rails and casters — so you can build furniture nobody sells.Material زي أثاث من محل. والـ CDK هو المفصلات والسكك والعجل — عشان تعمل أثاث محدش بيبيعه.

You reach for it whenهتحتاجها لما

Material when you want a working app this week. The CDK when the design does not match anybody's component library.Material لما تعوز تطبيق شغال الأسبوع ده. والـ CDK لما التصميم مايطابقش أي مكتبة components.

The whole idea in 4 picturesالفكرة كلها في 4 صور

Material gives componentsMaterial بيدّي components

Buttons, dialogs, tables, date pickers — themed, tested and accessible out of the box.أزرار وديالوجات وجداول ومنتقيات تواريخ — منسّقة ومختبرة ومتاحة للجميع من أول لحظة.

The CDK gives behaviourالـ CDK بيدّي سلوك

Overlay, drag-drop, focus trapping, virtual scroll — with zero opinions about looks.overlay وسحب وإفلات وحصر الـ focus وvirtual scroll — من غير أي رأي في الشكل.

Theme with tokensنسّق بالـ tokens

Material 3 themes are CSS custom properties. Override the tokens, not the components.ثيمات Material 3 عبارة عن CSS custom properties. غيّر الـ tokens، مش الـ components.

Weigh the bundleاحسب حجم الحزمة

Import only the components you use. Importing the whole library is a real cost.استورد الـ components اللي بتستعملها بس. استيراد المكتبة كلها تكلفة حقيقية.

which library?the decisionالقرار
// ANGULAR MATERIAL//   ✓ first-party, tracks every Angular release, superb a11y//   ✓ the safe default for an internal tool or a dashboard//   ✗ looks like Google unless you invest in theming // PRIMENG / NG-ZORRO / KENDO//   ✓ far more components — tables, charts, org charts, editors//   ✗ third-party: an Angular major release can strand you // TAILWIND + THE CDK//   ✓ total design freedom, tiny runtime, no component API to learn//   ✗ you build every component yourself (the CDK does the hard parts) // A REAL RULE: whatever you pick, pick ONE. two component// libraries in one app means two themes, two sets of a11y bugs,// and two focus-management strategies fighting each other.
Real exampleمثال حقيقي A 100,000-row table that stays smoothجدول 100,000 صف وفاضل سلس

Rendering a hundred thousand rows freezes the browser. Virtual scrolling renders only the twenty that fit on screen and recycles them as you scroll — and it is one wrapper element plus one directive.رسم مية ألف صف بيجمّد البراوزر. والـ virtual scrolling بيرسم العشرين اللي داخلين في الشاشة بس ويعيد استخدامهم وإنت بتنزل — وده عنصر لف واحد وdirective واحد.

import { ScrollingModule } from '@angular/cdk/scrolling'; @Component({  selector: 'app-big-list',  imports: [ScrollingModule],  template: `    <cdk-virtual-scroll-viewport itemSize="56" class="viewport">      <div *cdkVirtualFor="let row of rows(); templateCacheSize: 40"           class="row">        <strong>{{ row.name }}</strong>        <span>{{ row.email }}</span>      </div>    </cdk-virtual-scroll-viewport>  `,  styles: `.viewport { height: 600px } .row { height: 56px }`,})export class BigList {  readonly rows = signal<Row[]>(loadHundredThousand());} // itemSize MUST match the real row height, or scrolling drifts.

Watch outخد بالك

  • itemSize on a virtual scroll viewport must match the actual rendered row height in pixels. If it does not, the scrollbar and content drift apart.itemSize في الـ virtual scroll لازم يطابق ارتفاع الصف الحقيقي بالبكسل. ولو مش مطابق، الـ scrollbar والمحتوى بيبعدوا عن بعض.
  • The viewport needs an explicit height. Without one it collapses and renders nothing — the most common first-try failure.الـ viewport محتاج height صريح. ومن غيره بينهار ومبيرسمش حاجة — وده أشهر فشل من أول مرة.
  • Material components come pre-styled. Fighting them with ::ng-deep and !important is a losing game — use the theming API, or use the CDK and style it yourself.مكونات Material بتيجي منسّقة. والخناق معاها بـ ::ng-deep و!important معركة خاسرة — استعمل الـ theming API، أو استعمل الـ CDK ونسّق بنفسك.
  • Third-party libraries are a real upgrade risk. Before adopting one, check when it last released and whether it supports the current Angular major.المكتبات الخارجية خطر حقيقي وقت الترقية. قبل ما تعتمد واحدة، شوف آخر إصدار ليها إمتى وهل بتدعم إصدار أنجولار الحالي.
  • Do not import a whole library barrel just for one button. Import per component, or your first bundle jumps by hundreds of kilobytes.متعملش import لمكتبة كاملة عشان زرار واحد. اعمل import لكل component، وإلا أول bundle هيقفز بمئات الكيلوبايتات.
If you remember one thingلو هتفتكر حاجة واحدة

Reach for the CDK before you hand-roll an overlay, a drag handle or a virtual scroller. Accessibility is the part you will get wrong.استعمل الـ CDK قبل ما تعمل overlay أو drag أو virtual scroll بإيدك. الـ accessibility هي الحتة اللي هتغلط فيها.
