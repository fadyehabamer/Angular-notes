Part A: the to-do appالجزء الأول: تطبيق to-do

A task list sounds trivial. It is not: it is state (the list), derived state (how many are left), user input (add, toggle, remove) and the screen following all of it. Finish this and you have used every beginner topic at least once.قائمة مهام شكلها بسيط. هي مش كده: فيها حالة (الليستة)، وحالة مشتقة (فاضل كام)، وإدخال من المستخدم (ضيف، علّم، امسح)، والشاشة اللي بتحصلها كل ده. لما تخلّصها تكون استخدمت كل موضوع في المستوى المبتدئ مرة على الأقل.

npx @angular/cli@latest new todo --style=css --ssr=falsecd todo && ng serve
Step 01الخطوة 01

Look at what the CLI made youبُص على اللي الـ CLI عمله

Before writing anything, read the file that matters. This is the habit: never edit a file you have not read.قبل ما تكتب أي حاجة، اقرا الملف المهم. دي العادة: عمرك ما تعدّل في ملف إنت ماقرتوش.

src/app/app.tsread itاقراه
import { Component, signal } from '@angular/core'; @Component({  selector: 'app-root',  imports: [],                     // standalone: nothing is global,  template: `    <h1>{{ title() }}</h1>  `})export class App {  title = signal('todo');}

Three things to notice. The component is standalone — there is no NgModule anywhere, and imports is where you list directives and pipes you want in the template. The title is a signal, and the template reads it like a function: title(). And there is no separate .html or .css file yet — for small components, inline is fine.تلات حاجات تاخد بالك منهم. الـ component مستقل — مفيش NgModule في أي حتة، وimports هي المكان اللي بتكتب فيه أي directive أو pipe عايزها في التمبلت. الـ title بـsignal، والتمبلت بيقراها زي الدوال: title(). ومفيش ملف .html ولا .css منفصل لسه — في الـ components الصغيرة، السطر الواحد عادي.

Checkpointنقطة فحص

The app runs at localhost:4200 showing the word todo. Change the text inside signal('todo'), save, and watch the browser update without a reload — that loop is your whole day from now on.التطبيق شغال على localhost:4200 وعارض كلمة todo. غيّر النص اللي جوه signal('todo') واحفظ، وشوف البراوزر بيتحدث من غير reload — دي اللوب اللي هتعيش فيه من دلوقتي.

Step 03الخطوة 03

Render the list with @for — and track by idاعرض الليستة بـ @for — وtrack بـ id

The new control flow needs no import and no module. Its one rule people miss: every @for needs a track.الـ control flow الجديد مش محتاج import ولا module. القاعدة الواحدة اللي الناس بتفوتها: كل @for محتاجة track.

src/app/app.ts (template)templateالتمبلت
template: `  <h1>{{ title() }}</h1>  <ul>    @for (t of tasks(); track t.id) {      <li>{{ t.title }} @if (t.done) { ✓ }</li>    } @empty {      <li>Nothing yet.</li>    }  </ul>`
the trap you will hitavoidتجنّب
@for (t of tasks(); track t) {  …} // track t tracks the object identity.// Replacing the array with new objects re-creates// every <li> and loses focus and animation state.
track something stabledo thisاعمل كده
@for (t of tasks(); track t.id) {  …} // track t.id: the DOM node survives because// the id survives. One line, and it is the// difference between fast and janky lists.
Checkpointنقطة فحص

Two tasks on screen, the finished one with a ✓. In DevTools, the list is real <li> elements, not text.اتنين مهام على الشاشة، والتانية خلصانة عليها ✓. في الـ DevTools، الليستة عناصر <li> حقيقية، مش نص.

Step 04الخطوة 04

Add, toggle, remove — by replacing, not mutatingضيف، علّم، امسح — بالتبديل مش بالتعديل

This is the habit that separates people who struggle with Angular from people who do not: signals want new references. push and property assignment change the array's insides without telling anyone.دي العادة اللي بتفرّق اللي بيتعاونوا مع أنجولار عن اللي بيتعذبوا فيه: الـ signals عايزة references جديدة. الـ push وتعديل الخصائص بيغيّروا جوا المصفوفة من غير ما حد يعرف.

src/app/app.tsthe three verbsالأفعال التلاتة
export class App {  title = signal('todo');  tasks = signal<Task[]>([ /* … */ ]);  nextId = 3;   add(input: HTMLInputElement) {    const title = input.value.trim();    if (!title) return;    this.tasks.update(list =>      [...list, { id: this.nextId++, title, done: false }]);    input.value = '';  }   toggle(id: number) {    this.tasks.update(list =>      list.map(t => t.id === id ? { ...t, done: !t.done } : t));  }   remove(id: number) {    this.tasks.update(list => list.filter(t => t.id !== id));  }}
src/app/app.ts (template)wire the eventsوصّل الأحداث
template: `  <input #box placeholder="What needs doing?"         (keydown.enter)="add(box)">  <button (click)="add(box)">Add</button>   <ul>    @for (t of tasks(); track t.id) {      <li>        <input type="checkbox" [checked]="t.done"               (change)="toggle(t.id)">        {{ t.title }}        <button (click)="remove(t.id)">×</button>      </li>    }  </ul>`
Best practice — one way to each sideعادة صح — اتجاه واحد لكل ناحية

The checkbox is [checked] + (change), not [(ngModel)]. Data flows down, events flow up, and the signal stays the single source of truth. ngModel arrives much later, with forms.الـ checkbox بـ[checked] مع (change)، مش [(ngModel)]. الداتا بتنزل والأحداث بتعلى، والـ signal بتفضل المصدر الوحيد للحقيقة. الـ ngModel هتيجي بعدين مع الفورمز.

Checkpointنقطة فحص

You can add a task, tick it, and delete it, and the screen follows every action instantly. Also: add on an empty input does nothing — validation counts as part of the feature.تقدر تضيف مهمة، وتعلّم عليها، وتمسحها، والشاشة بتتابع كل حاجة فوراً. وكمان: add بإدخال فاضي مش بيعمل حاجة — الـ validation جزء من الفيتشر.

Step 05الخطوة 05

Extract a TodoStore serviceاستخرج خدمة TodoStore

Same behaviour, better shape. State that more than one component will ever need does not belong to a component — it belongs to an injectable in providedIn: 'root'.نفس السلوك، بشكل أحسن. الحالة اللي أكتر من component هيحتاجوها عمرها ما مكانها الصح في component — مكانها في injectable بـprovidedIn: 'root'.

src/app/todo-store.tsnew fileملف جديد
import { Injectable, signal, computed } from '@angular/core';import { Task } from './app'; @Injectable({ providedIn: 'root' })export class TodoStore {  private tasks = signal<Task[]>([ /* move the seed here */ ]);  private nextId = 3;   readonly left = computed(() =>    this.tasks().filter(t => !t.done).length);   readonly all = this.tasks.asReadonly();   add(title: string) {    if (!title.trim()) return;    this.tasks.update(list =>      [...list, { id: this.nextId++, title: title.trim(), done: false }]);  }  toggle(id: number) { /* same as before */ }  remove(id: number) { /* same as before */ }}
src/app/app.tsthe component gets thinالـ component بيبقى رفيع
import { Component, inject } from '@angular/core';import { TodoStore } from './todo-store'; @Component({ /* … */ })export class App {  title = signal('todo');  store = inject(TodoStore);   add(input: HTMLInputElement) { this.store.add(input.value); input.value = ''; }}
constructor injection — the old wayavoidتجنّب
constructor(  private store: TodoStore) {} // Works. But every field it feeds also needs// a constructor line, and classes grow.
inject() — the field you calldo thisاعمل كده
store = inject(TodoStore); // One line, no constructor, works in any// injection context, and reads left to right.
Best practice — readonly outside, writable insideعادة صح — readonly من بره، وكلاءة من جوه

The component reads store.all() and store.left() but can only call methods to change state. Exposing the raw writable signal would invite any component to .set() it — a bug factory. This in/out discipline is what code reviewers look for.الـ component بيقرا store.all() وstore.left() بس مش يقدر يغيّر غير عن طريق مناداة methods. لو كشفت الـ signal القابلة للكتابة، أي component هيبقى يقدر يعملها .set() — مصنع باجات. دي الديسسيبلين اللي مراجعي الكود بيدوروا عليها.

Checkpointنقطة فحص

Everything still works — add, tick, delete — and the component class is now mostly template concerns. left proves computed: tick a task and the count changes with zero extra code.كل حاجة شغالة زي ما هي — ضيف وعلّم وامسح — والـ component بقى خفيف ومش مسؤول عن المنطق. وleft بتثبت فكرة الـ computed: علّم على مهمة والعدد بيتغير من غير سطر كود زيادة.

Step 06الخطوة 06

The empty state, and the little a11y that mattersالحالة الفاضية، والإتاحة البسيطة اللي مهمة

Finishing is a skill. An empty list that says so, a label on the input, and focus returned after a delete — this is the last 20% where the real learning hides.الإنهاء مهارة. ليستة فاضية بتقول إنها فاضية، ولابل للإدخال، والـ focus بيرجع بعد المسح — دي آخر 20% اللي التعلّم الحقيقي مخبي فيها.

src/app/app.ts (template)templateالتمبلت
template: `  <h1>{{ title() }}</h1>   <label for="new-task">New task</label>  <input id="new-task" #box placeholder="What needs doing?" Go outside.</p>  }   <ul>    @for (t of store.all(); track t.id) {      <li>        <input type="checkbox" [checked]="t.done"               (change)="store.toggle(t.id)"               [attr.aria-label]="t.title">        {{ t.title }}        <button (click)="remove(t.id); box.focus()">×</button>      </li>    } @empty {      <li>No tasks yet — add the first one.</li>    }  </ul>`
Checkpointنقطة فحص

Delete the last task: the @empty message appears instead of a silent blank list. Tab into the app with the keyboard only: the input, every checkbox and every × is reachable, and a screen reader announces each checkbox by its task name.امسح آخر مهمة: رسالة الـ @empty بتظهر بدل ليستة فاضية من غير كلام. جرّب الـ tab بالإدخال على الكيبورد بس: الإدخال وكل checkbox وكل × واصلين، وقارئ الشاشة بينطق كل checkbox باسم مهمته.

Step 09الخطوة 09

A ProductCard component with input() and output()كومبوننت ProductCard بـ input() وoutput()

Your first real component split. The card owns nothing: data comes down as an input, decisions flow up as an output. Components that only talk like this are trivially reusable and trivially testable.أول تقسيم حقيقي للـ components. الكارت مش بيملك حاجة: الداتا بتنزل input، والقرارات بتطلع output. الـ components اللي بتتكلم بالشكل ده بس، إعادة استخدامها واختبارها حاجة سهلة جداً.

src/app/product-card.tsnew componentكومبوننت جديد
import { Component, input, output } from '@angular/core';import { Product } from './product'; @Component({  selector: 'product-card',  template: `    <div class="card">      <span class="emoji">{{ product().emoji }}</span>      <b>{{ product().title }}</b>      <span>{{ product().price }} EGP</span>      <button (click)="add.emit(product())">Add to cart</button>    </div>  `,  styles: `.card{border:1px solid #ddd;border-radius:12px;padding:14px}`})export class ProductCard {  product = input.required<Product>();  add = output<Product>();}
src/app/app.tsthe parent listensالأب بيسمع
import { Component, inject, signal } from '@angular/core';import { ProductCard } from './product-card';import { ProductService } from './product.service';import { Product } from './product'; @Component({  selector: 'app-root',  imports: [ProductCard],      // standalone: import what you use  template: `    <h1>Cart</h1>    @for (p of products.all; track p.id) {      <product-card [product]="p" (add)="addToCart($event)" />    }  `})export class App {  products = inject(ProductService);  cart = signal<Product[]>([]);   addToCart(p: Product) {    this.cart.update(c => [...c, p]);  }}

This one habit kills a whole class of bugs.input.required<Product>() بتخلي الـ compiler يلزمك إن أي استخدام يبعت [product]. لو نسيتها البيلد بيفشل، مش المستخدم. العادة دي بتقضي على نوع كامل من الباجات.

Step 10الخطوة 10

CartService with computed totalsخدمة CartService بإجماليات computed

Move the cart into a service before it grows. Totals are derived state — they must be computed, never manually kept in sync.انقل الكارت لـ service قبل ما يكبر. الإجماليات حالة مشتقة — مكانها computed، وعمرها ما هتتظبط بالإيد.

src/app/cart.service.tsnew fileملف جديد
import { Injectable, signal, computed } from '@angular/core';import { Product } from './product'; export interface CartLine {  product: Product;  qty: number;} @Injectable({ providedIn: 'root' })export class CartService {  private lines = signal<CartLine[]>([]);   readonly all = this.lines.asReadonly();  readonly count = computed(() =>    this.lines().reduce((n, l) => n + l.qty, 0));  readonly total = computed(() =>    this.lines().reduce((sum, l) => sum + l.qty * l.product.price, 0));   add(p: Product) {    this.lines.update(list => {      const hit = list.find(l => l.product.id === p.id);      if (hit) {        return list.map(l =>          l.product.id === p.id ? { ...l, qty: l.qty + 1 } : l);      }      return [...list, { product: p, qty: 1 }];    });  }   setQty(productId: number, qty: number) {    this.lines.update(list =>      list.map(l => l.product.id === productId ? { ...l, qty } : l));  }   remove(productId: number) {    this.lines.update(list =>      list.filter(l => l.product.id !== productId));  }}
Why merge instead of pushليه بندمج بدل الـ push

Adding the same product twice must become one line with qty 2, not two rows. Look how the update returns a new array in every branch — the reference-replacement habit from the to-do app, now carrying real logic.تضيف نفس المنتج مرتين لازم تبقى سطر واحد بـ qty 2، مش صفين. بص إزاي الـ update بترجع مصفوفة جديدة في كل حالة — عادة تبديل الـ reference من تطبيق to-do، بس بمنطق حقيقي المرة دي.

The standalone disciplineالديسسيبلين بتاع الـ standalone

Notice the loop you are in now: want a pipe → import it in imports → use it. Nothing is global, so every page declares exactly what it needs. That is more typing than ngModules, and exactly why reviewers can read your templates.خد بالك من اللوب اللي إنت فيه دلوقتي: عايز pipe → استوردها في imports → استخدمها. مفيش حاجة جلوبال، فكل صفحة بتعلن بالظبط اللي محتاجاه. ده كتابة أكتر من الـ ngModules، وده بالظبط سبب إن مراجعين الكود يقدروا يقراو تمبلتاتك.
