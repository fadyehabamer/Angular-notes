Lifecycle: what runs, and whenدورة الحياة: إيه اللي بيشتغل، وإمتى

A component is created, rendered, updated many times, then destroyed. Older Angular gave you eight hooks for those moments. Modern Angular quietly replaced most of them — you now need three, and one of those is only for talking to code that is not Angular.الـ component بيتعمل، وبيترندر، وبيتحدّث مرات كتير، وبعدين بيتدمّر. أنجولار القديم كان بيديك تمن hooks للحظات دي. وأنجولار الحديث استبدل معظمهم في هدوء — دلوقتي محتاج تلاتة بس، وواحد فيهم بس عشان تكلّم كود مش أنجولار.

What it actually isهي إيه بالظبط

Lifecycle hooks are methods Angular calls for you at fixed moments: created, drawn, updated, destroyed.الـ lifecycle hooks هي ميثودز أنجولار بيناديها بدالك في لحظات ثابتة: اتعمل، اترسم، اتحدّث، اتمسح.

Think of it likeاعتبرها زي

A shop's opening and closing routine. Unlock at nine, put the sign out, cash up at six, lock the door. Same order, every single day.روتين فتح وقفل المحل. تفتح الساعة تسعة، تحط اللافتة، تحسب الساعة ستة، تقفل الباب. نفس الترتيب كل يوم.

You reach for it whenهتحتاجها لما

Starting a timer, opening a socket, measuring an element — and above all, cleaning those up again.لما تبدأ تايمر، أو تفتح socket، أو تقيس عنصر — وأهم من ده كله، لما تنضّفهم بعد كده.

Clear timers, close sockets, unsubscribe. Or use DestroyRef and let Angular do it.امسح التايمرات، اقفل الـ sockets، الغِ الاشتراكات. أو استعمل DestroyRef وسيب أنجولار يعملها.

Real exampleمثال حقيقي A map that must not leakخريطة ممنوع تسرّب

Map and chart libraries attach global listeners and animation loops. Forget to destroy one and every visit to the page adds another running copy — the classic "app gets slower the longer you use it" bug.مكتبات الخرايط والرسوم بتعلّق listeners عامة وحلقات أنيميشن. وتنسى تدمّر واحدة، فكل مرة تدخل الصفحة بتضيف نسخة شغالة تانية — وده باج «التطبيق بيبطأ كل ما تستعمله» الكلاسيكي.

Watch outخد بالك

  • The constructor runs before anything is rendered. Reading viewChild() or touching the DOM there gives you undefined.الـ constructor بيشتغل قبل ما أي حاجة تترسم. وقراية viewChild() أو لمس الـ DOM هناك هتديك undefined.
  • ngAfterViewInit also runs on the server during SSR, where there is no DOM. afterNextRender does not — prefer it.ngAfterViewInit بيشتغل كمان على السيرفر أثناء الـ SSR، واللي مفيهوش DOM. أما afterNextRender فلأ — فضّله.
  • Lifecycle hooks are matched by name. Misspell ngOnInit as ngOninit and it silently never runs. Implementing OnInit makes the compiler check it.الـ lifecycle hooks بتتطابق بالاسم. لو كتبت ngOnInit غلط ngOninit مش هتشتغل وهتسكت. ولو عملت implements OnInit الـ compiler هيتأكد.
  • Anything you start — a timer, a listener, a subscription, a third-party widget — you stop. This is where memory leaks in Angular come from.أي حاجة بتبدأها — تايمر أو listener أو subscription أو ويدجت خارجية — بتقفلها. ومن هنا بتيجي تسريبات الذاكرة في أنجولار.
  • afterNextRender runs once; afterEveryRender runs after every single render. The second one is a performance trap unless you genuinely need it.afterNextRender بيشتغل مرة؛ وafterEveryRender بيشتغل بعد كل رندر. والتاني ده فخ أداء إلا لو محتاجه فعلاً.
If you remember one thingلو هتفتكر حاجة واحدة

ngOnInit starts things, ngOnDestroy stops them. Skipping the second one is exactly what a memory leak is.ngOnInit بتبدأ الحاجات، وngOnDestroy بتوقّفها. إنك تنسى التانية ده بالظبط معنى تسريب الذاكرة.

Q01 You need the real DOM element of a child. Which hook is the earliest safe one?محتاج عنصر الـ DOM الحقيقي لابن. أنهي hook أول مكان آمن؟
whyليه

ngOnInit runs before the template has been created, so view queries are still undefined there. ngAfterViewInit is the first moment the DOM exists — or use afterNextRender(), which is also safe on the server.ngOnInit بتشتغل قبل إنشاء الـ template، فاستعلامات الـ view لسه undefined فيها. ngAfterViewInit هي أول لحظة الـ DOM بيبقى موجود — أو استخدم afterNextRender()، وهي آمنة على السيرفر كمان.

Q02 Where do you undo a subscription or a third-party widget?بتلغي subscription أو widget من مكتبة خارجية فين؟
whyليه

Angular destroys its own bindings but knows nothing about your setInterval, your chart library or a manual subscribe(). Left behind, they keep running against a component that no longer exists — the classic memory leak.أنجولار بيهدم الروابط بتاعته، بس مبيعرفش حاجة عن setInterval بتاعك ولا مكتبة الرسم ولا subscribe() يدوي. ولو سيبتهم، بيفضلوا شغالين على component مش موجود خلاص — وده الـ memory leak الكلاسيكي.

Q03 Which hook tells you an input just changed to a new value?أنهي hook بتقولك إن input اتغيّر لقيمة جديدة؟
whyليه

ngOnChanges runs before every ngOnInit and again on every new input value, with the old and new values in hand. With signal inputs you would use computed() or effect() instead and skip the hook entirely.ngOnChanges بتشتغل قبل كل ngOnInit وبتتكرر مع كل قيمة input جديدة، والقيمة القديمة والجديدة في إيدك. ومع signal inputs هتستخدم computed() أو effect() وتستغنى عن الـ hook خالص.

Q04 Why is afterNextRender() often better than ngAfterViewInit?ليه afterNextRender() أحسن غالباً من ngAfterViewInit؟
whyليه

During server-side rendering there is no window and no real DOM, but ngAfterViewInit still runs — so DOM code there crashes the render. afterNextRender() is skipped on the server by design.وقت الرندر على السيرفر مفيش window ولا DOM حقيقي، ومع ذلك ngAfterViewInit بتشتغل — فكود الـ DOM هناك بيوقّع الرندر. أما afterNextRender() فبتتخطى على السيرفر بحكم التصميم.
