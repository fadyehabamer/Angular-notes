Template-driven forms with ngModelالفورمز من التمبلت بـ ngModel

Angular has two form systems. This is the small one: you declare the form in the HTML and Angular builds the model for you. It is the right choice for a login box or a contact form — and the wrong one the moment validation gets interesting.أنجولار عنده نظامين للفورمز. وده الصغير: بتعلن عن الفورم في الـ HTML وأنجولار بيبني الموديل بدالك. وهو الاختيار الصح لخانة تسجيل دخول أو فورم تواصل — والغلط أول ما الـ validation تبقى معقدة.

What it actually isهي إيه بالظبط

You write plain inputs with ngModel and Angular quietly builds the form object behind your back.إنت بتكتب خانات عادية فيها ngModel وأنجولار بيبني الفورم ورا ضهرك من غير ما تحس.

Think of it likeاعتبرها زي

A paper form with carbon copy underneath. You write on the top sheet; the copy fills itself in.ورقة فيها كربون تحتها. إنت بتكتب فوق، والنسخة بتتملي لوحدها.

You reach for it whenهتحتاجها لما

Small forms — a login box, a search filter, a settings toggle. Nothing with dynamic fields.الفورمات الصغيرة — تسجيل دخول، فلتر بحث، إعداد. مش أي حاجة فيها خانات بتتغيّر.

The whole idea in 4 picturesالفكرة كلها في 4 صور

ngModel on each inputngModel على كل خانة

Plus a name attribute — without it Angular cannot register the control.وكمان name — من غيرها أنجولار مش هيقدر يسجّل الخانة.

Angular watches stateأنجولار بيراقب الحالة

touched, dirty, valid — all tracked for you, free.touched وdirty وvalid — كلها متتبّعة بدالك، ببلاش.

Validators are attributesالفاليديشن attributes

required, minlength, email — the same words you already know from HTML.required وminlength وemail — نفس الكلمات اللي إنت عارفها من HTML.

It outgrows fastبيكبر عليها بسرعة

No types, no easy programmatic changes, awkward tests. Know when to move on.مفيش أنواع، ومش سهل تغيّرها بالكود، والاختبار متعب. اعرف إمتى تسيبها.

contact.component.tsjust a plain objectمجرد object عادي
import { FormsModule, NgForm } from '@angular/forms'; @Component({  selector: 'app-contact',  imports: [FormsModule],          // ← without this, ngModel does nothing  templateUrl: './contact.component.html',})export class Contact {  readonly sending = signal(false);   // no FormGroup, no FormControl. a plain object.  model = { name: '', email: '', message: '' };   async send(f: NgForm) {    if (f.invalid) { f.form.markAllAsTouched(); return; }     this.sending.set(true);    try {      await this.api.contact(this.model);      f.resetForm();               // clears values AND touched/dirty state    } finally {      this.sending.set(false);    }  }}

which form system?the decisionالقرار
// TEMPLATE-DRIVEN — ngModel, FormsModule//   ✓ a login box, a contact form, a search filter//   ✓ fewer moving parts, quicker to write//   ✗ validation logic lives in HTML attributes//   ✗ hard to unit test — you need the DOM//   ✗ no cross-field rules without pain//   ✗ the model is not strongly typed // REACTIVE — FormGroup, FormBuilder, ReactiveFormsModule//   ✓ anything with real validation rules//   ✓ fields that appear based on other fields//   ✓ fully typed, testable without a browser//   ✗ more code up front // Rule of thumb: under five fields and no cross-field rules,// template-driven is fine. Anything else, go reactive.

login.component.tsno form objectsمفيش كائنات فورم
export class Login {  email = '';  password = '';   readonly busy = signal(false);  readonly error = signal('');   async signIn() {    this.busy.set(true);    this.error.set('');    try {      await this.auth.signIn(this.email, this.password);      this.router.navigate(['/'], { replaceUrl: true });    } catch {      this.error.set('That email and password do not match.');    } finally {      this.busy.set(false);    }  }}

Watch outخد بالك

  • ngModel inside a <form> requires a name attribute, or Angular throws at runtime. Outside a form, use [ngModelOptions]="{ standalone: true }".ngModel جوه <form> محتاجة خاصية name، وإلا أنجولار هيرمي ايرور وقت التشغيل. وبره الفورم، استعمل [ngModelOptions]="{ standalone: true }".
  • Forgetting FormsModule fails silently — the input renders, nothing binds, and there is no error message.نسيان FormsModule بيفشل في صمت — الـ input بيترسم، ومفيش حاجة بتترابط، ومفيش رسالة خطأ.
  • ngModel updates on every keystroke. For a search box use [ngModelOptions]="{ updateOn: 'blur' }" or debounce it.ngModel بتتحدث مع كل حرف. ولخانة بحث استعمل [ngModelOptions]="{ updateOn: 'blur' }" أو اعمل لها debounce.
  • f.reset() clears values but leaves the form looking touched. f.resetForm() clears both — use that one.f.reset() بتمسح القيم بس بتسيب الفورم شكله touched. أما f.resetForm() فبتمسح الاتنين — استعمل دي.
  • The moment you need a rule about two fields together — password confirmation, date ranges — stop and switch to reactive forms. Template-driven cannot express it cleanly.أول ما تحتاج قاعدة بتخص حقلين مع بعض — تأكيد الباسورد أو نطاق تواريخ — قف وحوّل لـ reactive forms. الطريقة دي مش بتعبّر عنها بشكل نضيف.
If you remember one thingلو هتفتكر حاجة واحدة

Template-driven is fine until the form gets clever. Dynamic fields or cross-field rules mean it is time for reactive forms.الطريقة دي كويسة لحد ما الفورم يبقى معقّد. خانات ديناميكية أو قواعد بين الخانات = وقت الـ reactive forms.
