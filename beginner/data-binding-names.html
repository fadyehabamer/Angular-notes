[ ] and ( ), name by name[ ] و( )، اسم اسم

The idea is simple: [ ] sends a value in, ( ) sends an event out, [( )] does both. The confusing part is the names. In [value]="term()" the two words have different owners, and in [(stars)]="minStars" one of them lives in another component. Once you can read every binding as target = source, and say who owns each side, bindings stop being guesswork. This page shows exactly that.الفكرة بسيطة: [ ] بتدخّل قيمة، و( ) بتطلّع event، و[( )] بتعمل الاتنين. اللي بيلخبط هو الأسماء. في [value]="term()" الكلمتين ليهم أصحاب مختلفين، وفي [(stars)]="minStars" واحدة منهم عايشة في component تاني. أول ما تعرف تقرا أي binding كـ الهدف = المصدر، وتقول مين صاحب كل ناحية، الـ bindings بتبطل تبقى تخمين. الصفحة دي بتوريك ده بالظبط.

That is the proof of which names are yours.كل اسم انت اللي اخترته اتبدّل بكلمة عشوائية. كلمات أنجولار فضلت مكانها. الكود ده لسه بيشتغل عادي. وده الدليل إن الأسماء دي بتاعتك.

  1. 1search.tsthe sourceالمصدر
    protected readonly term = signal('');protected readonly pumpkin = signal('');

    Everything starts with term, a name you picked in your class. Every binding below uses it on the right-hand side, inside the quotes.كل حاجة بتبدأ من term، اسم انت اخترته في الكلاس بتاعك. وكل binding تحت بيستخدمه في الناحية اليمين، جوه علامات التنصيص.

  2. 2search.htmlin · [ ]لجوه · [ ]
    <input [value]="term()"><input [value]="pumpkin()">

    Square brackets send the value in. The left side, value, is the input element’s DOM property: the browser owns that name. The right side is yours.الأقواس المربعة بتدخّل القيمة لجوه. الناحية الشمال، value، هي الـ property بتاعة عنصر الـ input في الـ DOM: الاسم ده بتاع المتصفح. والناحية اليمين بتاعتك.

  3. 3search.htmlout · ( )لبرّه · ( )
    <input (input)="term.set($any($event.target).value)"><input (input)="pumpkin.set($any($event.target).value)">

    Round brackets listen. input here is the browser’s event, fired on every keystroke. $event is Angular’s name for that event; target and value are the browser’s. $any tells the type checker “trust me”. Only term is yours.الأقواس المدورة بتسمع. input هنا الـ event بتاع المتصفح، بيشتغل مع كل حرف. و$event اسم أنجولار للـ event ده؛ وtarget وvalue بتوع المتصفح. و$any بتقول للـ type checker «ثق فيّا». وterm بس هو بتاعك.

  4. 4search.htmlin · reactsلجوه · بيتفاعل
    <button [disabled]="!canSubmit()" (click)="search()">Go</button><button [disabled]="!taco()" (click)="kiwi()">Go</button>

    One button, one value in, one event out. disabled and click are the browser’s. canSubmit and search are yours. When term changes, canSubmit changes, and the button follows.زرار واحد، قيمة داخلة وevent طالع. disabled وclick بتوع المتصفح. وcanSubmit وsearch بتوعك. لما term تتغير، canSubmit بتتغير، والزرار بيمشي وراها.

  5. 5search.htmlboth · [( )]الاتنين · [( )]
    <app-rating [(stars)]="minStars" /><app-potato [(apricot)]="turnip" />

    On your component’s tag the target is not the browser’s any more. stars belongs to the rating component, so the two files must agree on it. minStars is the search’s own signal, written without brackets because the binding writes back into it.على تاج الـ component بتاعك الهدف مبقاش بتاع المتصفح. stars بتاع الـ rating component، فالملفين لازم يتفقوا عليه. وminStars الـ signal بتاعة الـ search، ومكتوبة من غير قوسين عشان الـ binding بيكتب فيها تاني.

  6. 6rating.tsthe other sideالناحية التانية
    readonly stars = model(0);readonly apricot = model(0);

    Here stars is declared. model is Angular’s: it creates an input called stars and an output called starsChange, which is exactly the pair [( )] needs.هنا stars بيتعلن. وmodel بتاعة أنجولار: بتعمل input اسمه stars وoutput اسمه starsChange، ودول بالظبط الاتنين اللي [( )] محتاجهم.

The whole thing in one lineالحكاية كلها في سطر

[target]="source" and (target)="statement". The target is named by whoever owns the element: the browser for HTML tags, your other component for your tags. The source is always named by you.[target]="source" و(target)="statement". الـ target بيسمّيه اللي يملك العنصر: المتصفح في تاجات HTML، والـ component التاني بتاعك في التاجات بتاعتك. والـ source دايمًا انت اللي بتسمّيه.

  • On an HTML tag, the target is looked up, never invented. value, disabled, click, input come from the browser. If you are unsure, look the element up on MDN.على تاج HTML، الهدف بتدوّر عليه، عمرك ما بتألفه. value وdisabled وclick وinput جايين من المتصفح. لو مش متأكد، دوّر على العنصر في MDN.
  • On your own component’s tag, the target is that component’s input or output. It is yours, but shared: the child declares it, the parent types it. That is the only orange name in a binding.على تاج الـ component بتاعك، الهدف هو الـ input أو الـ output بتاع الـ component ده. هو بتاعك، بس متشارك: الابن بيعلنه والأب بيكتبه. ودي الأسماء البرتقاني الوحيدة في الـ binding.
  • Brackets decide whether the quotes are code. [x]="term()" runs term(). x="term()" is the text “term()”. ( ) quotes are always code: a statement that runs when the event fires.الأقواس هي اللي بتقرر علامات التنصيص كود ولا لأ. [x]="term()" بتشغّل term(). وx="term()" هي الكلام «term()». وعلامات ( ) دايمًا كود: أمر بيشتغل لما الـ event يحصل.
