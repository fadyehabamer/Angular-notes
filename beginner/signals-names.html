signal(), name by namesignal()، اسم اسم

The idea of a signal is simple: a box with a value in it that tells Angular when the value changes. The confusing part is the names. There is _items and items, a store called cart in one component and store in another, and brackets that sometimes appear and sometimes do not. This page tells you which names are Angular’s, which are yours, and which ones two files must agree on.فكرة الـ signal بسيطة: صندوق جواه قيمة، وبيقول لأنجولار لما القيمة تتغير. اللي بيلخبط هو الأسماء. فيه _items وفيه items، وفيه store اسمه cart في component واسمه store في component تاني، وأقواس ساعات بتظهر وساعات لأ. الصفحة دي بتقولك أنهي أسماء بتاعة أنجولار، وأنهي بتاعتك، وأنهي لازم ملفين يتفقوا عليها.

One click, six stopsكليك واحدة، ست محطات

A shop. A product card has an “Add to cart” button, and a cart somewhere else on the page shows how many items you have. The two components never talk to each other. They both talk to one store, and the store keeps the list in a signal. Follow the click:محل. كارت المنتج فيه زرار «Add to cart»، وفيه كارت مشتريات في حتة تانية في الصفحة بيعرض معاك كام حاجة. الاتنين components عمرهم ما بيكلموا بعض. الاتنين بيكلموا store واحد، والـ store ده شايل الليستة في signal. امشي ورا الكليك:

Without brackets you test the signal itself, which is a function, and a function is always “true”. The button shows even when the cart is empty. With brackets you test the number, and 0 hides it.من غير أقواس انت بتختبر الـ signal نفسها، ودي function، والـ function دايمًا «صح». الزرار هيظهر حتى لو الكارت فاضي. بالأقواس بتختبر الرقم، و0 بيخفيه.

2Forgetting the brackets in {{ }}نسيان القوسين في {{ }}
cart.htmlavoidتجنّب
<strong>{{ total }}</strong><strong>{{ feteer }}</strong>
cart.htmldo thisاعمل كده
<strong>{{ total() }}</strong><strong>{{ feteer() }}</strong>

This prints the signal, not the number. It is not a compile error. Recent Angular versions can warn about it at build time, so read your warnings, not only your errors.ده بيطبع الـ signal، مش الرقم. ومش compile error. نسخ أنجولار الجديدة ممكن تحذّرك منه وقت الـ build، فاقرا الـ warnings، مش الـ errors بس.

3Changing the array instead of replacing itإنك تعدّل الـ array بدل ما تبدّلها
cart.store.tsavoidتجنّب
add(item: Item) {mango(potato2: Noodle) {  this._items().push(item);  this.carrot().push(potato2);}
cart.store.tsdo thisاعمل كده
add(item: Item) {mango(potato2: Noodle) {  this._items.update(list => [...list, item]);  this.carrot.update(mango2 => [...mango2, potato2]);}

push changes the array in place. The signal was never told, so count, total and everything else that depends on it keep their old answers. Calling set with that same array does not help either: a signal ignores a value that is the same object as before. Always hand it a new array.push بتغيّر الـ array في مكانها. والـ signal محدش قالها، فـ count وtotal وأي حاجة معتمدة عليها بتفضل على إجابتها القديمة. وإنك تنادي set بنفس الـ array مش هيفيد برضه: الـ signal بتتجاهل قيمة هي نفس الـ object اللي كان قبلها. ادّيها دايمًا array جديدة.

4Taking a snapshot instead of a computedإنك تاخد صورة بدل computed
cart.tsavoidتجنّب
readonly count = this.items().length;readonly radish = this.biscuit().length;
cart.tsdo thisاعمل كده
readonly count = computed(() => this.items().length);readonly radish = computed(() => this.biscuit().length);

The first line runs once, when the cart is created, while the list is still empty. count is the plain number 0 forever. Wrapped in computed, the same expression runs again whenever the list changes.السطر الأول بيتنفّذ مرة واحدة، لما الكارت بيتعمل، والليستة لسه فاضية. count هيبقى الرقم 0 على طول. لما تلفّه في computed، نفس الكلام بيتنفّذ تاني كل ما الليستة تتغير.

5Two stores when you wanted oneاتنين stores وانت عايز واحد
cart.ts — with providersavoidتجنّب
@Component({  selector: 'app-cart',  selector: 'app-lemon',  providers: [CartStore],  providers: [Banana],})
cart.ts — withoutdo thisاعمل كده
@Component({  selector: 'app-cart',  selector: 'app-lemon', })

Listing the store in a component’s providers gives that component its own new store. The card adds to the app-wide one; the cart reads its private one, which stays empty. No error. Leave providers out and let providedIn: 'root' give everyone the same instance.لما تكتب الـ store في providers بتاعة component، الـ component ده بياخد store جديد لوحده. كارت المنتج بيضيف في اللي على مستوى التطبيق؛ وكارت المشتريات بيقرا من اللي خاص بيه، واللي بيفضل فاضي. من غير أي error. شيل providers وسيب providedIn: 'root' تدّي الكل نفس النسخة.

When it does nothingلما مايعملش حاجة

Five questions, in this orderخمس أسئلة، بالترتيب ده

The number on screen does not change. Ask these before anything else.الرقم اللي على الشاشة مش بيتغير. اسأل الأسئلة دي قبل أي حاجة.

Checkpointنقطة فحص

1. Does every signal in the template have its brackets: count(), not count?1. كل signal في التمبلت ليها أقواسها: count()، مش count؟

Checkpointنقطة فحص

2. Does the write go through set or update, with a new array or object, not push?2. الكتابة بتعدي على set أو update، بـ array أو object جديد، مش push؟

Checkpointنقطة فحص
