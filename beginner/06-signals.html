Signals: state that announces itselfالـ Signals: حالة بتبلّغ عن نفسها

A plain property is silent — change it and Angular has to ask every binding in the app whether anything moved. A signal is not silent: reading registers the reader, writing notifies exactly those readers. Everything modern in Angular is downstream of that one sentence.الـ property العادية ساكتة — تغيّرها وأنجولار لازم يسأل كل binding في التطبيق: اتحرك عندك حاجة؟ الـ signal مش ساكتة: القراية بتسجّل مين قرا، والكتابة بتبلّغ اللي قروا بالظبط. كل حاجة حديثة في أنجولار نازلة من الجملة دي.

What it actually isهي إيه بالظبط

A signal is a box with a value in it that tells Angular the moment the value changes.الـ signal هو صندوق جواه قيمة، وبيقول لأنجولار في نفس اللحظة اللي القيمة بتتغيّر فيها.

Think of it likeاعتبرها زي

A doorbell on a box. Anyone who cares wires themselves to the bell, instead of opening the box every five seconds to check whether anything changed.جرس على الصندوق. اللي مهتم بيوصّل نفسه بالجرس، بدل ما يفتح الصندوق كل خمس ثواني يشوف اتغيّر ولا لأ.

You reach for it whenهتحتاجها لما

For any value that changes and is shown on screen. In a modern Angular app, that is nearly all of them.لأي قيمة بتتغيّر وبتتعرض على الشاشة. في أنجولار الحديث، دي تقريباً كل القيم.

Reading registers youالقراية بتسجّلك

Calling count() inside a template quietly writes your name on the bell.لما بتنادي count() جوه template، اسمك بيتكتب على الجرس من غير ما تحس.

set() rings the bellset() بتدق الجرس

set replaces the value, update changes it based on the old one.set بتستبدل القيمة، وupdate بتغيّرها بناءً على القديمة.

Not the page, not the component — just the exact pieces that read that signal.مش الصفحة، ولا الـ component، الحتت اللي قرت الـ signal دي بس.

@Injectable({ providedIn: 'root' })export class CartStore {  // private + writable: only this class may mutate it  private readonly _items = signal<Item[]>([]);   // public + read-only: the shape everybody else sees  readonly items = this._items.asReadonly();   add(item: Item)   { this._items.update(l => [...l, item]); }  remove(id: string){ this._items.update(l => l.filter(i => i.id !== id)); }  clear()           { this._items.set([]); }}

Watch outخد بالك

  • Forgetting the parentheses. @if (count) tests the function object, which is always truthy. {{ count }} prints the function source.نسيان القوسين. @if (count) بيختبر الـ function object، وده دايماً truthy. و{{ count }} بيطبع كود الـ function.
  • .set() compares by reference. items().push(x) then .set(items()) is the same array — nothing updates. Build a new one..set() بيقارن بالـ reference. لو عملت items().push(x) وبعدين .set(items()) دي نفس الـ array — مفيش حاجة هتتحدث. ابني واحدة جديدة.
  • Never .set() what you could computed(). If a value is a function of other values, it has no business being stored.عمرك ما تعمل .set() لحاجة كان ممكن تبقى computed(). لو القيمة دالة في قيم تانية، مالهاش لازمة تتخزن.
  • Values that never change after construction do not need to be signals. Wrapping everything is noise, not architecture.القيم اللي مش بتتغير بعد الإنشاء مش محتاجة تبقى signals. لف كل حاجة في signal ده دوشة مش تصميم.
  • A computed must be pure. Calling an API or writing another signal inside one gives you a value that changes depending on who looked at it and when.الـ computed لازم تبقى نضيفة. لو نادیت API أو كتبت في signal تانية من جواها، القيمة هتتغير حسب مين بصّ عليها وإمتى.
If you remember one thingلو هتفتكر حاجة واحدة

Read it with count(), change it with count.set(5). The brackets are not decoration — without them you get the box, not the value.اقراه بـ count()، وغيّره بـ count.set(5). الأقواس مش زينة — من غيرها بتاخد الصندوق نفسه مش القيمة.
