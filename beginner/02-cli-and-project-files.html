The CLI, and what every file is forالـ CLI، وكل ملف بيعمل إيه

You will spend your whole Angular life in about six terminal commands. The CLI writes the boilerplate, wires the files together and names things consistently — let it. Hand-created components are where beginners lose an afternoon to a typo.هتقضي عمرك في أنجولار على حوالي ستة أوامر في الترمينال. الـ CLI بيكتب الكود المتكرر، ويوصّل الملفات ببعض، ويسمّي الحاجات بنظام — سيبه يعمل كده. الـ components اللي بتتعمل بالإيد هي اللي بتضيّع من المبتدئين نص يوم على غلطة إملائية.

What it actually isهي إيه بالظبط

ng is a command that writes the boring files for you and runs your app while you work on it.ng ده أمر بيكتبلك الملفات المملة وبيشغّل التطبيق وإنت شغال عليه.

Think of it likeاعتبرها زي

A kitchen assistant. You say component, product-card and the prep work is already on the counter before you finish the sentence.زي مساعد في المطبخ. تقوله component اسمه product-card وتلاقي التحضير خلص قبل ما تخلّص الجملة.

You reach for it whenهتحتاجها لما

Every single time you need a new component, service or route. Typing these files by hand is how typos get in.كل مرة محتاج component أو service أو route جديد. لما بتكتبهم بإيدك بتيجي الغلطات الإملائية.

ng serve watches young serve بيراقبك

Runs a dev server and rebuilds the second you save. Leave it running all day.بيشغّل سيرفر تطوير وبيعيد البناء بمجرد ما تحفظ. سيبه شغال طول اليوم.

ng build ships itng build بيطلّعه

Produces the small, optimised files you actually put on a server.بيطلّع الملفات الصغيرة المضغوطة اللي بتحطها فعلاً على السيرفر.

Real exampleمثال حقيقي Your first feature, start to finishأول فيتشر ليك، من الأول للآخر

Three commands and two small edits give you a new page at its own URL. This is the loop you will repeat for every feature you ever build in Angular.تلات أوامر وتعديلين صغيرين بيدوك صفحة جديدة على URL بتاعها. ودي الدورة اللي هتكررها مع كل فيتشر هتبنيه في أنجولار.

1. generate itterminalالترمينال
ng g c pages/about # CREATE src/app/pages/about/about.ts# CREATE src/app/pages/about/about.html# CREATE src/app/pages/about/about.css# CREATE src/app/pages/about/about.spec.ts
2. give it a URLapp.routes.tsapp.routes.ts
import { Routes } from '@angular/router'; export const routes: Routes = [  {    path: 'about',    loadComponent: () => import('./pages/about/about').then(m => m.About),  },];
3. link to itapp.htmlapp.html
<nav>  <a routerLink="/">Home</a>  <a routerLink="/about">About</a></nav> <router-outlet /> <!-- add RouterLink and RouterOutlet to imports: [] in app.ts -->

Watch outخد بالك

  • Use routerLink, never href, for links inside your app. href reloads the whole application and you lose all state.استعمل routerLink مش href للينكات جوه تطبيقك. href بيعيد تحميل التطبيق كله وبتضيّع كل الحالة.
  • Never edit anything in node_modules/, and never commit it. It is rebuilt from package.json by npm install.عمرك ما تعدّل حاجة في node_modules/، وعمرك ما ترفعها على git. بتتبني من package.json بـ npm install.
  • Global styles go in src/styles.css. Styles in a component file only apply to that component — that is deliberate, not a bug.الاستايلات العامة بتتحط في src/styles.css. والاستايلات اللي في ملف component بتتطبق على الـ component ده بس — وده مقصود مش باج.
  • Generating a component does not import it anywhere. You still add it to the imports array of whichever template uses it.توليد الـ component مش بيعمل له import في أي مكان. لسه لازم تضيفه لمصفوفة imports بتاعة التمبلت اللي هيستخدمه.
  • If ng is “command not found”, the global install did not land on your PATH. npx ng serve works from inside the project without any global install.لو ng طلعلك «command not found»، يبقى التثبيت العام مش على الـ PATH. وnpx ng serve بتشتغل من جوه المشروع من غير أي تثبيت عام.
If you remember one thingلو هتفتكر حاجة واحدة

ng generate and ng serve are ninety percent of the CLI. Learn those two properly; the rest can wait.ng generate و ng serve هما تسعين في المية من الـ CLI. اتقنهم الاتنين، والباقي يستنى.

Q01 ng generate component cart — which file holds the HTML?ng generate component cart — أنهي ملف فيه الـ HTML؟
whyليه

A component is a small family of files with one name: .ts is the logic, .html is the picture, .css is the styling, .spec.ts is the test. Knowing which is which is most of finding your way around a project.الـ component عبارة عن مجموعة ملفات صغيرة بنفس الاسم: الـ .ts المنطق، والـ .html الشكل، والـ .css التنسيق، والـ .spec.ts الاختبار. إنك تعرف مين فيهم إيه، ده معظم حكاية إنك تعرف تتحرك في المشروع.

Q02 Why use ng generate instead of creating the files by hand?ليه نستخدم ng generate بدل ما نعمل الملفات بإيدينا؟
whyليه

Nothing stops you writing the files yourself — the CLI is a time saver, not a requirement. What it buys you is consistency: the same file names, the same selector convention, the same class name, so the next person can guess where things are.مفيش حاجة تمنعك تكتب الملفات بنفسك — الـ CLI بيوفّر وقت، مش شرط. اللي بتكسبه هو الاتساق: نفس أسماء الملفات، ونفس عُرف الـ selector، ونفس اسم الكلاس، فاللي بعديك يقدر يتوقّع كل حاجة فين.

Q03 What does ng serve do that ng build does not?ng serve بيعمل إيه وng build مبيعملهوش؟
whyليه

ng serve is for working: it keeps everything in memory and rebuilds on save. ng build is for shipping: it writes the real optimised output into dist/. Never deploy what ng serve produced.ng serve للشغل: بيحتفظ بكل حاجة في الميموري وبيعيد البناء أول ما تحفظ. وng build للنشر: بيكتب الناتج الحقيقي المحسّن في dist/. متنشر خالص اللي ng serve عمله.

Q04 Where do you put a package's settings so they apply to the whole app?بتحط إعدادات مكتبة فين علشان تسري على التطبيق كله؟
whyليه

app.config.ts is the app-wide settings list — provideRouter(), provideHttpClient() and friends all go in its providers array. angular.json configures the build; package.json lists dependencies.app.config.ts هو قائمة إعدادات التطبيق كله — provideRouter() وprovideHttpClient() وأصحابهم كلهم بيتحطوا في مصفوفة providers بتاعته. angular.json بيظبط البناء، وpackage.json بيسرد المكتبات.
