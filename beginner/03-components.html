A component is a class with a label on itالـ component كلاس عليه لافتة

No NgModule, no registration ceremony. A class, a decorator saying which tag it answers to, and a list of what its template is allowed to use. Miss that last list and Angular renders nothing — silently.مفيش NgModule ولا مراسم تسجيل. كلاس، وdecorator بيقول هو بيرد على أنهي tag، ولستة بالحاجات اللي التمبلت مسموح له يستخدمها. لو نسيت اللستة الأخيرة دي أنجولار مش هيرندر أي حاجة — وهيسكت.

What it actually isهي إيه بالظبط

A component is one area of the screen: a class that holds the data, an HTML file that draws it, and a CSS file that styles it.الـ component هو جزء واحد من الشاشة: class شايل الداتا، وملف HTML بيرسمها، وملف CSS بينسّقها.

Think of it likeاعتبرها زي

A Lego brick. It knows its own shape and colour, it does not care what is next to it, and you click it together with others to build a page.زي تيلة ليجو. عارفة شكلها ولونها، ومش فارق معاها اللي جنبها، وبتركّبها مع غيرها عشان تبني صفحة.

You reach for it whenهتحتاجها لما

Any time a piece of the page has its own data, or repeats, or is big enough that you scroll to find it.أي جزء في الصفحة ليه داتا خاصة بيه، أو بيتكرر، أو كبير لدرجة إنك بتنزل تدوّر عليه.

Every name on this page — yours or Angular’s?كل اسم في الصفحة دي — بتاعك ولا بتاع أنجولار؟

A component has two public faces: its class name (which a parent lists in imports) and its selector (which a parent types as a tag). Its inputs are public too. Everything else inside it is yours alone.الـ component ليه وشّين عموميين: اسم الكلاس (اللي الأب بيحطه في imports) والـ selector (اللي الأب بيكتبه كتاج). والـ inputs بتاعته عمومية برضه. أي حاجة تانية جواه بتاعتك انت لوحدك.

Watch outخد بالك

  • NG0304: not a known element is almost always a missing entry in imports, not a typo in the selector. Check the array first.NG0304: not a known element دي في الغالب حاجة ناقصة من imports، مش غلطة إملائية في الـ selector. بص على المصفوفة الأول.
  • imports lists what the template uses — components, directives, pipes. Services do not go there; they are injected.imports بتحط فيها اللي التمبلت بيستخدمه — components وdirectives وpipes. الـ services مالهاش دعوة هنا؛ دي بتتعمل لها inject.
  • standalone: true is the default now. If you still write it, it is harmless noise; if you write standalone: false you are opting back into NgModules.standalone: true بقى هو الافتراضي. لو لسه بتكتبه فهو دوشة مش ضارة؛ إنما لو كتبت standalone: false يبقى إنت راجع لـ NgModules بإرادتك.
  • Selector prefixes are not decoration. Keep app- (or your library prefix) so your tags can never collide with a real HTML element.بادئة الـ selector مش زينة. خليك على app- (أو بادئة المكتبة بتاعتك) عشان الـ tags بتاعتك عمرها ما تتصادم مع عنصر HTML حقيقي.
  • Inline template is fine while it fits on a screen. Past that, templateUrl — a 300-line string is a file wearing a disguise.الـ template الـ inline كويس طالما داخل في الشاشة. بعد كده استعمل templateUrl — النص اللي 300 سطر ده ملف لابس قناع.

whyليه

With standalone components, a tag you have not imported is just unknown HTML: nothing renders and nothing crashes. Dev mode logs an is not a known element warning that is easy to scroll past — so check the parent's imports: [] first, every time.مع الـ standalone components، أي تاج مش عامله import بيعتبر HTML مش معروف: مفيش حاجة بتترسم ومفيش حاجة بتقع. وضع التطوير بيسجّل تحذير is not a known element وسهل جداً تعدّي عليه — فشيّك على imports: [] بتاع الأب الأول، في كل مرة.

whyليه

selector: 'app-user-card' means you write <app-user-card>. Q03 Where does a component's logic live?منطق الـ component بيعيش فين؟
whyليه

@Component({...}) is only a label that tells Angular how to wire the class up — selector, template, imports. The behaviour is the plain TypeScript class underneath it, which is why you can test it like any other class.@Component({...}) ده مجرد لافتة بتقول لأنجولار يوصّل الكلاس إزاي — selector وtemplate وimports. أما السلوك فهو كلاس TypeScript عادي تحتيها، وعلشان كده تقدر تختبره زي أي كلاس تاني.
