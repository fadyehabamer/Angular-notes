input(), output(), model()input() و output() و model()

The classic @Input / @Output decorators still work — the companion deck covers them. These function-based versions are better for one concrete reason: an input is a signal, so it drops straight into a computed with no ngOnChanges in sight.الـ @Input و@Output القدام لسه شغالين — والملف المصاحب بيغطيهم. النسخ اللي على شكل functions أحسن لسبب واحد ملموس: الـ input بقى signal، فبيدخل على طول جوه computed من غير أي ngOnChanges.

What it actually isهي إيه بالظبط

input() takes data from the parent, output() sends events back up, and model() does both.input() بتاخد داتا من الأب، وoutput() بتبعت أحداث لفوق، وmodel() بتعمل الاتنين.

Think of it likeاعتبرها زي

A vending machine. Coins go in, a snack comes out. It never reaches into your pocket, and you never reach into its shelves.ماكينة بيع. الفلوس بتدخل، والحاجة بتخرج. هي عمرها ما بتحط إيدها في جيبك، وإنت عمرك ما بتحط إيدك في رفوفها.

Watch outخد بالك

  • input() has no .set() — the parent owns the value. If the child must write it, that is model(). If it needs a local copy that resets when the input changes, that is linkedSignal().input() مالهاش .set() — الأب هو المالك. لو الابن لازم يكتب فيها، ده شغل model(). ولو محتاج نسخة محلية بترجع لأصلها لما الـ input يتغير، ده linkedSignal().
  • You cannot mix the two styles on one property. @Input() x and x = input() are alternatives, not layers.مينفعش تخلط الأسلوبين على نفس الـ property. @Input() x وx = input() بدائل، مش طبقات.
  • Signal inputs are not readable in the constructor either — but you no longer need to. Put the logic in a computed and it runs when the value exists.الـ signal inputs كمان مش بتتقرا في الـ constructor — بس مبقتش محتاج. حط المنطق في computed وهو هيشتغل لما القيمة تبقى موجودة.
  • [(x)] requires a model() named x, or the old pair x + xChange. Any other naming silently does nothing.[(x)] محتاجة model() اسمها x، أو الثنائي القديم x + xChange. أي تسمية تانية مش هتعمل حاجة وهتسكت.
  • Objects still travel by reference. Mutating line() inside the child edits the parent’s object too — pass a copy or emit an event instead.الـ objects لسه بتتنقل بالـ reference. لو عدّلت line() جوه الابن هتكون عدّلت object الأب كمان — مرّر نسخة أو ابعت event بدل كده.
If you remember one thingلو هتفتكر حاجة واحدة

Parent to child is an input. Child to parent is an output. If you need something else, you probably want a service.من الأب للابن = input. من الابن للأب = output. لو محتاج حاجة تانية، غالباً إنت عايز service.

Q01 A parent binds (remove)="drop($event)" and $event is always undefined. Why?الأب بيربط (remove)="drop($event)" و$event دايماً undefined. ليه؟
whyليه

$event is whatever you hand to emit. emit() sends nothing; emit(this.line.id) sends the id. Typing the output — output<string>() — makes the compiler catch this for you.$event هو اللي بتسلّمه لـ emit. emit() مش بتبعت حاجة، وemit(this.line.id) بتبعت الـ id. ولما تحدّد نوع الـ output — output<string>() — الـ compiler هو اللي يمسكلك الغلطة دي.

Q02 What is the difference between title="Hello" and [title]="Hello"?إيه الفرق بين title="Hello" و[title]="Hello"؟

Square brackets mean evaluate this as an expression. Without them you are passing a literal string. whyليه

Angular builds the class first and assigns the inputs afterwards, so the constructor always sees undefined.
