PWAs and the Angular service workerالـ PWA وservice worker بتاع أنجولار

A service worker is a script that sits between your app and the network. Angular ships a configurable one, so you declare what to cache in a JSON file instead of writing fetch handlers. The result: the app opens instantly on a repeat visit, and keeps working on a bad connection.الـ service worker سكريبت بيقعد بين تطبيقك والشبكة. وأنجولار بييجي بواحد قابل للإعداد، فبتعلن هتخزّن إيه في ملف JSON بدل ما تكتب معالجات fetch. والنتيجة: التطبيق بيفتح فوراً في الزيارة التانية، وبيفضل شغال على نت وحش.

What it actually isهي إيه بالظبط

A PWA is your web app with a service worker — a small script that caches files so the app still opens offline.الـ PWA هو تطبيق الويب بتاعك مع service worker — سكريبت صغير بيخزّن الملفات فالتطبيق بيفتح حتى من غير نت.

Think of it likeاعتبرها زي

A shopkeeper who keeps a copy of everything in the back room. The delivery lorry is late? The shelves are still full.صاحب محل بيحتفظ بنسخة من كل حاجة في المخزن. العربية اتأخرت؟ الرفوف لسه مليانة.

You reach for it whenهتحتاجها لما

Field apps, poor connectivity, or anything a user opens more than once a day on a phone.تطبيقات الميدان، والنت الضعيف، أو أي حاجة المستخدم بيفتحها أكتر من مرة في اليوم على موبايل.

is a PWA worth it here?be honestكن صادق
// ✓ WORTH IT//   - people return daily (a dashboard, a tool, a reader)//   - connectivity is unreliable (field work, transit, rural)//   - the data is mostly read and changes slowly//   - you want an installable icon without an app store // ✗ USUALLY NOT WORTH IT//   - a marketing site people visit once//   - anything where stale data is dangerous (trading, live stock)//   - an app that changes every day — you will fight the cache // THE COST: a whole extra caching layer to reason about.// 'why am I seeing the old version?' becomes a support question// you will answer many times.
Real exampleمثال حقيقي The update problem, and why it bitesمشكلة التحديث، وليه بتوجع

You deploy a fix. A user has had the tab open since yesterday. Without SwUpdate they keep running the broken version indefinitely — and they will tell you the bug is not fixed, and they will be right.إنت نشرت إصلاح. والمستخدم فاتح التاب من امبارح. من غير SwUpdate هيفضل شغال على النسخة البايظة للأبد — وهيقولك الباج مش متصلّح، وهيبقى معاه حق.

what actually happensthe sequenceالتسلسل
// 1. you deploy. index.html and the JS hashes change.// 2. the open tab's service worker is STILL serving the old//    files from cache. the user sees no change at all.// 3. on the next check, the worker downloads the new version//    in the background — and installs it as WAITING.// 4. it activates only when EVERY tab for your origin closes.//// a user who never closes the tab never gets the fix.// this is by design: it stops the app changing under their hands.//// your job is step 5: notice, and offer the reload.
the minimum you must shipdo not skip thisمتعديهاش

Reload now?')) {      await sw.activateUpdate();      location.reload();    }  });}

Watch outخد بالك

  • The service worker does not run under ng serve. Test it with a production build served by a static server, or you will conclude it is broken.الـ service worker مش بيشتغل مع ng serve. اختبره بـ build إنتاج مقدّم من سيرفر ثابت، وإلا هتستنتج إنه بايظ.
  • Without SwUpdate, a user with an open tab runs your old version indefinitely. Shipping a PWA without update handling is shipping a bug.من غير SwUpdate، المستخدم اللي فاتح تاب بيفضل على نسختك القديمة للأبد. ونشر PWA من غير التعامل مع التحديث ده نشر باج.
  • strategy: "performance" on an endpoint whose data matters will show stale data confidently. Use freshness with a timeout unless the data really is static.strategy: "performance" على endpoint داتاه مهمة هيوري داتا قديمة بثقة. استعمل freshness مع timeout إلا لو الداتا ثابتة فعلاً.
  • Only GET requests are cached. A POST made offline simply fails — real offline writes need a queue you build yourself (IndexedDB plus a sync on reconnect).الـ GET بس هو اللي بيتخزّن. والـ POST من غير نت بيفشل وخلاص — والكتابة الحقيقية من غير نت محتاجة طابور تبنيه بنفسك (IndexedDB مع مزامنة عند رجوع الاتصال).
  • Debug in DevTools → Application → Service Workers. “Update on reload” and “Unregister” will save you hours of confusion during development.صحّح في DevTools ← Application ← Service Workers. و«Update on reload» و«Unregister» هيوفروا عليك ساعات لخبطة أثناء التطوير.
If you remember one thingلو هتفتكر حاجة واحدة

The service worker serves the old version until it is told otherwise. Handle SwUpdate or users will report bugs you already fixed.الـ service worker بيقدّم النسخة القديمة لحد ما حد يقوله غير كده. اتعامل مع SwUpdate وإلا المستخدمين هيبلّغوا عن مشاكل إنت مصلّحها.

Q01 What does the service worker sit between?الـ service worker قاعد بين إيه وإيه؟
whyليه

It intercepts requests, so it can answer from its cache when the network is gone. That single position is what makes offline support and instant repeat loads possible.بيعترض الطلبات، فيقدر يرد من الكاش بتاعه لما الشبكة تروح. والموقع الواحد ده هو اللي بيخلي الدعم بدون إنترنت والتحميل المتكرر الفوري ممكنين.

Q02 Which strategy suits an API that changes often?أنهي استراتيجية تناسب API بيتغيّر كتير؟
whyليه

performance is right for things that rarely change — fonts, images, the app shell. Live data wants freshness, so the cache is only used when the network fails.performance مناسبة للحاجات اللي نادراً ما تتغيّر — الخطوط والصور وهيكل التطبيق. أما البيانات الحيّة فعايزة freshness، فالكاش بيستخدم بس لما الشبكة تفشل.

Q03 A user reports seeing an old version after you deployed. What is happening?مستخدم بيقول إنه شايف نسخة قديمة بعد النشر. إيه اللي بيحصل؟
whyليه

That staleness is the deal you accepted for offline support. Use SwUpdate to notice a new version and prompt the user to reload — otherwise they may sit on an old build for days.التقادم ده هو الاتفاق اللي قبلته مقابل الدعم بدون إنترنت. استخدم SwUpdate علشان تلاحظ نسخة جديدة وتطلب من المستخدم يعيد التحميل — وإلا يمكن يفضل على بناء قديم أيام.

Q04 Does the service worker run in ng serve?الـ service worker بيشتغل في ng serve؟
whyليه

Caching during development would be maddening, so it is disabled. Test it by building for production and serving dist/ with a static server — http-server is enough.الكاش وقت التطوير كان هيبقى مجنّن، فهو معطّل. اختبره بإنك تبني للإنتاج وتقدّم dist/ بسيرفر ملفات ثابتة — http-server يكفي.
