NgRx, SignalStore and friendsNgRx و SignalStore وأخواتهم

State libraries buy you two things: an enforced convention across a large team, and a devtools timeline that answers “why did this change?”. They cost bundle size and ceremony. Know what you are buying before you adopt one — and know that most apps genuinely do not need it.مكتبات الحالة بتشتري لك حاجتين: convention مفروض على فريق كبير، وخط زمني في الـ devtools بيجاوب على «ليه ده اتغير؟». وتمنهم حجم bundle ومراسم. اعرف بتشتري إيه قبل ما تعتمد واحدة — واعرف إن معظم التطبيقات فعلاً مش محتاجاها.

What it actually isهي إيه بالظبط

State libraries add rules about how data may change — actions, reducers, devtools — on top of what a service already does.مكتبات الحالة بتضيف قواعد لطريقة تغيير الداتا — actions وreducers وdevtools — فوق اللي الـ service بيعمله أصلاً.

Think of it likeاعتبرها زي

A ledger instead of a notebook. Slower to write in, but you can prove exactly who changed what and when.دفتر حسابات بدل نوتة. أبطأ في الكتابة، بس تقدر تثبت مين غيّر إيه وإمتى بالظبط.

You reach for it whenهتحتاجها لما

Large teams, complex flows, or when you genuinely need time-travel debugging. Not for a to-do list.الفرق الكبيرة، والتدفقات المعقّدة، أو لما تحتاج فعلاً debugging بالرجوع في الزمن. مش لتطبيق مهام.

choosing honestlythe real adviceالنصيحة الحقيقية
// PLAIN SIGNAL SERVICE     0 kB    — the default. most apps.//   → start here. always. you can migrate later. // NGRX SIGNALSTORE      ~ 8 kB    — convention, minimal ceremony//   → a team that wants one agreed shape for every store // NGRX STORE (Redux)    ~ 25 kB   — actions, devtools, time travel//   → large teams, complex flows, or you genuinely need the timeline // NGXS                  ~ 15 kB   — class-based, less boilerplate//   → smaller community; fine, but check its release cadence // THE HONEST ADVICE:// do not adopt a state library because the app 'feels big'.// adopt it when you can name the specific problem it solves// for you. otherwise you have bought ceremony and paid in kB.

Every name on this page — yours or Angular’s?كل اسم في الصفحة دي — بتاعك ولا بتاع أنجولار؟

Every function that starts with with, create or patch belongs to NgRx. The names inside them (the state keys, computed names, method names, action names) are yours, but components read them, so they are orange: rename them in the store and in every component together.أي function بتبدأ بـ with أو create أو patch دي بتاعة NgRx. الأسماء اللي جواها (مفاتيح الـ state، أسماء الـ computed، أسماء الميثودز، أسماء الـ actions) بتاعتك، بس الـ components بتقراها، فهي برتقاني: غيّرها في الـ store وفي كل component مع بعض.

Watch outخد بالك

  • Do not adopt a state library because the app “feels big”. Adopt it when you can name the problem it solves — usually “I cannot trace why this changed”.متعتمدش مكتبة حالة عشان التطبيق «حاسس إنه كبير». اعتمدها لما تقدر تسمّي المشكلة اللي بتحلها — وغالباً بتبقى «مش عارف أتتبع ليه ده اتغير».
  • Never put derived data in the store. Compute it in a selector or a computed — a stored total is a stored bug.عمرك ما تحط داتا مشتقة في الـ store. احسبها في selector أو computed — الإجمالي المخزّن ده باج مخزّن.
  • Reducers must be pure: no HTTP, no Date.now(), no random. All of that belongs in an effect, or devtools replay lies to you.الـ reducers لازم تكون نضيفة: مفيش HTTP ولا Date.now() ولا عشوائية. كل ده مكانه الـ effects، وإلا إعادة الـ devtools هتكدب عليك.
  • Not all state is global. Form drafts, open/closed panels and hover state belong in the component — putting them in a global store is pure overhead.مش كل حالة عامة. مسودات الفورمز والبانلز المفتوحة وحالة الـ hover مكانها الـ component — وحطها في store عام ده حِمل زيادة وبس.
  • Migrating from a plain signal service to SignalStore later is genuinely easy — the public shape is the same. That is a strong reason to start simple.التحويل من signal service عادية لـ SignalStore بعدين سهل فعلاً — الشكل العام واحد. وده سبب قوي إنك تبدأ بسيط.

Start with a signal service. Move to a library when you can name the specific pain it removes — not before.ابدأ بـ service فيه signals. وانتقل لمكتبة لما تقدر تسمّي الوجع اللي هتشيله بالظبط — مش قبل كده.

Q01 In the NgRx pattern, who talks to the API?في نمط NgRx، مين اللي بيتكلم مع الـ API؟
whyليه

Reducers must be pure — same input, same output, no side effects — because that purity is what makes the state predictable and replayable. Anything async lives in an effect.الـ reducers لازم تكون نقية — نفس المدخل، نفس المخرج، ومفيش تأثيرات جانبية — لأن النقاء ده هو اللي بيخلي الحالة متوقّعة وقابلة للإعادة. وأي حاجة غير متزامنة مكانها effect.

Q02 A component dispatches load(). What does it know about the result?component بيرسل load(). بيعرف إيه عن النتيجة؟
whyليه

Dispatching is fire-and-forget: an announcement that something should happen. The component's only job afterwards is reading state — which is why this scales, and why it feels indirect at first.الإرسال ده "ابعت وانسى": إعلان إن حاجة المفروض تحصل. وشغل الـ component بعدها هو قراية الحالة بس — وعلشان كده النمط ده بيتوسّع، وعلشان كده بيبان غير مباشر في الأول.

Q03 When is a full global store the wrong choice?إمتى الـ store العام الكامل يكون اختيار غلط؟
whyليه

Global state has a real cost in ceremony: actions, reducers, effects, selectors. A wizard's current step or a table's sort column is local — keep it in the component, or in a small service scoped to that route.الحالة العامة لها تكلفة حقيقية في الطقوس: actions وreducers وeffects وselectors. أما خطوة الـ wizard الحالية أو عمود ترتيب الجدول فدي محلية — سيبها في الـ component، أو في service صغيرة محدودة بالمسار ده.

Q04 What is a selector for?الـ selector بيستخدم لإيه؟
whyليه

A selector is computed() for a store: it derives a view of the state and caches until its inputs change. Components should read selectors, never reach into the raw state shape.الـ selector هو computed() بتاع الـ store: بيشتق منظر من الحالة وبيحفظه لحد ما مدخلاته تتغيّر. والـ components المفروض تقرا selectors، ومتلمسش شكل الحالة الخام.
