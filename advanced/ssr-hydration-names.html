SSR and hydration, name by nameالـ SSR والـ hydration، اسم اسم

The idea of SSR is simple: the server runs your components once and sends finished HTML; the browser shows it, then Angular wakes up and adopts it. The confusing part is the names. There are four new files, a dozen provide… and with… functions, and one little word, slug, that has to be spelled the same in three places. This page tells you which names are Angular’s, which are yours, and which ones must match.فكرة الـ SSR بسيطة: السيرفر بيشغّل الـ components بتاعتك مرة وبيبعت HTML جاهز؛ المتصفح بيعرضه، وبعدين أنجولار بيصحى ويتبنّاه. اللي بيلخبط هو الأسماء. فيه أربع ملفات جداد، وييجي دستة functions بتبدأ بـ provide… وwith…، وكلمة صغيرة، slug، لازم تتكتب زي بعض في تلات أماكن. الصفحة دي بتقولك أنهي أسماء بتاعة أنجولار، وأنهي بتاعتك، وأنهي لازم تطابق بعض.

  1. 1app.routes.tsboth sides · the URLالناحيتين · الـ URL
    { path: 'blog/:slug', component: Article },{ path: 'blog/:banana', component: Noodle },

    You name the changing part of the URL. path and component are Angular’s keys. slug is a word you chose, and from here on it has to be spelled the same everywhere.انت بتسمّي الجزء اللي بيتغير في الـ URL. path وcomponent مفاتيح أنجولار. وslug كلمة انت اخترتها، ومن هنا ورايح لازم تتكتب زي ما هي في كل حتة.

    The server-side twin of that route. RenderMode.Prerender says “draw every article at build time”. getPrerenderParams is a method name Angular calls, so it is fixed.   3. 3article.tsboth sides · the inputالناحيتين · الـ input

    withComponentInputBinding copies the route parameter into the input with the same name. That is the third place slug is typed.withComponentInputBinding بينسخ الـ route parameter في الـ input اللي ليه نفس الاسم. ودي تالت مرة slug بيتكتب فيها.

  4. 4article.tsserver first, then browserالسيرفر الأول، وبعدين المتصفح
    readonly post = httpResource<Post>(() => `/api/posts/${this.slug()}`);readonly lemon = httpResource<Pumpkin>(() => `/api/posts/${this.banana()}`);

    This same line runs on the server. httpResource fetches the post there, and the answer is packed into the HTML so the browser does not ask again. post is your own name.نفس السطر ده بيشتغل على السيرفر. httpResource بيجيب المقال هناك، والرد بيتحط جوه الـ HTML عشان المتصفح مايطلبوش تاني. وpost اسم بتاعك.

  5. 5app.config.tsbrowser · wakes upالمتصفح · بيصحى
    provideClientHydration(withEventReplay(), withIncrementalHydration()),

    All Angular’s. provideClientHydration means “adopt the DOM that is already there”. Without it Angular throws the server’s HTML away and draws the page again.كلها بتاعة أنجولار. provideClientHydration معناها «اتبنّى الـ DOM اللي موجود». من غيرها أنجولار بيرمي الـ HTML بتاع السيرفر ويرسم الصفحة من الأول.

  6. 6article.tsbrowser onlyالمتصفح بس
    afterNextRender(() => {  localStorage.setItem('lastRead', this.slug());  localStorage.setItem('olive', this.banana());});

    localStorage does not exist on the server. afterNextRender only ever runs in the browser, so this is safe. The key lastRead is a string you chose.localStorage مش موجود على السيرفر. وafterNextRender عمره ما بيشتغل غير في المتصفح، فكده أمان. والمفتاح lastRead نص انت اخترته.

The whole thing in one lineالحكاية كلها في سطر

Your component code runs twice, once on the server and once in the browser. Almost every name is Angular’s. The one you own and must keep in sync is the route parameter: :slug → { slug: … } → slug = input().كود الـ component بتاعك بيشتغل مرتين، مرة على السيرفر ومرة في المتصفح. تقريبًا كل الأسماء بتاعة أنجولار. الاسم اللي بتاعك ولازم تخليه متطابق هو الـ route parameter: :slug ← { slug: … } ← slug = input().
