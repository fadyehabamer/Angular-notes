Renderer2 and safe DOM accessRenderer2 والوصول الآمن للـ DOM

Ninety-five percent of DOM work belongs in a template binding. For the rest — a directive that must set a style, a library that needs an element — Renderer2 is the abstraction that keeps your code working on the server, in a web worker, and under a strict CSP, where document does not exist.خمسة وتسعين في المية من شغل الـ DOM مكانه binding في التمبلت. وللباقي — directive لازم يحط استايل، أو مكتبة محتاجة عنصر — Renderer2 هو التجريد اللي بيخلي كودك شغال على السيرفر، وفي web worker، وتحت CSP صارم، حيث document مش موجود.

What it actually isهي إيه بالظبط

Renderer2 is a safe way to touch the DOM that still works on a server, in a worker, or with hydration.Renderer2 هو طريقة آمنة تلمس بيها الـ DOM وبتفضل شغالة على السيرفر أو في worker أو مع الـ hydration.

Think of it likeاعتبرها زي

Talking through an interpreter instead of shouting. Slightly slower, but understood everywhere you go.تتكلم عن طريق مترجم بدل ما تزعّق. أبطأ شوية، بس مفهوم في أي مكان تروحه.

You reach for it whenهتحتاجها لما

When binding genuinely cannot do it: a third-party library, a measured position, a focus trap.لما الـ binding مايقدرش فعلاً: مكتبة خارجية، أو موضع محسوب، أو حصر focus.

import { Directive, Renderer2, ElementRef, inject, afterNextRender } from '@angular/core'; @Directive({ selector: '[appRipple]', host: { '(click)': 'ripple($event)' } })export class Ripple {  private readonly r = inject(Renderer2);  private readonly host = inject(ElementRef<HTMLElement>);   ripple(e: MouseEvent) {    const span = this.r.createElement('span');     this.r.addClass(span, 'ripple');    this.r.setStyle(span, 'left', e.offsetX + 'px');    this.r.setStyle(span, 'top', e.offsetY + 'px');    this.r.setAttribute(span, 'aria-hidden', 'true');     this.r.appendChild(this.host.nativeElement, span);     // listen() returns its own unlisten function    const off = this.r.listen(span, 'animationend', () => {      this.r.removeChild(this.host.nativeElement, span);      off();    });  }} // createElement  createText   appendChild  insertBefore  removeChild// setAttribute   removeAttribute   addClass   removeClass// setStyle       removeStyle       setProperty   listen

// Renderer2 has no read API — no getBoundingClientRect, no scrollTop.// for MEASUREMENT, nativeElement is correct and unavoidable. export class StickyHeader {  private readonly host = inject(ElementRef<HTMLElement>);  readonly stuck = signal(false);   constructor() {    afterNextRender(() => {      const io = new IntersectionObserver(        ([e]) => this.stuck.set(!e.isIntersecting),        { threshold: [1] },      );      io.observe(this.host.nativeElement);      inject(DestroyRef).onDestroy(() => io.disconnect());    });  }} // note: an IntersectionObserver or ResizeObserver is almost always// better than reading layout on scroll — it does not force reflow.
Real exampleمثال حقيقي A tooltip that works under SSRtooltip شغال مع الـ SSR

A tooltip must create a node, position it, and remove it. Written with document it crashes the server render; written with Renderer2 the same file runs everywhere, and the server simply produces no tooltip.الـ tooltip لازم يعمل node ويحدد مكانها ويشيلها. ولو اتكتب بـ document بيكسّر رندر السيرفر؛ ولو اتكتب بـ Renderer2 نفس الملف بيشتغل في كل حتة، والسيرفر ببساطة مش بيطلّع tooltip.

tooltip.directive.tsportableقابل للنقل
@Directive({  selector: '[appTooltip]',  host: { '(mouseenter)': 'show()', '(mouseleave)': 'hide()',          '(focus)': 'show()', '(blur)': 'hide()' },})export class Tooltip {  readonly appTooltip = input.required<string>();  private readonly r = inject(Renderer2);  private readonly host = inject(ElementRef<HTMLElement>);  private node: HTMLElement | null = null;   show() {    if (this.node) return;    const n = this.r.createElement('div');    this.r.addClass(n, 'tooltip');    this.r.setAttribute(n, 'role', 'tooltip');    this.r.appendChild(n, this.r.createText(this.appTooltip()));    this.r.appendChild(this.host.nativeElement, n);    this.node = n;  }   hide() {    if (!this.node) return;    this.r.removeChild(this.host.nativeElement, this.node);    this.node = null;  }   constructor() { inject(DestroyRef).onDestroy(() => this.hide()); }}

Watch outخد بالك

  • Renderer2 has no read API. For measurement you must use nativeElement — inside afterNextRender, so it never runs on the server.Renderer2 مالوش API للقراية. وللقياس لازم تستعمل nativeElement — جوه afterNextRender، عشان عمره ما يشتغل على السيرفر.
  • Every listen() returns an unlisten function. Not calling it leaks a listener for the lifetime of the page.كل listen() بترجّع دالة إلغاء. وعدم نداءها بيسرّب listener طول عمر الصفحة.
  • setProperty(el, 'innerHTML', x) bypasses Angular’s sanitizer exactly like direct assignment does. It is not safer for being on the Renderer.setProperty(el, 'innerHTML', x) بيتخطى معقّم أنجولار بالظبط زي الإسناد المباشر. ومش بقى أأمن عشان هو على الـ Renderer.
  • Reading layout (offsetHeight, getBoundingClientRect) forces a synchronous reflow. In a scroll handler that is a guaranteed jank source — use an observer.قراية التخطيط (offsetHeight وgetBoundingClientRect) بتفرض reflow متزامن. وفي معالج scroll ده مصدر تهنيج مضمون — استعمل observer.
  • If you are reaching for Renderer2 often, check you are not fighting the framework. Most cases are a binding or a host binding you have not thought of yet.لو بتلجأ لـ Renderer2 كتير، اتأكد إنك مش بتتخانق مع الفريمورك. معظم الحالات دي binding أو host binding إنت لسه مفكرتش فيه.
If you remember one thingلو هتفتكر حاجة واحدة

Ninety-nine times out of a hundred a binding is the answer. Renderer2 is the hundredth.تسعة وتسعين مرة من مية، الـ binding هو الحل. وRenderer2 هو المرة المية.
