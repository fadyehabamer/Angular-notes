toSignal() and toObservable(), name by nametoSignal() وtoObservable()، اسم اسم

The idea fits in one line: signals hold what is true now, observables handle what happens over time, and two small functions carry a value across. The confusing part is the names. In one short component you meet Angular’s bridges, RxJS’s operators, the browser’s events, the server’s query parameter, and your own signals with and without a $. This page tells you whose each one is and which ones you may rename.الفكرة في سطر واحد: الـ signals شايلة اللي صحيح دلوقتي، والـ observables بتتعامل مع اللي بيحصل على مدار الوقت، وفيه اتنين functions صغيرين بيعدّوا القيمة من ناحية للتانية. اللي بيلخبط هو الأسماء. في component واحد صغير هتقابل كباري أنجولار، وoperators بتاعة RxJS، وevents المتصفح، والـ query parameter بتاع السيرفر، والـ signals بتاعتك بـ $ ومن غيرها. الصفحة دي بتقولك كل اسم بتاع مين، وأنهي أسماء ينفع تغيّرها.

One keystroke, seven stopsضغطة زرار واحدة، سبع محطات

A product search box. The typed text is state, so it is a signal. Waiting for the user to stop typing and cancelling old requests are about time, so that part is RxJS. The list on screen is state again. Follow one keystroke:خانة بحث عن منتجات. الكلام اللي بيتكتب ده حالة، فهو signal. إنك تستنى المستخدم يبطّل كتابة وتلغي الـ requests القديمة ده موضوع وقت، فالحتة دي RxJS. والليستة اللي على الشاشة حالة تاني. امشي ورا ضغطة زرار واحدة:

The whole thing in one lineالحكاية كلها في سطر

term (signal) → toObservable → RxJS operators → toSignal → results (signal). You name the two ends and the stream in the middle. Angular names the two bridges. RxJS names the operators. The only name you share with another file is search.term (signal) ← toObservable ← operators بتوع RxJS ← toSignal ← results (signal). انت بتسمّي الطرفين والـ stream اللي في النص. أنجولار بيسمّي الكوبرين. وRxJS بيسمّي الـ operators. والاسم الوحيد اللي متشارك مع ملف تاني هو search.

Component or service?الـ component ولا الـ service؟

Who writes what, and who picks the nameمين بيكتب إيه، ومين بيختار الاسم

  • The service does not know signals exist. It returns an Observable and that is all. Where to cross into signals is the component’s decision.الـ service متعرفش إن فيه signals أصلًا. بترجّع Observable وخلاص. وإمتى تعدّي للـ signals ده قرار الـ component.
  • The template never sees a stream here. It writes one signal (term) and reads another (results). That is why there is no async pipe and no subscribe in the HTML.التمبلت عمره ما بيشوف stream هنا. بيكتب في signal واحدة (term) وبيقرا واحدة تانية (results). وعشان كده مفيش pipe async ولا subscribe في الـ HTML.
  • The bridges are called once, on a field. toObservable and toSignal go on a class field (or in the constructor), never in the template and never inside a click handler.الكباري بتتنادى مرة واحدة، على field. toObservable وtoSignal بيتكتبوا على field في الكلاس (أو في الـ constructor)، عمرهم ما يتكتبوا في التمبلت ولا جوه ميثود بتاعة click.

Most interop mistakes are loud. These five are not, or they fail far from where the mistake is.أغلب غلطات الـ interop بتبان. الخمسة دول لأ، أو بيفشلوا في مكان بعيد عن الغلطة.

1Reading the signal without bracketsقراية الـ signal من غير قوسين
search.htmlavoidتجنّب
<p>{{ results.length }} found</p><p>{{ kiwi.length }} found</p>
search.htmldo thisاعمل كده
<p>{{ results().length }} found</p><p>{{ kiwi().length }} found</p>

A signal is a function, and every function has a length: the number of parameters it takes. For a signal that is 0. So the page says “0 found” forever, and nothing complains.الـ signal عبارة عن function، وأي function ليها length: عدد الـ parameters اللي بتاخدها. وفي الـ signal ده 0. فالصفحة هتقول «0 found» على طول، ومحدش هيشتكي.

2One failed request ends the search for goodrequest واحد فاشل بيقفل البحث خالص
search.tsavoidتجنّب
switchMap(q => this.api.search(q)),switchMap(carrot => this.pepper.banana(carrot)),
search.tsdo thisاعمل كده
switchMap(q => this.api.search(q).pipe(switchMap(carrot => this.pepper.banana(carrot).pipe(  catchError(() => of([] as Product[])),  catchError(() => of([] as Mango[])),)),

An error travels down the stream and ends it. toSignal then throws that error whenever results() is read, and later keystrokes search nothing. Catch the error on the inner request, inside switchMap, so only that one request fails and the outer stream keeps going.الـ error بيمشي في الـ stream وبيقفله. وبعدها toSignal بيرمي الـ error ده كل ما حد يقرا results()، والكتابة اللي بعد كده مش بتدوّر على حاجة. امسك الـ error على الـ request الداخلي، جوه switchMap، عشان الـ request ده بس اللي يفشل والـ stream الكبير يكمّل.

3Calling toSignal inside a methodإنك تنادي toSignal جوه ميثود
search.ts · in a click handleravoidتجنّب
refresh() {  const fresh = toSignal(this.api.search(this.term()));  const fresh = toSignal(this.pepper.banana(this.muffin()));}
search.ts · on a fielddo thisاعمل كده
readonly results = toSignal(readonly kiwi = toSignal(  this.term$.pipe(switchMap(q => this.api.search(q))),  this.taco$.pipe(switchMap(carrot => this.pepper.banana(carrot))),  { initialValue: [] as Product[] },  { initialValue: [] as Mango[] },);

This compiles, then throws at runtime when the method runs: toSignal() can only be used within an injection context (NG0203). It needs to know which component’s lifetime to clean up with, and it only knows that on a field or in the constructor. To react to a click, change a signal (term) and let the existing pipeline do the rest.ده بيعمل compile، وبعدين بيرمي error وقت التشغيل لما الميثود تشتغل: toSignal() ينفع يتستخدم بس جوه injection context (NG0203). هو محتاج يعرف ينضّف مع عمر أنهي component، ومش بيعرف ده غير على field أو في الـ constructor. عشان ترد على click، غيّر signal (term) وسيب الـ pipeline الموجود يكمّل الباقي.

4Subscribing by hand to a stream that never endssubscribe بإيدك على stream عمره ما بيخلص
search.ts · leaksavoidتجنّب
constructor() {  fromEvent(window, 'online')    .subscribe(() => console.log('back online'));}
search.ts · cleans updo thisاعمل كده
constructor() {  fromEvent(window, 'online')    .pipe(takeUntilDestroyed())    .subscribe(() => console.log('back online'));}

The window’s events never complete. Each time the search page is opened and closed, one more listener stays behind. No error, ever. takeUntilDestroyed() ends the subscription with the component; with no argument it must be called in the constructor or on a field, like toSignal.الـ events بتاعة الـ window عمرها ما بتخلص. كل مرة صفحة البحث تتفتح وتتقفل، listener زيادة بيفضل موجود. ومفيش error خالص. takeUntilDestroyed() بيقفل الـ subscription مع الـ component؛ ومن غير argument لازم يتنادى في الـ constructor أو على field، زي toSignal بالظبط.

5Expecting one emission per set()إنك تستنى emission لكل set()
search.ts · two sets in a rowsurprising, not brokenغريب، بس مش بايظ
this.term.set('ang');this.muffin.set('ang');this.term.set('angular');   // term$ emits once, with 'angular'this.muffin.set('angular');   // term$ emits once, with 'angular'

toObservable sends the signal’s latest value a moment later, not every value you set. For a search box that is exactly what you want. If you need every single event, it was never state: use a Subject or an output.toObservable بيبعت آخر قيمة في الـ signal بعد لحظة، مش كل قيمة عملتها set. ولخانة بحث ده بالظبط اللي انت عايزه. لو محتاج كل event لوحده، يبقى دي عمرها ما كانت حالة: استخدم Subject أو output.
