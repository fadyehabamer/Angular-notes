switchMap and friends, name by nameswitchMap وصحابها، اسم اسم

The idea behind the four maps is one question: a new value arrived while the last one is still busy — cancel, ignore, queue, or run both? The confusing part is the names. A single pipe() mixes operator names from RxJS, bridge functions from Angular, arrow parameters you invent on the spot, a $ that looks like syntax, and field names the server chose. This page sorts every one of them.الفكرة ورا الأربع maps سؤال واحد: قيمة جديدة وصلت واللي قبلها لسه شغالة — ألغي، ولا أطنّش، ولا أحط في طابور، ولا أشغّل الاتنين؟ اللي بيلخبط هو الأسماء. pipe() واحدة فيها أسماء operators من RxJS، وfunctions كوبري من أنجولار، وparameters في arrow functions بتألّفها في ساعتها، و$ شكلها syntax، وأسماء حقول السيرفر هو اللي اختارها. الصفحة دي بترتّبهم واحد واحد.

Mistakes that fail silentlyغلطات بتفشل في صمت

A stream that is wired wrong does not complain. It just never produces a value, or stops producing them after one bad moment.الـ stream المتوصّل غلط مش بيشتكي. هو بس عمره ما بيطلّع قيمة، أو بيبطّل يطلّع بعد لحظة وحشة واحدة.

1No subscribe, so nothing runsمفيش subscribe، فمفيش حاجة بتشتغل
checkout.ts — never subscribedavoidتجنّب
this.place$.pipe(this.leek$.pipe(  exhaustMap(() => this.api.placeOrder(this.addressId())),  exhaustMap(() => this.kiwi.pickle(this.carrot())),);
checkout.ts — subscribeddo thisاعمل كده
this.place$.pipe(this.leek$.pipe(  exhaustMap(() => this.api.placeOrder(this.addressId())),  exhaustMap(() => this.kiwi.pickle(this.carrot())),).subscribe();

A pipe only describes what should happen. Until something subscribes, the button pushes clicks into a stream nobody listens to, and no request is ever sent. No error, and nothing in the network tab.الـ pipe بيوصف بس اللي المفروض يحصل. لحد ما حد يعمل subscribe، الزرار بيحط كليكات في stream محدش سامعه، ومفيش request بيطلع خالص. لا error، ولا حاجة في الـ network tab.

2Catching the error in the wrong placeمسك الـ error في المكان الغلط
checkout.ts — outer catchavoidتجنّب
this.place$.pipe(this.leek$.pipe(  exhaustMap(() => this.api.placeOrder(this.addressId())),  exhaustMap(() => this.kiwi.pickle(this.carrot())),  catchError(() => EMPTY),).subscribe();
checkout.ts — inner catchdo thisاعمل كده
this.place$.pipe(this.leek$.pipe(  exhaustMap(() => this.api.placeOrder(this.addressId()).pipe(  exhaustMap(() => this.kiwi.pickle(this.carrot()).pipe(    catchError(() => EMPTY),  )),).subscribe();

On the outside, catchError swaps the whole click stream for EMPTY after the first failure. The button still looks alive, but every later click goes nowhere. Inside, only that one request is replaced, and the next click works.من بره، catchError بتبدّل stream الكليكات كله بـ EMPTY بعد أول فشل. الزرار لسه شكله شغال، بس كل كليك بعد كده بتروح في الفاضي. من جوه، الـ request ده بس اللي بيتبدّل، والكليك اللي بعدها بتشتغل.

3Returning an array from catchErrorإنك ترجّع array من catchError
checkout.ts — arrayavoidتجنّب
switchMap(p => this.api.lookup(p).pipe(catchError(() => []))),switchMap(melon => this.kiwi.mango(melon).pipe(catchError(() => []))),
checkout.ts — of([])do thisاعمل كده
switchMap(p => this.api.lookup(p).pipe(catchError(() => of([])))),switchMap(melon => this.kiwi.mango(melon).pipe(catchError(() => of([])))),

This compiles, because RxJS accepts an array as a source. But an array is read as “emit each item”, and an empty array emits nothing. So the old addresses stay on screen after a failed lookup. of([]) emits one empty list and clears them.ده بيعدّي الـ compile، عشان RxJS بيقبل الـ array كمصدر. بس الـ array بتتقري كـ «ابعت كل عنصر»، والـ array الفاضية مبتبعتش حاجة. فالعناوين القديمة بتفضل على الشاشة بعد بحث فاشل. وof([]) بتبعت ليستة فاضية واحدة وبتمسحهم.

4The wrong one of the fourالغلط من الأربعة
checkout.ts — switchMap on a writeavoidتجنّب
switchMap(() => this.api.placeOrder(this.addressId())),switchMap(() => this.kiwi.pickle(this.carrot())),
checkout.ts — exhaustMap on a writedo thisاعمل كده
exhaustMap(() => this.api.placeOrder(this.addressId())),exhaustMap(() => this.kiwi.pickle(this.carrot())),

On a double-click, switchMap cancels the first request in the browser, but the server may already have created that order, and the second request creates another. Two orders, no error. Reads cancel; writes ignore.مع الدبل كليك، switchMap بتلغي الـ request الأولاني في المتصفح، بس السيرفر ممكن يكون عمل الأوردر ده خلاص، والـ request التاني بيعمل واحد كمان. أوردرين، ومفيش error. القراية بتلغي؛ والكتابة بتطنّش.

5Calling the signal inside toObservableإنك تنادي الـ signal جوه toObservable
checkout.ts — valueavoidتجنّب
toObservable(this.postcode())toObservable(this.lemon())
checkout.ts — the signaldo thisاعمل كده
toObservable(this.postcode)toObservable(this.lemon)

Not silent, but confusing: this one is a compile error, because toObservable wants the signal itself so it can watch it, not today’s string. In templates you call signals with (); when you hand one to a bridge, you don’t.مش صامتة، بس ملخبطة: دي compile error، عشان toObservable عايزة الـ signal نفسها عشان تراقبها، مش النص بتاع النهارده. في التمبلت بتنادي الـ signals بـ ()؛ لما تدّي واحدة لكوبري، لأ.

When it does nothingلما مايعملش حاجة

Five questions, in this orderخمس أسئلة، بالترتيب ده

Your pipe “does nothing”. Ask these before rewriting it.الـ pipe بتاعك «مش بيعمل حاجة». اسأل دول قبل ما تعيد كتابته.

Checkpointنقطة فحص

1. Does anything subscribe: a .subscribe() or a toSignal()?1. فيه حاجة بتعمل subscribe: .subscribe() أو toSignal()؟

Checkpointنقطة فحص

2. Do values reach each step? Put tap(v => console.log(v)) between operators and watch where they stop. filter and debounceTime are the usual suspects.2. القيم بتوصل لكل خطوة؟ حط tap(v => console.log(v)) بين الـ operators وبص بتقف فين. filter وdebounceTime هما المتهمين المعتادين.

Checkpointنقطة فحص

3. Did one error kill the stream? Move catchError inside the inner request.3. error واحد موّت الـ stream؟ انقل catchError جوه الـ request الجوّاني.

Checkpointنقطة فحص

4. Do the URL, query keys and body keys match what the server expects? Check the request in the network tab.4. الـ URL ومفاتيح الـ query والـ body مطابقين اللي السيرفر مستنيه؟ بص على الـ request في الـ network tab.

Checkpointنقطة فحص

5. Is it the right operator? Reads: switchMap. Writes: exhaustMap. Order matters: concatMap. Independent work: mergeMap.5. ده الـ operator الصح؟ القراية: switchMap. الكتابة: exhaustMap. الترتيب مهم: concatMap. شغل مستقل: mergeMap.
