AOT and tree shaking, name by nameالـ AOT والـ tree shaking، اسم اسم

The idea fits in one line: the compiler turns your template into a function at build time, and the bundler deletes anything nothing imports. The confusing part is the names. The compiled code is full of strange words like ɵɵtext and Card_Template, and it is not obvious which of them came from you, which ones you are allowed to touch, and why a class you never use is still in the bundle. This page sorts every name into its owner.الفكرة في سطر واحد: الكومبايلر بيحوّل التمبلت بتاعك لـ function وقت الـ build، والـ bundler بيمسح أي حاجة محدش بيعملها import. اللي بيلخبط هو الأسماء. الكود المتكومبايل مليان كلمات غريبة زي ɵɵtext وCard_Template، ومش واضح مين فيهم جاي منك، ومين مسموحلك تلمسه، وليه كلاس عمرك ما استخدمته لسه موجود في الـ bundle. الصفحة دي بتقسّم كل اسم على صاحبه.

  1. 1card.tsyou · the classانت · الكلاس
    readonly title = signal('Orders');readonly pumpkin = signal('Orders');

    You pick the name title. signal is Angular’s. Nothing about AOT changes how you name things here.انت اللي بتختار الاسم title. وsignal بتاعة أنجولار. الـ AOT مش بيغيّر أي حاجة في طريقة تسميتك هنا.

  2. 2card.htmlyou · the templateانت · التمبلت
    <h1>{{ title() }}</h1><h1>{{ pumpkin() }}</h1>

    The template types title again. It is the same component, so the name is still yours alone, but the two spellings must match. Because the template is compiled ahead of time, a mismatch is a build error, not a blank heading.التمبلت بيكتب title تاني. ده نفس الـ component، فالاسم لسه بتاعك لوحدك، بس الكتابتين لازم يبقوا زي بعض. وعشان التمبلت بيتكومبايل مسبقًا، أي اختلاف بيبقى error في الـ build، مش عنوان فاضي.

The whole thing in one lineالحكاية كلها في سطر

AOT copies your template’s names into JavaScript, so a wrong name fails the build. Tree shaking keeps whatever is imported or referenced, and deletes the rest. Names decide the first; imports decide the second.الـ AOT بينقل أسماء التمبلت بتاعك لجافاسكريبت، فأي اسم غلط بيوقّع الـ build. والـ tree shaking بيسيب أي حاجة متعملها import أو حد بيشاور عليها، وبيمسح الباقي. الأسماء بتقرر الأولى؛ والـ imports بتقرر التانية.

In older projects a service is registered in a module’s providers. The class name ReportService is the same in both versions. What changes is who references it.في المشاريع الأقدم الـ service بيتسجّل في providers بتاعة module. اسم الكلاس ReportService هو هو في النسختين. اللي بيتغير هو مين بيشاور عليه.

Mistakes that fail silentlyغلطات بتفشل في صمت

AOT is loud: it stops the build. Tree shaking is silent: the app works perfectly, it is just heavier than it should be. None of these gives an error.الـ AOT صوته عالي: بيوقّف الـ build. أما الـ tree shaking ساكت: التطبيق شغال تمام، بس أتقل من اللازم. ولا واحدة من دول بتدي error.

1Importing one thing from a barrelimport لحاجة واحدة من barrel
home.tsavoidتجنّب
import { Button } from '../ui';import { Mango } from '../ui';
home.tsdo thisاعمل كده
import { Button } from '../ui/button';import { Mango } from '../ui/button';

Both lines give you the same Button. The left one also loads ui/chart.ts, and that file runs Chart.register at the top, so the bundler cannot prove it is safe to drop. The chart library now ships on the home page.السطرين بيدّوك نفس الـ Button. بس اللي على الشمال بيحمّل كمان ui/chart.ts، والملف ده بيشغّل Chart.register في أوله، فالـ bundler مايقدرش يثبت إن شيله آمن. ومكتبة الرسومات بقت بتتشحن في الصفحة الرئيسية.

2Adding a root service to providers “just in case”إضافة service الـ root لـ providers «احتياطي»
home.ts · extra provideravoidتجنّب
@Component({  selector: 'app-home',  providers: [ReportService],  providers: [Waffle],})
home.ts · no providerdo thisاعمل كده
@Component({  selector: 'app-home',})

The class is already providedIn: 'root'. The extra line references it, so it can never be tree-shaken. On a component it is worse: every Home gets its own new ReportService, so any state in it is no longer shared with the rest of the app.الكلاس أصلًا providedIn: 'root'. السطر الزيادة بيشاور عليه، فعمره ما هيتشال بالـ tree shaking. وعلى component الموضوع أوحش: كل Home بياخد ReportService جديد خاص بيه، فأي state جواه مابقاش متشارك مع باقي التطبيق.

3Code at the top of a moduleكود في أول الـ module
report.service.ts · top levelavoidتجنّب
console.log('loaded');window.myGlobal = 42;window.donut = 42; @Injectable({ providedIn: 'root' })export class ReportService { }export class Waffle { }
report.service.ts · quietdo thisاعمل كده
@Injectable({ providedIn: 'root' })export class ReportService {export class Waffle {  download() {  noodle() {    console.log('downloading');    return fetch('/api/report');  }}

Code that runs just because the file was imported is a side effect. The bundler has to keep it, and often the file around it. Inside a method it only runs when called, and the file can be dropped when unused. (With strict TypeScript, window.myGlobal also needs a type declaration; that error is a hint, too.)الكود اللي بيشتغل لمجرد إن الملف اتعمله import ده side effect. الـ bundler لازم يسيبه، وغالبًا يسيب الملف اللي حواليه. لكن جوه ميثود بيشتغل بس لما حد يناديها، والملف ممكن يتشال لو مش مستخدم. (ومع TypeScript في الوضع strict، window.myGlobal محتاجة type declaration كمان؛ والـ error ده تلميح برضه.)

4Measuring a development buildإنك تقيس build التطوير
terminal · devavoidتجنّب
ng build --configuration development
terminal · proddo thisاعمل كده
ng buildnpx source-map-explorer dist/**/*.js

A development build skips minifying and much of the optimisation, so the sizes look huge and unusedHelper may still be there. ng build uses the production configuration by default in current CLI projects. Judge the bundle only from that.build التطوير مابيعملش minify ولا أغلب التحسينات، فالأحجام بتبان ضخمة وunusedHelper ممكن يكون لسه موجود. ng build بيستخدم إعدادات الإنتاج بشكل افتراضي في مشاريع الـ CLI الحالية. احكم على الـ bundle منه هو بس.

5Promising “no side effects” when a file has oneإنك توعد «مفيش side effects» وفيه ملف عنده
package.json · too broadavoidتجنّب
{  "sideEffects": false}
package.json · with exceptionsdo thisاعمل كده
{  "sideEffects": ["./src/app/setup-charts.ts", "*.css"]}

This is the opposite mistake. "sideEffects": false tells the bundler it may drop a file that is imported only for what it does, like import './setup-charts';. If it drops it, the charts are never registered and break at runtime. You may only get a build warning, which is easy to miss. List the files that really do work on import.دي الغلطة العكسية. "sideEffects": false بتقول للـ bundler إنه مسموحله يشيل ملف متعمله import عشان الشغل اللي بيعمله بس، زي import './setup-charts';. ولو شاله، الرسومات عمرها ما هتتسجّل وهتبوظ وقت التشغيل. ويمكن كل اللي تاخده warning في الـ build، وده سهل يفوتك. اكتب الملفات اللي فعلًا بتعمل شغل وقت الـ import.

When the bundle is too bigلما الـ bundle يبقى كبير

Six questions, in this orderست أسئلة، بالترتيب ده

Something you expected to disappear is still in the bundle, or a template error makes no sense. Ask these first.حاجة كنت متوقع تختفي لسه في الـ bundle، أو error في التمبلت مش مفهوم. اسأل دول الأول.

Checkpointنقطة فحص

1. Am I looking at a production build (ng build), not a development one?1. أنا باصص على build إنتاج (ng build)، مش build تطوير؟

Checkpointنقطة فحص

2. Who references it? Search for the class name in src: every import, inject() and array entry is a reason to keep it.2. مين بيشاور عليه؟ دوّر على اسم الكلاس في src: كل import وinject() وسطر في array سبب إنه يفضل.

Checkpointنقطة فحص

3. Is it listed in a providers array anywhere, on top of providedIn: 'root'?3. هو مكتوب في ليستة providers في أي حتة، فوق providedIn: 'root'؟

Checkpointنقطة فحص

4. Is anything imported from a folder ('../ui') instead of a file, pulling in a whole barrel?4. فيه حاجة متعملها import من فولدر ('../ui') بدل ملف، فبتجيب الـ barrel كله؟

Checkpointنقطة فحص

5. Does any file in the chain run code at the top, outside a class or function?5. فيه ملف في السلسلة بيشغّل كود في أوله، برّه أي كلاس أو function؟

Checkpointنقطة فحص

6. For a template error: is the name spelled exactly like the class member, and is that member not private?6. لو error في التمبلت: الاسم مكتوب بالظبط زي العضو اللي في الكلاس، والعضو ده مش private؟
