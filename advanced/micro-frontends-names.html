Micro frontends, name by nameالـ micro frontends، اسم اسم

The idea fits in a line: the shell asks for a remote by name at runtime, and the remote hands over whatever it exposed under an agreed key. The confusing part is the names. The word checkout appears as a remote name, a URL path, a folder and a file, and only one of those is the link between the two apps. Worse, a mismatch is never a build error: each app builds fine on its own. This page shows which names cross the boundary.الفكرة في سطر: الـ shell بيطلب الـ remote باسمه وقت التشغيل، والـ remote بيسلّم اللي هو عارضه تحت مفتاح متفقين عليه. اللي بيلخبط هو الأسماء. كلمة checkout بتظهر كاسم remote، وكمسار URL، وكفولدر، وكملف، وواحدة بس فيهم هي الرابط بين التطبيقين. والأوحش إن أي اختلاف عمره ما بيبقى build error: كل تطبيق بيتبني تمام لوحده. الصفحة دي بتوريك أنهي أسماء بتعدّي الحدود.

The whole thing in one lineالحكاية كلها في سطر

Three strings cross the boundary: the remote name checkout, the exposed key ./routes, and the export CHECKOUT_ROUTES. Both teams must spell them identically, and neither build will tell you if they do not.تلات strings بس بيعدّوا الحدود: اسم الـ remote checkout، والمفتاح المعروض ./routes، والـ export CHECKOUT_ROUTES. الفريقين لازم يكتبوهم بالظبط زي بعض، ولا build فيهم هيقولك لو مش كده.

Every name on this page — yours or Angular’s?كل اسم في الصفحة دي — بتاعك ولا بتاع أنجولار؟

The orange names are the contract between two teams. They are plain strings (a remote name, an exposed key, an exported constant), and because the two apps are built separately, no compiler ever sees both sides. A mismatch shows up at runtime, when a user opens the page. Everything from @angular-architects/native-federation is fixed.الأسماء البرتقاني هي العقد بين فريقين. هي strings عادية (اسم remote، ومفتاح معروض، وconstant متعمله export)، وعشان التطبيقين بيتبنوا كل واحد لوحده، مفيش كومبايلر بيشوف الناحيتين أبدًا. أي اختلاف بيظهر وقت التشغيل، لما يوزر يفتح الصفحة. وأي حاجة جاية من @angular-architects/native-federation ثابتة.

Either way, ./routes and CHECKOUT_ROUTES are the same agreement.الـ shell القديم كان غالبًا بيشاور على URL الـ remote على طول بـ remoteEntry، والملف كان اسمه remoteEntry.js. أما Native Federation بيدوّر على الـ remote باسمه في الـ manifest. وفي الحالتين، ./routes وCHECKOUT_ROUTES هما نفس الاتفاق.
