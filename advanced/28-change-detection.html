What actually makes Angular re-renderإيه اللي بيخلي أنجولار يرندر تاني فعلاً

Change detection is neither magic nor continuous. Something schedules a check, Angular walks the component tree, and each component is either dirty or skipped. Knowing exactly five things mark a component dirty is the whole subject.الـ change detection لا سحر ولا شغال على طول. حاجة بتجدول فحص، وأنجولار بيمشي على شجرة الـ components، وكل واحد يا dirty يا بيتعدّى. ومعرفة إن خمس حاجات بالظبط هي اللي بتعلّمه dirty دي الموضوع كله.

What it actually isهي إيه بالظبط

Change detection is Angular walking the component tree asking "did anything change?" and updating the DOM where it did.الـ change detection هو أنجولار وهو بيلف على شجرة الـ components ويسأل «في حاجة اتغيّرت؟» ويحدّث الـ DOM في اللي اتغيّر.

Think of it likeاعتبرها زي

A night watchman doing rounds. The old way was checking every door on every round. Signals hand him a list of exactly which doors moved.غفير بيعمل جولة. الطريقة القديمة إنه يفحص كل باب في كل جولة. الـ signals بتدّيله لستة بالأبواب اللي اتحركت بالظبط.

You reach for it whenهتحتاجها لما

You do not call it. You feel it — as a slow list, a jumpy scroll, or a value on screen that refuses to update.إنت مش بتناديه. إنت بتحسّه — في لستة بطيئة، أو scroll بينطط، أو قيمة على الشاشة رافضة تتحدّث.

Angular walks the treeأنجولار بيلف على الشجرة

Top to bottom, comparing each binding's current value against its last one.من فوق لتحت، بيقارن قيمة كل binding دلوقتي بآخر قيمة ليها.

OnPush prunes branchesOnPush بتقص فروع

A component is skipped entirely unless an input changed or an event fired inside it.الـ component بيتساب خالص إلا لو input اتغيّر أو حدث اتطلق جواه.

Signals go straight thereالـ signals بتروح على طول

No walking at all — the signal already knows exactly which views read it.مفيش لفّان خالص — الـ signal عارفة بالظبط أنهي views قرتها.

Real exampleمثال حقيقي A live price ticker in a 500-row tableمؤشر أسعار حي في جدول 500 صف

A websocket pushes a price every 200 ms. With zone.js and default change detection that is a full tree walk five times a second. With a signal store and OnPush rows, only the cells whose price actually moved are touched.الـ websocket بيبعت سعر كل 200 مللي ثانية. مع zone.js والـ change detection الافتراضي دي لفة كاملة على الشجرة خمس مرات في الثانية. ومع signal store وصفوف OnPush، الخلايا اللي سعرها اتغير فعلاً هي بس اللي بتتلمس.

price.store.tsone signal per symbolsignal لكل رمز
@Injectable({ providedIn: 'root' })export class PriceStore {  private readonly map = new Map<string, WritableSignal<number>>();   priceOf(symbol: string) {    if (!this.map.has(symbol)) this.map.set(symbol, signal(0));    return this.map.get(symbol)!();  }   // called from outside Angular — no NgZone.run needed,  // a signal write schedules its own targeted check  push(symbol: string, price: number) {    this.map.get(symbol)?.set(price);  }}
ticker-row.component.tsone cell updatesخلية واحدة بتتحدث
@Component({  selector: 'app-ticker-row',  changeDetection: ChangeDetectionStrategy.OnPush,  template: `<td>{{ symbol() }}</td><td>{{ store.priceOf(symbol()) }}</td>`,})export class TickerRow {  readonly symbol = input.required<string>();  readonly store = inject(PriceStore);} // 500 rows on screen, one price ticks → one row re-renders.

Watch outخد بالك

  • push(), splice() and property mutation are invisible to OnPush. Replace the reference, or hold the value in a signal.push() وsplice() وتعديل الخصائص كلهم مش مرئيين لـ OnPush. بدّل الـ reference، أو حط القيمة في signal.
  • A third-party callback (a chart library, a map SDK) runs outside Angular. Set a signal from it and the update lands — no NgZone.run required.أي callback من library خارجية (chart أو map SDK) بيشتغل بره أنجولار. حط signal من جواه والتحديث هيوصل — من غير NgZone.run.
  • OnPush everywhere plus signals for state is not an optimisation you apply later. It is the shape the framework now expects.OnPush في كل حتة مع signals للحالة دي مش تحسينة بتعملها بعدين. دي الشكل اللي الفريمورك بقى متوقعه.
  • Measure instead of guessing: ng.profiler.timeChangeDetection() in the console, or record a profile in Angular DevTools.قِس بدل ما تخمّن: ng.profiler.timeChangeDetection() في الكونسول، أو سجّل profile في Angular DevTools.
  • A setInterval you forgot about costs a full tree walk on every tick under zone.js — a common cause of a mysteriously warm laptop.setInterval نسيته بيكلّفك لفة كاملة على الشجرة كل تكة تحت zone.js — سبب شائع للاب توب اللي بيسخن من غير سبب واضح.

Q01 Under OnPush, which of these does not mark a component for check?مع OnPush، أنهي واحدة من دول مش بتعلّم الـ component للفحص؟
whyليه

OnPush compares references. user.name = 'x' leaves the same object, so nothing looks different and the view is skipped. Replace instead: user = { ...user, name: 'x' }.OnPush بيقارن المراجع. وuser.name = 'x' بتسيب نفس الكائن، فمفيش حاجة باينة مختلفة والـ view بيتخطى. استبدل بدالها: user = { ...user, name: 'x' }.

Q02 Where does a change detection pass start?دورة فحص التغييرات بتبدأ منين؟
whyليه

It always sweeps from the top down, once per pass. That is why an expensive getter in a template is dangerous — and why OnPush helps so much, since it lets Angular skip whole branches.دايماً بتكنس من فوق لتحت، مرة كل دورة. وعلشان كده أي getter مكلّف في template بيبقى خطر — وعلشان كده OnPush بيساعد كتير، لأنه بيخلي أنجولار يتخطى فروع كاملة.

Q03 A signal changes deep in the tree under OnPush. What does Angular do?signal اتغيّرت في عمق الشجرة مع OnPush. أنجولار بيعمل إيه؟
whyليه

Signals know exactly which views read them, so they can mark a precise path dirty. This is why signals plus OnPush is the fast combination, and why it makes zoneless possible at all.الـ signals عارفة بالظبط أنهي views بتقراها، فبتقدر تعلّم طريق محدد كمتّسخ. وعلشان كده الـ signals مع OnPush هما التركيبة السريعة، وعلشان كده الـ zoneless بقى ممكن أصلاً.

Q04 Why is a method call in a template a performance risk?ليه نداء دالة في template بيبقى خطر على الأداء؟
whyليه

Angular cannot know whether the result changed, so it calls the method every single pass — many times a second while you scroll. A computed() caches until a dependency actually changes.أنجولار مبيعرفش لو النتيجة اتغيّرت، فبينادي الدالة في كل دورة — يعني مرات كتير في الثانية وإنت بتعمل scroll. أما computed() فبتحفظ النتيجة لحد ما تبعية تتغيّر فعلاً.
