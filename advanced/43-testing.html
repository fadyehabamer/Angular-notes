Testing a component without a browserتختبر component من غير براوزر

A test is a second opinion about whether your code does what you think. Angular gives you a real component, a real template and a fake everything-else. Start with three kinds of test and ignore the rest until you need them.التست ده رأي تاني في إن كودك بيعمل اللي إنت فاكره ولا لأ. أنجولار بيديك component حقيقي وتمبلت حقيقي وكل حاجة تانية مزيفة. ابدأ بتلات أنواع تستات وتجاهل الباقي لحد ما تحتاجه.

What it actually isهي إيه بالظبط

A unit test is a small program that runs your component and checks what it did — no browser, no clicking.اختبار الوحدة هو برنامج صغير بيشغّل الـ component بتاعك ويشوف عمل إيه — من غير متصفح ولا ضغط بالماوس.

Think of it likeاعتبرها زي

Testing a light switch on the workbench with a battery, instead of installing it in a house and flipping the breaker.تجرّب مفتاح النور على الترابيزة ببطارية، بدل ما تركّبه في بيت وتنزّل الكهربا.

You reach for it whenهتحتاجها لما

On logic that has rules: prices, permissions, validation, date maths. Not on markup that changes weekly.على المنطق اللي ليه قواعد: الأسعار والصلاحيات والتحقق وحسابات التواريخ. مش على markup بيتغيّر كل أسبوع.

The whole idea in 4 picturesالفكرة كلها في 4 صور

TestBed builds a mini appTestBed بيبني تطبيق مصغّر

Real DI, real template, no browser window. It is faster than it sounds.DI حقيقي، وtemplate حقيقي، من غير شباك متصفح. أسرع مما تتخيّل.

Fake the outsideزيّف اللي بره

Provide a stub service instead of hitting a real API. Tests must not use the network.وفّر service مزيف بدل ما تضرب API حقيقي. الاختبارات ماينفعش تستعمل الشبكة.

Act like a userاتصرّف زي المستخدم

Dispatch a click, set an input value, then let change detection settle.اطلق click، وحط قيمة في input، وبعدين سيب الـ change detection يستقر.

Assert the outcomeتأكّد من النتيجة

What is on screen, or what the service was called with. Never the internals.اللي على الشاشة، أو الـ service اتنادى بإيه. مش التفاصيل الداخلية.

Real exampleمثال حقيقي The first test worth writing todayأول تست يستاهل تكتبه النهاردة

Do not start by testing components. Start with the pure functions — validators, formatters, computed logic. They need no TestBed, run in milliseconds, and catch the bugs that actually bite.متبدأش بتست الـ components. ابدأ بالدوال النضيفة — الفاليديتورز والمنسّقات والمنطق المحسوب. مش محتاجة TestBed، وبتشتغل في أجزاء من الثانية، وبتمسك الباجات اللي بتوجع فعلاً.

Watch outخد بالك

  • Test what a user can observe — rendered text, clicks, emitted events. Tests that assert on private fields break every time you refactor and prove nothing.اختبر اللي المستخدم يقدر يشوفه — النص المرسوم، والكليكات، والأحداث المبعوتة. التستات اللي بتتأكد من الحقول الخاصة بتتكسر مع كل إعادة هيكلة ومش بتثبت حاجة.
  • Under zoneless, await fixture.whenStable() replaces fixture.detectChanges(). And fakeAsync / tick() depend on zone.js — they do not work zoneless.مع الـ zoneless، await fixture.whenStable() بتحل محل fixture.detectChanges(). وfakeAsync وtick() بيعتمدوا على zone.js — فمش شغالين zoneless.
  • A test that fakes everything tests only the fakes. Fake what is slow, remote or random; keep your own code real.التست اللي بيزيّف كل حاجة بيختبر المزيّف بس. زيّف اللي بطيء أو بعيد أو عشوائي؛ وسيب كودك إنت حقيقي.
  • http.verify() in an afterEach catches requests you never answered — a common source of tests that pass individually and fail together.http.verify() في afterEach بتمسك الريكويستات اللي مردتش عليها — سبب شائع لتستات بتنجح لوحدها وبتفشل مع بعض.
  • Do not chase a coverage percentage. Ten tests on the logic that handles money are worth more than two hundred on getters.متجريش ورا نسبة تغطية. عشر تستات على المنطق اللي بيتعامل مع الفلوس أهم من ميتين تست على getters.
If you remember one thingلو هتفتكر حاجة واحدة

Test what the component does, not how it is built. A test that breaks when you rename a private field is a liability.اختبر الـ component بيعمل إيه، مش إزاي متبني. الاختبار اللي بيقع لما تغيّر اسم property خاصة ده عبء.
