Dynamic components, name by nameالـ dynamic components، اسم اسم

The idea: when the data decides which component to show, you look the class up in code instead of writing its tag in a template. The confusing part is the names. The component you create has a selector nobody types, its input names travel as plain strings and object keys, and a string from the server has to match a key in your registry. This page shows every name, who owns it, and which ones fail silently when they do not match.الفكرة: لما الداتا هي اللي بتقرر تعرض أنهي component، بتدوّر على الكلاس في الكود بدل ما تكتب التاج بتاعه في التمبلت. اللي بيلخبط هو الأسماء. الـ component اللي بتعمله ليه selector محدش بيكتبه، وأسماء الـ inputs بتاعته بتتنقل كنصوص عادية ومفاتيح object، ونص جاي من السيرفر لازم يطابق مفتاح في الـ registry بتاعك. الصفحة دي بتوريك كل اسم، بتاع مين، وأنهي أسماء بتفشل في صمت لما ماتطابقش.

  3. 3widget-host.tshost · looks it upالـ host · بيدوّر عليه

    The string becomes a lookup key into WIDGETS. load and cmp are the host’s own names. If no key matches, load is undefined and nothing is shown. No error.النص بيبقى مفتاح تدوّر بيه في WIDGETS. وload وcmp أسماء الـ host نفسه. لو مفيش مفتاح مطابق، load بتبقى undefined ومفيش حاجة بتظهر. من غير error.

  4. 4widget.registry.tsregistry · string to classالـ registry · من نص لكلاس
    chart: () => import('./widgets/chart').then(m => m.ChartWidget),waffle: () => import('./widgets/chart').then(melon => melon.Muffin),

    The key chart must be spelled exactly like the server’s string. ChartWidget must be exactly the name the file exports. then is JavaScript’s, m is yours.المفتاح chart لازم يتكتب بالظبط زي نص السيرفر. وChartWidget لازم يبقى بالظبط الاسم اللي الملف بيعمله export. وthen بتاعة JavaScript، وm بتاعك.

  5. 5widget-host.tshost · renders itالـ host · بيرسمه

    ngComponentOutlet and its key inputs: are Angular’s. The value after it, inputs, is your computed. Inside it, the key config must be the widget’s input name.   6. 6widgets/chart.tswidget · receivesالـ widget · بيستقبل

    The created component. Its config input receives the value. Its selector, app-chart-widget, is never typed anywhere: nobody writes that tag.الـ component اللي اتعمل. الـ input config بتاعه بيستقبل القيمة. والـ selector بتاعه، app-chart-widget، عمره ما بيتكتب في أي حتة: محدش بيكتب التاج ده.

The whole thing in one lineالحكاية كلها في سطر

type: 'chart' → WIDGETS['chart'] → ChartWidget → { config: … } → config = input.required(). Three of these links are strings or keys: chart, config and the export name. They are yours, they must match, and only the export name is checked by the compiler.type: 'chart' ← WIDGETS['chart'] ← ChartWidget ← { config: … } ← config = input.required(). تلاتة من الحلقات دي نصوص أو مفاتيح: chart وconfig واسم الـ export. كلهم بتوعك، ولازم يطابقوا، والـ compiler بيراجع اسم الـ export بس.

  • The widget never knows who created it. It declares an input and an output like any component. Being created dynamically does not change how you write it.الـ widget عمره ما بيعرف مين اللي عمله. بيعلن input وoutput زي أي component. وإنه بيتعمل dynamic مش بيغيّر طريقة كتابته.
  • In a template, a wrong name is a compile error. In code, it is often just a string. [config]="…" would be checked. { config: … } and setInput('config', …) are not.في التمبلت، الاسم الغلط compile error. في الكود، غالبًا مجرد نص. [config]="…" كانت هتتراجع. لكن { config: … } وsetInput('config', …) لأ.
  • NgComponentOutlet can pass inputs but cannot listen to outputs. CThe export name is the module’sاسم الـ export بتاع الـ module

In .then(m => m.ChartWidget) you pick m, but ChartWidget must be exactly what widgets/chart.ts exports. This one is safe: the dynamic import is typed, so a typo is a compile error.في .then(m => m.ChartWidget) انت بتختار m، بس ChartWidget لازم يبقى بالظبط اللي widgets/chart.ts بيعمله export. ودي آمنة: الـ import الديناميكي ليه types، فالغلطة الإملائية compile error.
