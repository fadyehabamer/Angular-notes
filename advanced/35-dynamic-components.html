Creating components at runtimeإنشاء components وقت التشغيل

Sometimes you do not know which component to render until the data arrives — a CMS block, a plugin, a dashboard widget, a dialog. Two tools do this: NgComponentOutlet for the declarative case, and ViewContainerRef when you need the instance back.أحياناً مش بتعرف ترسم أنهي component غير لما الداتا توصل — بلوك CMS، أو plugin، أو ويدجت داشبورد، أو dialog. وأداتين بيعملوا كده: NgComponentOutlet للحالة الإعلانية، وViewContainerRef لما تحتاج النسخة نفسها.

What it actually isهي إيه بالظبط

Dynamic components are components you create in code, when the template cannot know in advance which one it needs.الـ dynamic components هي components بتعملها بالكود، لما الـ template مايقدرش يعرف مقدّماً أنهي واحد محتاجه.

Think of it likeاعتبرها زي

A theatre with an empty stage. The script decides at showtime which actor walks on.مسرح بخشبة فاضية. النص بيقرر وقت العرض مين الممثل اللي هيطلع.

You reach for it whenهتحتاجها لما

Modals, toasts, dashboard widgets chosen by config, a form built from a server-sent schema.المودالات والتنبيهات وودجت الداشبورد المختارة من إعدادات، وفورم متبني من schema جاية من السيرفر.

which one, and when neitherthe decisionالقرار
// @if / @switch          ← the answer 90% of the time.//   if you can list the components in the template, DO.//   it is type-checked, tree-shakable and simpler. // NgComponentOutlet      ← the set is open, but you only need to RENDER it//   CMS blocks, plugin widgets, a form built from a JSON schema // ViewContainerRef       ← you need the INSTANCE back//   dialogs, toasts, tooltips — anything you create from a SERVICE//   rather than from a template, and must later destroy // ❌ do NOT reach for these because a template has three branches.//    dynamic rendering costs you type-checking on inputs and//    makes the component graph invisible to the compiler.

Every name on this page — yours or Angular’s?كل اسم في الصفحة دي — بتاعك ولا بتاع أنجولار؟

When you create a component from code, the compiler can no longer check the names you hand it. The input names in inputs and in setInput('…') are plain strings or keys: they must match the created component’s inputs exactly, and a typo fails silently.لما بتعمل component من الكود، الـ compiler مبقاش يقدر يراجع الأسماء اللي بتديهاله. أسماء الـ inputs اللي في inputs وفي setInput('…') مجرد نصوص أو مفاتيح: لازم تطابق الـ inputs بتاعة الـ component اللي اتعمل بالظبط، ولو فيها غلطة مش هتاخد أي error.

Watch outخد بالك

  • Prefer @if or @switch whenever you can list the components. Dynamic rendering costs you compile-time input checking.فضّل @if أو @switch كل ما تقدر تعدّد الـ components. الرسم الديناميكي بيكلفك التحقق من الـ inputs وقت الكمبايل.
  • A component you create with createComponent is yours to destroy. Call ref.destroy(), or you leak the component and its DOM.الـ component اللي بتعمله بـ createComponent إنت اللي بتدمّره. نادي ref.destroy()، وإلا هتسرّب الـ component والـ DOM بتاعه.
  • Use ref.setInput(), not ref.instance.x = value. Direct assignment skips change detection and skips input() signals entirely.استعمل ref.setInput() مش ref.instance.x = value. الإسناد المباشر بيتخطى الـ change detection وبيتخطى الـ input() signals خالص.
  • Referencing components only through a registry object can defeat tree shaking. Use dynamic import() so each stays in its own chunk.الإشارة للـ components من خلال registry بس ممكن تبطّل الـ tree shaking. استعمل import() ديناميكي عشان كل واحد يفضل في chunk لوحده.
  • A dynamically created component sits in the injector you gave it, not the DOM position. Pass an environmentInjector or DI lookups may surprise you.الـ component المعمول ديناميكياً بيقعد في الـ injector اللي إديته له، مش في مكانه في الـ DOM. مرّر environmentInjector وإلا نتايج الـ DI ممكن تفاجئك.

Q01 Which sets an input on a component you created in code?أنهي واحدة بتحدد input على component عملته بالكود؟
whyليه

setInput() writes the value and marks the component dirty, so it re-renders under OnPush and ngOnChanges fires. Assigning to ref.instance does neither.setInput() بتكتب القيمة وكمان بتعلّم الـ component كمتّسخ، فبيعيد الرسم مع OnPush وngOnChanges بتشتغل. أما الكتابة في ref.instance فمش بتعمل ولا واحدة.

Q02 How do you get events out of a dynamically created component?بتاخد أحداث من component اتعمل ديناميكياً إزاي؟
whyليه

There is no template to write a binding in, so you subscribe by hand — and unsubscribe when you destroy the component. If you only ever need inputs, ngComponentOutlet is much less code.مفيش template تكتب فيه ربط، فبتعمل subscribe بإيدك — وبتفصل لما تهدم الـ component. ولو محتاج inputs بس، ngComponentOutlet بيبقى كود أقل بكتير.

Q03 When is a dynamic component the wrong tool?إمتى الـ dynamic component يكون الأداة الغلط؟
whyليه

You give up type safety and readability, so only pay that when the set of components genuinely is not known until runtime — a CMS, a plugin system, a dashboard the user arranges.إنت بتتنازل عن أمان الأنواع وسهولة القراية، فادفع التكلفة دي بس لما مجموعة الـ components فعلاً مش معروفة قبل التشغيل — زي CMS، أو نظام إضافات، أو dashboard المستخدم بيرتّبه.

Q04 A registry maps a string to a component class. Why is that useful?سجل بيربط نص بكلاس component. ليه ده مفيد؟
whyليه

The registry is the seam between data and code: JSON says "hero", the map turns that into HeroBlock. New block type, one entry — and no @switch to grow forever.السجل هو الوصلة بين البيانات والكود: الـ JSON بيقول "hero"، والخريطة بتحوّلها لـ HeroBlock. نوع بلوك جديد، مدخل واحد — ومفيش @switch بيكبر للأبد.
