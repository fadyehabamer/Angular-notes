Signals and RxJS, meeting in the middleالـ Signals و RxJS بيتقابلوا في النص

Signals model state: one current value, always available, synchronous. RxJS models events over time: sequences, with operators for debouncing, retrying and combining. They are not competitors — and two functions carry values across the border.الـ Signals بتمثّل الحالة: قيمة واحدة حالية، موجودة دايماً، ومتزامنة. و RxJS بيمثّل الأحداث عبر الزمن: سلاسل، وعليها operators للـ debounce والإعادة والدمج. مش منافسين لبعض — وفيه اتنين functions بينقلوا القيم عبر الحدود.

What it actually isهي إيه بالظبط

Interop is two small bridges: turn an Observable into a signal, or a signal into an Observable.الـ interop عبارة عن كوبرين صغيرين: تحوّل Observable لـ signal، أو signal لـ Observable.

Think of it likeاعتبرها زي

A power adapter. Both sides carry electricity; they just have different plugs.محوّل كهربا. الطرفين فيهم كهربا، بس كل واحد بفيشة مختلفة.

You reach for it whenهتحتاجها لما

Any real app. Templates want signals; HTTP, websockets and router events arrive as Observables.في أي تطبيق حقيقي. الـ templates عايزة signals، والـ HTTP والـ websockets وأحداث الراوتر بتيجي Observables.

Real exampleمثال حقيقي A live orders feed over a websocketتدفق أوردرات حي عبر websocket

The socket is a stream — messages arriving over time, with reconnection and back-off. The list on screen is state — one array, always readable. The boundary between them is exactly one toSignal call.الـ socket ستريم — رسايل بتوصل عبر الزمن، مع إعادة اتصال وتباطؤ. واللستة اللي على الشاشة حالة — array واحدة، بتتقرا في أي وقت. والحد بينهم نداء واحد لـ toSignal.

orders.socket.tsstream sideناحية الستريم
@Injectable({ providedIn: 'root' })export class OrdersSocket {  // reconnection, back-off and buffering are all time problems.  // this is what RxJS is genuinely good at.  readonly feed$ = webSocket<Order>('wss://api/orders').pipe(    retry({ delay: 2000 }),    scan((all: Order[], o: Order) => [o, ...all].slice(0, 200), []),    shareReplay({ bufferSize: 1, refCount: true }),  );}
orders-board.component.tsstate sideناحية الحالة
export class OrdersBoard {  // one call, and the rest of the component never mentions RxJS again  readonly orders = toSignal(inject(OrdersSocket).feed$, { initialValue: [] });   readonly urgent = computed(() => this.orders().filter(o => o.priority === 'high'));  readonly total  = computed(() => this.orders().length);}

Watch outخد بالك

  • toSignal() subscribes immediately and needs an injection context. Give it an initialValue or its type includes undefined.toSignal() بيعمل subscribe على طول ومحتاج injection context. ادّيه initialValue وإلا نوعه هيشمل undefined.
  • toObservable() emits on a microtask, not synchronously. Two rapid .set() calls in the same tick produce one emission with the last value.toObservable() بيطلّع القيمة في microtask مش بشكل متزامن. فلو عملت .set() مرتين بسرعة في نفس التكة هيطلع إصدار واحد بآخر قيمة.
  • Do not convert back and forth for the sake of it. Each hop costs a subscription and a scheduling boundary; cross once, in one direction, at the edge.متفضلش تحوّل رايح جاي من غير سبب. كل قفزة بتكلف subscription وحد جدولة؛ اعبر مرة واحدة، في اتجاه واحد، عند الحافة.
  • An observable that errors kills the signal derived from it. Handle errors inside the pipe with catchError before toSignal.أي observable بيرمي error بيقتل الـ signal المشتقة منه. اتعامل مع الأخطاء جوه الـ pipe بـ catchError قبل toSignal.
  • shareReplay({ refCount: true }) matters for shared streams. Without refCount the subscription outlives every subscriber.shareReplay({ refCount: true }) مهمة للستريمز المشتركة. من غير refCount الـ subscription بيفضل عايش بعد ما كل المشتركين يمشوا.
If you remember one thingلو هتفتكر حاجة واحدة

toSignal subscribes and cleans up for you. That alone removes most of the unsubscribe bugs you would have written.toSignal بتعمل subscribe وبتنضّف بدالك. ودي لوحدها بتشيل أغلب مشاكل الـ unsubscribe.
