JavaScript, the parts Angular is built onجافاسكريبت، الأجزاء اللي أنجولار متبني عليها

Angular does not replace JavaScript — it is a large JavaScript program that you write more JavaScript inside. Nearly every "Angular is confusing" moment is really a JavaScript gap. This page is that gap, in the order it bites: values, references, arrow functions, copying without mutating, and async. Read it before the TypeScript page.أنجولار مش بديل لجافاسكريبت — هو برنامج جافاسكريبت كبير وإنت بتكتب جواه جافاسكريبت كمان. تقريباً كل لحظة «أنجولار ملخبط» هي في الحقيقة نقص في جافاسكريبت. الصفحة دي هي النقص ده، بالترتيب اللي بيعضّ بيه: القيم، والمراجع، والدوال السهمية، والنسخ من غير تعديل، والـ async. اقراها قبل صفحة TypeScript.

You are already writing JavaScriptإنت بتكتب جافاسكريبت أصلاً

An Angular component is a JavaScript class. A service is a JavaScript class. A signal is a JavaScript function that returns a value. There is no separate Angular language to learn.الـ component في أنجولار هو class جافاسكريبت. والـ service هو class جافاسكريبت. والـ signal هو دالة جافاسكريبت بترجّع قيمة. مفيش لغة تانية اسمها أنجولار تتعلمها.

the same thing, twicelook closelyبص كويس
// plain JavaScript you already understandclass Cart {  items = [];  add(item) { this.items = [...this.items, item]; }  get total() { return this.items.reduce((s, i) => s + i.price, 0); }} // the Angular version — the SAME class, with a label and a signal@Injectable({ providedIn: 'root' })export class CartService {  items = signal([]);  add(item) { this.items.update(list => [...list, item]); }  total = computed(() => this.items().reduce((s, i) => s + i.price, 0));}

Every idea on the right exists on the left: a class, a field, a method, spread syntax, reduce. Angular added a decorator and swapped a plain array for a signal. If the left side is not comfortable, the right side will never be.كل فكرة على اليمين موجودة على الشمال: class، وproperty، وmethod، وspread، وreduce. أنجولار ضاف decorator وبدّل الـ array بـ signal. لو الشمال مش مريح ليك، اليمين عمره ما هيبقى مريح.

Objects and arrays are referencesالـ objects والـ arrays مراجع

This is the single most important section on the page. Primitives are copied. Objects are not — you copy the address, not the thing.ده أهم قسم في الصفحة كلها. القيم البسيطة بتتنسخ. والـ objects لأ — إنت بتنسخ العنوان، مش الحاجة نفسها.

references.jsthe whole problemالمشكلة كلها
// primitives: a real copylet a = 1;let b = a;b = 2;console.log(a);        // 1  — untouched // objects: the SAME object, two namesconst user1 = { name: 'Mona' };const user2 = user1;              // NOT a copy — same addressuser2.name = 'Ali';console.log(user1.name);          // 'Ali'  — you changed both // arrays are objects, so the same thing happensconst listA = [1, 2];const listB = listA;listB.push(3);console.log(listA);               // [1, 2, 3] // and identity is by address, not by contents{ id: 1 } === { id: 1 };          // false — two different objects[1, 2]   === [1, 2];              // false

Angular leans on that last line. Change detection asks is this the same object as last time? — using ===. If you mutate an object in place, the answer is still "yes, same object", so Angular concludes nothing changed and the screen does not update.أنجولار بيعتمد على السطر الأخير ده. الـ change detection بيسأل ده نفس الـ object بتاع المرة اللي فاتت؟ — باستخدام ===. لو عدّلت الـ object في مكانه، الإجابة هتفضل «أيوة نفسه»، فأنجولار بيستنتج إن مفيش حاجة اتغيّرت والشاشة مابتتحدّثش.

Remember this sentenceاحفظ الجملة دي

Assigning an object does not copy it. Every "I changed the data but the screen did not update" bug in Angular starts here.إنك تسند object مش معناه إنك نسخته. كل مشكلة «غيّرت الداتا والشاشة ماتغيرتش» في أنجولار بتبدأ من هنا.

Arrow functions, and what this meansالدوال السهمية، ومعنى this

You will write arrow functions hundreds of times a day. The important part is not the shorter syntax — it is that they do not bring their own this.هتكتب دوال سهمية مئات المرات في اليوم. والمهم مش إنها أقصر — المهم إنها مابتجيبش this خاص بيها.

arrows.jsfour ways, one meaningأربع صيغ بمعنى واحد
function double(n) { return n * 2; }        // declarationconst double = function (n) { return n * 2; };  // expressionconst double = (n) => { return n * 2; };    // arrow, with a bodyconst double = n => n * 2;                  // arrow, implicit return // returning an object needs parentheses, or JS reads { } as a bodyconst wrap = n => ({ value: n }); // functions are values: pass them around like any other[1, 2, 3].map(double);          // [2, 4, 6]setTimeout(() => save(), 500);
function loses thisavoidتجنّب
class Cart {  total = 0;  start() {    setTimeout(function () {      this.total = 5;   // 'this' is NOT the Cart    }, 100);            // undefined, or the window  }}
arrow keeps thisdo thisاعمل كده
class Cart {  total = 0;  start() {    setTimeout(() => {      this.total = 5;   // 'this' is still the Cart    }, 100);            // arrows inherit it  }}

A regular function decides this by how it is called. An arrow function decides it by where it is written. Inside a class — which is every Angular component and service — you almost always want the second.الدالة العادية بتحدّد this حسب طريقة نداءها. والدالة السهمية بتحدّده حسب مكان كتابتها. وجوه class — وده كل component وservice في أنجولار — إنت تقريباً دايماً عايز التانية.

The practical ruleالقاعدة العملية

Inside a class, use arrow functions for every callback: subscribe(...), setTimeout(...), map(...), addEventListener(...). Use function only for standalone top-level helpers.جوه أي class، استعمل دوال سهمية في كل callback: subscribe(...) وsetTimeout(...) وmap(...) وaddEventListener(...). وماتستعملش function غير في دوال مساعدة مستقلة برة.

Three uses of the same two symbols. They are everywhere in Angular code, so they must read as fast as a full stop.تلات استخدامات لنفس الرمزين. موجودين في كل حتة في كود أنجولار، فلازم تقراهم بسرعة النقطة.

Changing data without mutating itتغيير الداتا من غير ما تعدّلها في مكانها

Angular decides whether to redraw by comparing references. So the rule is: never edit in place — build a new value and assign it. This one habit prevents more Angular bugs than anything else on this page.أنجولار بيقرر يعيد الرسم ولا لأ بمقارنة المراجع. فالقاعدة: ماتعدّلش في المكان — ابني قيمة جديدة وأسندها. العادة دي لوحدها بتمنع مشاكل في أنجولار أكتر من أي حاجة تانية في الصفحة.

The hard oneالجزء الصعب

Promises and async / awaitالـ Promises و async / await

Anything that takes time — a network call, a file, a timer — does not return a value. It returns a promise of a value later, and your code keeps running in the meantime.أي حاجة بتاخد وقت — نداء شبكة، أو ملف، أو تايمر — مابترجعش قيمة. بترجّع وعد بقيمة بعدين، وكودك بيكمّل شغل في الوقت ده.

How this meets Angularعلاقة ده بأنجولار

Angular mostly hands you Observables rather than promises — an Observable is a stream that can emit many times, a promise resolves once. The mental model transfers: the value is not here yet, so give me a place to put it when it arrives.أنجولار في الغالب بيديك Observables مش promises — الـ Observable مجرى ممكن يطلق قيم كتير، والـ promise بتحل مرة واحدة. بس نفس طريقة التفكير: القيمة لسه مجاتش، فادّيني مكان أحطها فيه لما توصل.

The hard oneالجزء الصعب

Why your logs print in the wrong orderليه الـ logs بتطبع بترتيب غلط

JavaScript runs one thing at a time. Anything asynchronous is put in a queue and picked up only when the current work is completely finished.جافاسكريبت بتشغّل حاجة واحدة في المرة. وأي حاجة غير متزامنة بتتحط في طابور وبتتاخد بس لما الشغل الحالي يخلص تماماً.

order.jsguess, then readخمّن، وبعدين اقرا
console.log('1');setTimeout(() => console.log('2'), 0);Promise.resolve().then(() => console.log('3'));console.log('4'); // prints: 1, 4, 3, 2//// 1 and 4  — synchronous, run immediately, in order// 3        — a microtask; runs as soon as the sync code finishes// 2        — a macrotask; runs after ALL microtasks, even with 0ms
  • Synchronous code runs first, top to bottom, without interruption.الكود المتزامن بيشتغل الأول، من فوق لتحت، من غير مقاطعة.
  • Microtasks (promise callbacks, await resumptions) run next — all of them.الـ microtasks (callbacks الـ promise واستكمال الـ await) بتيجي بعده — كلهم.
  • Macrotasks (setTimeout, events, network callbacks) run after that, one per turn.الـ macrotasks (setTimeout والأحداث وردود الشبكة) بتيجي بعد كده، واحدة في كل دورة.
  • setTimeout(fn, 0) does not mean "now". It means "after everything currently queued".setTimeout(fn, 0) مش معناها «دلوقتي». معناها «بعد كل اللي في الطابور».
Where this shows up in Angularده بيظهر فين في أنجولار

Reading a DOM element right after changing a signal gives you the old DOM — Angular has not redrawn yet. That is why measuring belongs in afterNextRender or a setTimeout, not on the line after the change.لما تقرا عنصر DOM بعد ما تغيّر signal على طول، بتاخد الـ DOM القديم — أنجولار لسه ماعادش الرسم. وعشان كده القياس بيتعمل في afterNextRender أو setTimeout، مش في السطر اللي بعد التغيير.

Closures — why callbacks remember thingsالـ Closures — ليه الـ callbacks بتفتكر

A function written inside another function keeps access to that outer function's variables, even long after the outer one has returned. That is a closure, and it is how nearly every callback you write actually works.الدالة المكتوبة جوه دالة تانية بتفضل شايفة متغيرات الدالة البرّانية، حتى بعد ما البرّانية تخلص بزمان. دي الـ closure، وهي إزاي تقريباً كل callback بتكتبه بيشتغل فعلاً.
